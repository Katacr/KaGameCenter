# 08 数据统计与通用服务

更新时间：2026-07-16

## GameResultService

```kotlin
resultService.recordKill(room, killerId, victimId, points = 1)
resultService.recordDeath(room, playerId)
resultService.recordWin(room, playerId, points = 3)
resultService.recordLoss(room, playerId)
resultService.recordWinLoss(room, participants, winners, winPoints = 3)
resultService.addMetric(room, playerId, "objectives-completed")
val objectives = resultService.metric(room, playerId, "objectives-completed")
```

统一表 `kgc_player_stats` 保存：

```text
player_id, game_id, plays, wins, losses,
kills, deaths, points, updated_at
```

主插件在玩家成功加入房间时记录 play。模块负责在明确的玩法事件点记录击杀、死亡和最终胜负，防止重复结算。

扩展表 `kgc_player_metrics` 以 `player_id/game_id/metric_id` 为联合主键保存玩法专属整数计数。指标名会转换为最多 64 字符的稳定小写标识，模块应在唯一事件点调用 `addMetric`，不要自行操作仓库或拼接 `game_id`。

玩家可通过主菜单、房间菜单或 `/kgc stats [gameId]` 查看统计。详情页固定显示基础统计，并按稳定 `metricId` 排序列出该玩法的全部扩展指标；主插件不维护任何玩法指标白名单。

`GameStatsMenuOpenedEvent` 在 KaMenu 或内置箱子菜单成功打开战绩配置后同步发布，提供在线 Player 和可空玩法 ID；概览页为 `null`，指定详情页使用规范化输入 ID。两条配置菜单都失败并退回主 Dialog 时不发布。事件不可取消，只用于音效、审计等打开后反馈。

相同菜单回退语义也适用于 `GameRoomsMenuOpenedEvent`：`/kgc selector <gameId>` 或 `kgc:open-rooms <gameId>` 成功打开筛选房间列表后携带规范化筛选 ID，全局房间列表携带 `null`。模块 ID 匹配该模块的全部托管玩法，完整 globalId 匹配单个玩法；事件不可取消。

支持独立等级曲线的玩法可以把累计经验保存为扩展指标，并在持久化后发布 `GamePlayerExperienceGainedEvent`；事件提供 UUID、可空在线 Player、稳定来源、实际增加量、累计经验及派生出的等级/级内经验/下一阈值。一次奖励跨越至少一级时先发布 `GamePlayerLevelUpEvent`，其中保留前后等级和最终进度，再发布经验事件；两者均不可取消。

当前后端支持 SQLite/MySQL。可累加整数使用扩展指标；路线最佳成绩、复杂职业数据等非计数结构仍放模块私有存储，并隔离表/文件且在 `onUnload()` 关闭连接。

SQLite 统计与好友连接均限制为单连接，并启用 WAL 和 5 秒 `busy_timeout`，降低两个异步/同步持久化通道写入同一数据库时的锁竞争；MySQL 使用配置的连接池上限。

## FriendService

`GameCenterApi.friendService` 与 `GameModuleContext.friendService` 暴露进程内关系缓存：

```kotlin
val relation = context.friendService.relation(player.uniqueId, target.uniqueId)
val friends = context.friendService.friendsOf(player.uniqueId)
val result = context.friendService.request(player.uniqueId, target.uniqueId)
```

- `request/accept/deny/remove` 先原子更新同步内存状态，再由单线程执行器按顺序持久化。
- SQLite/MySQL 使用 `kgc_friendships` 与 `kgc_friend_requests`；数据库关闭或初始化失败时回退内存仓库。
- `resolvePlayer` 只能在 Bukkit 主线程调用，支持 UUID、在线精确名称和曾登录名称。
- 模块可以读取好友关系或复用操作 API，但不应自行缓存好友集合；通知、菜单和跨服表现仍由调用方决定。
- 当前关系只在单个 GameCenter 实例加载时同步；Velocity 跨服好友在线状态、跨服私聊和关系广播尚未纳入协议。

## RoomTaskService

```kotlin
roomTaskService.runTask(room.id, Runnable { ... })
roomTaskService.runTaskLater(room.id, 20L, Runnable { ... })
roomTaskService.runTaskTimer(room.id, 0L, 20L, Runnable { ... })
roomTaskService.track(room.id, task)
roomTaskService.cancelRoom(room.id)
```

- 所有玩法任务绑定 roomId。
- `onClose()` 调用 `cancelRoom`。
- Bukkit scheduler 同步任务不适合数据库/文件 IO。
- 不为每个玩家创建可以合并的永久循环任务。

## RoomEntityOwnershipService

```kotlin
val tnt = world.spawn(location, TNTPrimed::class.java)
entityOwnershipService.track(room.id, tnt, player.uniqueId, "explosive")

val record = entityOwnershipService.remove(tnt.uniqueId) ?: return
if (record.roomId != room.id) return
val ownerId = record.ownerId
```

- type 是模块自定义分类。
- 事件中始终校验 roomId。
- 服务不删除实体，只记录归属。
- 实体死亡、爆炸、拾取和房间关闭后移除记录。

## RoomPresentationService

```kotlin
val npc = roomPresentationService.spawnNpc(
    room.id,
    location,
    Villager::class.java,
    type = "shop"
) { villager ->
    villager.profession = Villager.Profession.WEAPONSMITH
}

val text = roomPresentationService.spawnText(
    room.id,
    location.clone().add(0.0, 2.0, 0.0),
    Component.text("右键打开"),
    type = "shop-label"
)

val item = roomPresentationService.spawnFloatingItem(
    room.id,
    location,
    ItemStack(Material.DIAMOND),
    type = "generator-icon"
)
roomPresentationService.updateText(text.uniqueId, Component.text("已升级"))
roomPresentationService.rotateFloatingItem(item.uniqueId, 90.0)
```

- NPC 默认无 AI、无碰撞、无敌、静音并持久存在。
- 文本和浮动物品使用核心内部实现，模块不应依赖具体实体通用属性。
- 所有返回实体自动进入房间资源作用域，关房统一删除；区块模板清理可通过 `roomResourceScopeService.isEntityTracked(room.id, entityId)` 保留这些实体，模块仍负责保存玩法身份映射和交互规则。

## RoomReconnectStateService

```kotlin
override fun onPlayerReconnectExpired(playerId: UUID) {
    val snapshot = reconnectStateService.get(room.id, playerId) ?: return
    val location = snapshot.location
    val inventory = snapshot.inventoryContents
    val attackerId = snapshot.lastDamagerId
}
```

断线快照由 `GameRoomManager` 自动捕获和释放。模块只能在重连回调期间读取，不应长期持有其中的 `Location` 或 `ItemStack`；房间限定的 `remove(roomId, playerId)` 用于防止旧任务误删新房间状态，生存状态、角色、复活阶段和胜负仍属于 Session。

## WeightedPool

```kotlin
val pool = WeightedPool(
    listOf(
        WeightedPool.Entry(RewardType.COMMON, 5),
        WeightedPool.Entry(RewardType.RARE, 1)
    )
)

val reward = pool.next()
```

批量分发：

```kotlin
WeightedRewardDistributor(pool).distribute(players, amountPerPlayer = 1) { player, reward ->
    giveReward(player, reward)
}
```

权重小于等于 0 的条目被忽略。服务只决定抽到什么，不应用物品或效果。

## GamePhaseTimer

```kotlin
private val timer = GamePhaseTimer()

fun begin(seconds: Int) {
    timer.resetSeconds(seconds)
}

fun tick() {
    if (timer.isSecondBoundary) {
        broadcastTime(timer.secondsLeft)
    }
    if (timer.tick()) {
        advancePhase()
    }
}
```

- timer 只计数，不修改房间或模块 phase。
- `secondsLeft` 适合 UI 展示。
- 阶段切换时明确 reset/clear。

## PlayerRuntimeStateService

```kotlin
playerRuntimeStateService.captureIfAbsent(room.id, player)

// 修改模式、飞行、速度、隐身、药水等。

playerRuntimeStateService.restore(room.id, player)
playerRuntimeStateService.clearRoom(room.id)
```

它保存模块临时状态，不保存背包、经验、血量和位置；完整快照由主插件 PlayerSnapshotService 管理。

## PlayerEliminationService

```kotlin
eliminationService.enableImmediateRespawn(room.world!!)
eliminationService.eliminate(room, player, spectatorLocation)

// 需要通用观战快捷栏时：
eliminationService.eliminate(
    room,
    player,
    spectatorLocation,
    spectatorPolicy = SpectatorPolicy(mode = SpectatorMode.MANAGED)
)
```

- 模块仍负责判定淘汰并先更新自己的存活状态。
- 服务只保存按 `roomId/playerId` 隔离的观战表现状态；托管模式通过 `SpectatorService` 发放快捷栏，但不改变参赛身份集合。
- 主插件统一处理 `PlayerRespawnEvent` 和淘汰观战者的输入限制。
- 玩家离开、重连过期或房间关闭时由 `GameRoomManager` 清理标记。

## RoomResourceScopeService

```kotlin
private val resources = context.roomResourceScopeService.open(room.id)

resources.trackEntity(entity, ownerId, "projectile")
resources.captureBlock(block)
resources.trackViewer(player.uniqueId)
resources.releaseEntity(entity.uniqueId)
```

- 每个 `roomId` 只有一个作用域，可由 Session 保存其句柄。
- 房间关闭时自动取消 RoomTask、删除临时实体、清实体归属、恢复方块、清 Packet viewer 和名牌。
- 模块仍负责清空自己的玩家、阶段、箱子和胜负数据。

## ManagedMapPointService / SpawnAssignmentService

```kotlin
val point = managedMapPointService.fromLocation(player.location)
managedMapPointService.replace(config, "example.lobby", point)

val assignments = spawnAssignmentService.assign(players, spawnPoints)
    ?: return failConfiguration()
```

- `ManagedMapPoint` 不保存世界名，运行时通过 `toLocation(room.world)` 映射。
- 命名点位使用稳定 ID，服务提供读取、新增/替换和删除。
- 出生点分配只负责随机且不重复地配对；点位不足返回 `null`，不传送玩家、不修改 Session 状态。

## 何时抽到主插件

只有满足以下条件才新增通用服务：

- 至少两个模块出现同类重复实现。
- 服务不需要知道具体角色、道具或胜负语义。
- 能以 roomId/UUID 明确隔离状态。
- 有清晰的创建、更新和清理生命周期。

只在单个玩法出现的规则先留在模块，避免主插件夹带玩法私货。
