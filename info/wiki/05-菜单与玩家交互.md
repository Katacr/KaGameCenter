# 05 菜单与玩家交互

更新时间：2026-07-16

## 选择渲染方式

KaMenu 适合：

- 大量文本或房间列表。
- 下拉选择和输入框。
- 管理员托管游戏编辑器。
- Paper Dialog 多列按钮布局。

内置箱子菜单适合：

- 道具、职业、队伍和投票选择。
- 高频点击和分页物品列表。
- 需要原版物品图标的操作面板。

Paper Dialog 只作为主菜单最终兜底，不建议模块直接依赖兜底服务。

## KaMenu 外部配置

模块动态构造 `YamlConfiguration`：

```kotlin
val config = YamlConfiguration().apply {
    set("Title", "示例编辑器")
    set("Settings.can_escape", true)
    set("Settings.after_action", "WAIT_FOR_RESPONSE")
    set("Body.summary.type", "message")
    set("Body.summary.text", "大厅: ${if (lobbySet) "已设置" else "未设置"}")
    set("Bottom.type", "multi")
    set("Bottom.columns", 3)
    set("Bottom.buttons.set_lobby.text", "设置大厅")
    set("Bottom.buttons.set_lobby.actions", listOf(
        "kgc:module-game-action ${game.globalId} set-lobby"
    ))
}

context.menuService.openExternalConfig(
    player,
    config,
    "kagamecenter:example:${game.globalId}"
)
```

渲染顺序：KaMenu `openConfig`，失败后尝试内置箱子菜单兼容层。

## 模块编辑器动作

标准动作：

```text
kgc:module-game-action <globalId> <action>
```

主插件根据 globalId 找到模块编辑器，再调用：

```kotlin
handleAction(player, game, action, variables)
```

模块动作只处理当前托管游戏。不要把当前编辑对象保存在全局单例；通过 `game.globalId` 和 `MapEditorService.currentSessionId(player)` 校验。

## Paper Dialog 刷新

Dialog 打开后不能原地修改组件。动态状态更新策略：

1. 执行动作。
2. 保存配置或地图。
3. 重新调用 `openEditor`/`openExternalConfig`。

会重新打开菜单的动作不要先执行 close，否则客户端会明显闪烁。

房间菜单的 `Body.*.TYPE: room_player_list` 会由主插件动态替换为可点击文本：每名玩家显示 `<head:玩家名> [玩家名]`，房主额外显示 `★`。个人模式按玩家列表分行；队伍模式按队伍标题、成员和“加入队伍”动作分组。点击玩家会打开成员操作页。

加入、离开、重连和队伍分配事件会合并为一次 5 tick 延迟刷新，确保成员集合与队伍写入已经提交。刷新只向仍在同一房间且房间处于可加入阶段的在线成员重发 Dialog，运行期不会强制打断玩家界面。

## 主插件持久化模板

```text
plugins/KaGameCenter/menus/
```

主插件动态 `TYPE`：

- `game_list`
- `map_list`
- `room_rows`
- `player_slots`
- Body `room_player_list`

模块不应注册与主插件同名的 TYPE。普通静态按钮和 KaMenu 原生动作保留在 YAML 中。

`/kgc selector <gameId> [group]` 与 `kgc:open-rooms <gameId> [group]` 打开按玩法及可选分组过滤的房间选择器，不改变 `/kgc rooms` 的文本状态输出。模块 ID 匹配该模块的全部托管玩法，完整 globalId（如 `example:default`）只匹配对应玩法；非 `default` 分组继续按托管配置 `selector-group` 精确过滤，`default` 表示不过滤。分组通过 Velocity 快照标签同步，旧快照回退 `default`。标题、数量、空列表、刷新、详情、成员操作和返回动作保持全部筛选上下文。

KaMenu 或内置箱子菜单成功打开房间列表后同步发布不可取消 `GameRoomsMenuOpenedEvent`，提供玩家、可空玩法 ID 与可空非默认分组；全局列表和 `default` 分组分别规范化为 `null`。两种配置菜单均失败而只回退主 Dialog 时不发布，模块可监听该后置事件实现玩法选择器音效或审计，但不能替换已经打开的菜单。

## 好友菜单与命令

主菜单提供好友入口，成员操作页会按 `FriendRelation` 动态显示添加、接受、拒绝、私聊或删除操作。好友列表输入框接受玩家名或 UUID；输入值由 KaMenu `Inputs.player_id` 传入 `kgc:friend-add`，私聊确认页使用 `Inputs.message`。

```text
/kgc friend list
/kgc friend add <玩家名|UUID>
/kgc friend accept <玩家名|UUID>
/kgc friend deny <玩家名|UUID>
/kgc friend remove <玩家名|UUID>
/kgc friend join <玩家名|UUID>
/kgc friend spectate <玩家名|UUID>
/kgc friend msg <玩家名|UUID> <消息>
```

加入或观战好友前会重新校验好友关系、目标在线状态、双方当前房间身份和目标房间准入条件。私聊当前只面向同一 Bukkit 服务端的在线好友，不承担跨服消息转发。

## 箱子菜单

直接打开模板：

```kotlin
context.chestMenuService.open(player, "main")
```

打开内存配置：

```kotlin
context.chestMenuService.openConfig(player, config, contextId)
```

模块动态数据源：

```kotlin
context.registerChestMenuDataSource("players", ChestMenuDataSource { viewer, menuContext ->
    room.players.mapNotNull(Bukkit::getPlayer).map { target ->
        ChestMenuEntry(
            variables = mapOf(
                "player.uuid" to target.uniqueId.toString(),
                "player.name" to target.name,
                "room.id" to room.id
            )
        )
    }
})
```

YAML 使用 `type: "example:players"`。每个动态槽位拥有独立变量，点击动作从当前槽位读取，避免多个玩家/房间串台。

核心 `ChestMenuListener` 会在默认优先级取消全部 `ChestMenuHolder` 点击后再路由 YAML 动作，并在 MONITOR 阶段最终保持这类虚拟菜单的点击与拖拽取消，避免后续监听器放行后把渲染图标移动进玩家背包。需要叠加专用动态点击语义的模块仍应识别已取消事件并只处理自己的 Holder，但不需要重复维护最终取消状态。

## 箱子菜单动作

- 点击：`left/right/shift_left/shift_right/drop`。
- 导航：`open/close/update/PAGE_NEXT/PAGE_PREV`。
- 输出：`tell/message/sound`。
- 命令：`command/console`。
- 主插件：`kgc:<payload>`。
- 条件：逻辑与比较运算，可预解析 PlaceholderAPI。

## 输入和变量安全

- 房间名称等玩家输入必须限制长度和危险字符。
- globalId、roomId、UUID 应从动作变量重新解析并校验对象仍存在。
- 不相信菜单打开时的旧状态；点击时重新检查权限、房主身份、房间阶段和人数。
- 管理员按钮隐藏不能替代动作层权限检查。
- 关闭房间或离开后，不继续使用菜单中缓存的旧 `GameRoom` 引用。

## 潜行 + F

主插件统一处理：

- 房间外打开游戏中心主菜单。
- 房间内打开当前房间菜单。

模块如需局内菜单，应由房间菜单动作再进入模块界面，不要重复注册同一快捷键的全局监听。

主菜单和房间菜单都提供个人战绩入口。`/kgc stats [gameId]` 走同一菜单链：房间内省略玩法 ID 时打开当前玩法详情，房间外显示已有玩法概览；渲染仍按 KaMenu、箱子菜单、Dialog 兜底顺序执行。KaMenu 或箱子菜单真实打开战绩配置后发布不可取消 `GameStatsMenuOpenedEvent`，提供玩家及可空 `gameId`；全玩法概览为 `null`。两条配置渲染均失败而只回退主 Dialog 时不发布，模块可据此播放玩法专属 GUI 音效，但不能在后置事件中替换已打开界面。
