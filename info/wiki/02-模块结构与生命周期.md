# 02 模块结构与生命周期

更新时间：2026-07-16

## 运行目录

```text
plugins/KaGameCenter/modules/
  <module>-<version>.jar
  <module>/
    config.yml
    lang/
    games/
      game/
      map/
```

加载器顺序：

1. 扫描模块 jar，释放缺失的 `config.yml` 和 `lang/`。
2. 扫描模块目录中的 `config.yml`。
3. 检查 `enabled/main/jar/entrypoint`，并从 JAR 内读取 `version`。
4. 创建独立 `URLClassLoader`。
5. 实例化 `GameModuleProvider` 并调用 `onLoad(context)`。

地图和预设游戏包不会从 jar 自动释放。

模块版本由根 `gradle.properties` 的 `<module>Version` 声明。配置指向的版本化 jar 存在时会直接加载；旧配置指向 `<module>.jar`，或配置指向的版本化 jar 已不存在时，会选择同目录最新修改的 `<module>-<version>.jar`，并把实际相对路径和版本回写到外部配置。版本化文件不会按语义版本比较，部署目录中仍应只保留准备启用的产物。

## 注册方法

```kotlin
context.registerModule(module)
context.registerListener(listener)
context.registerAdminCommand(command)
context.registerGameEditor(editor)
context.registerChatFormatter(formatter)
context.registerChestMenuDataSource("type", source)
context.registerPermission("kagamecenter.example.use", "Example permission", PermissionDefault.TRUE)
context.trackTask(task)
context.runTaskTimer(delayTicks, periodTicks, action)
```

管理员命令自动挂载到 `/kgc admin <command.name>`。箱子菜单数据源自动加模块命名空间，例如 `example:players`。模块私有权限由上下文动态注册，已有同名权限不会被模块接管。

## 卸载顺序

1. `provider.onUnload()`。
2. `context.cleanup()`。
3. 关闭模块 classloader。

`context.cleanup()` 会取消 context 追踪的任务，并注销 listener、聊天格式器、箱子菜单数据源、动态权限、管理员命令、托管游戏编辑器、玩法及默认定义。注册表资源按对象实例注销，旧上下文不会删除后来注册的同 ID 替代实例。

如果 `provider.onLoad(context)` 中途失败，加载器会回滚已启动的 Provider 和全部 context 资源，再关闭模块 classloader；Provider 不需要为 context 已跟踪的半加载资源额外编写失败清理。

## 安全热重载

```text
/kgc reload model <moduleId>
/kgc reload model all
```

命令需要 `kagamecenter.admin`，并在 Bukkit 主线程依次执行：

1. 关闭目标模块的全部运行房间。
2. 保存并关闭该模块全部地图编辑会话。
3. 调用 `provider.onUnload()`、`context.cleanup()` 并关闭 classloader。
4. 重新检查模块 jar 中缺失的 `config.yml` 和 `lang/` 资源。
5. 加载当前配置指向的 jar，并刷新托管游戏目录。

任一卸载清理步骤失败时不会再加载第二份同 ID 模块实例。模块重载是有损管理操作，活动房间会被关闭；仅修改主插件公共地图模板时应使用 `/kgc reload map`，该命令不触发模块重载。

以下资源必须由模块自己清理：

- 自建线程或 executor。
- 数据库、HTTP、Redis 等外部连接。
- 未通过 context 创建的 BukkitTask。
- 静态缓存和第三方回调。

## 配置归属

模块级 `config.yml` 适合：

- 显示名、人数和默认时间。
- 道具权重、角色比例等全局默认值。
- 公共地图列表。
- 观战策略。

具体托管游戏 yml 适合：

- 大厅、出生点和区域。
- 检查点、箱子、刷新点。
- 该地图专属规则覆盖。

主插件配置不保存小游戏专属字段。

## 模块私有语言

```text
src/main/resources/lang/zh_CN.yml
src/main/resources/lang/en_US.yml
```

```kotlin
val language = ModuleLanguage(
    context.plugin,
    context.languageManager,
    context.dataFolder,
    "lang"
) { path -> javaClass.classLoader.getResourceAsStream(path) }
language.reload()
```

玩法、道具、角色、结算和模块编辑器文本都放模块语言文件。主插件只保存通用房间、命令和菜单文案。

`ModuleLanguage` 的资源目录参数 `"lang"` 对应 JAR 根目录的 `lang/<locale>.yml`。运行文件只在缺失时释放，永不覆盖管理员修改；单个键缺失时依次回退 JAR 当前语言、外部英文、JAR 英文，最后才查询主插件语言。字符串与字符串列表共享该优先级，模块可用 `getMessageList` 读取多行内容，旧标量会自动视为单元素列表；这样模块升级新增文案无需修改旧文件，也不会产生 `lang/lang` 路径。

## 依赖声明

在 `GameDefinition` 中声明：

```kotlin
requiredPlugins = listOf("PacketEvents")
optionalPlugins = listOf("PlaceholderAPI")
```

- required 缺失时阻止创建房间。
- optional 缺失时模块自行降级。
- 模块不能依赖“服务器大概率安装”而跳过声明。
