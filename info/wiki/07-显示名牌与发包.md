# 07 显示、名牌与发包

更新时间：2026-07-16

## 主插件默认显示

玩家进入房间后，`GameDisplayService` 默认提供：

- sidebar 计分板。
- BossBar。
- 加入/准备/开始/关闭 Title。
- 状态 ActionBar。
- Tab header/footer、玩家列表名和排序。

模块可以接管：

```kotlin
override fun usesCustomScoreboard(): Boolean = true
override fun usesCustomActionBar(): Boolean = true
override fun usesCustomTabHeaderFooter(): Boolean = true
override fun usesCustomTabPlayerNames(): Boolean = true
```

模块接管后必须在玩家离开和房间关闭时清理自己的显示。

`usesCustomScoreboard()` 是房间级声明；如果模块只在部分阶段显示自定义 Sidebar，仍需在任一阶段可能接管时返回 `true`，并在切换到关闭阶段时仅清理自己曾渲染的玩家。全部阶段均关闭时才交回通用房间 Sidebar。

`usesCustomTabHeaderFooter()` 只转移 Tab 头尾所有权；主插件仍会更新玩家列表名称和 `playerListOrder`，但不再调用 `setPlayerListHeaderFooter` 覆盖模块内容。主插件在加入房间前保存原头尾，并在正常离房、踢出、关房或插件统一清理时恢复。模块应在成功加入、重连和阶段变化时写入初始内容，再按自身配置低频刷新；不要为接管头尾而停止通用玩家名称与排序。

`usesCustomTabPlayerNames()` 只转移 `playerListName` 所有权，核心仍为全部正式玩家和外部观战者维护 `playerListOrder`，并在离房与统一清理时恢复入房前名称和排序。该契约应保持房间级稳定：如果任一阶段会自定义名称就持续返回 `true`，由模块在关闭格式的阶段主动写入纯玩家名；全部阶段关闭时才返回 `false` 交回通用队伍名称。模块可覆盖 `tabPlayerListOrder(player, defaultOrder)`，在核心每 tick 计算默认值后按玩法阶段与身份返回非负顺序；不覆盖时正式玩家沿用队伍/未分组默认顺序，外部观战者稳定置后。

名称帧支持参考 `{vPrefix}` 与 `{vSuffix}`，分别通过可选 PlaceholderAPI 解析目标玩家的 `%vault_prefix%` 和 `%vault_suffix%`。PlaceholderAPI、Vault 或对应扩展缺失时两者为空，不显示原始占位符；既有外部语言文件不使用 token 时行为不变。名称模板和解析结果支持 `&`/`§` 旧式颜色，未着色文本继续使用玩法身份颜色。

模块需要原生生命 objective 时应只在实际展示阶段注册，并在阶段切换时清理；动画刷新不要重建不变的 Sidebar 行。

## 玩家头像状态

模块可通过 `GameSession.bossBarStatus()` 返回通用竞技状态快照，核心每 tick 更新同一条 Adventure BossBar，并自动同步正式玩家与观战者 viewer：

```kotlin
override fun bossBarStatus() = GameBossBarStatus(
    left = PlayerStatusSide(
        label = Component.text("A 队", NamedTextColor.GREEN),
        players = teamA.map { PlayerAvatarStatus(it.id, it.name, it.alive) }
    ),
    center = Component.text("01:30"),
    right = PlayerStatusSide(
        label = Component.text("B 队", NamedTextColor.RED),
        players = teamB.map { PlayerAvatarStatus(it.id, it.name, it.alive) }
    )
)
```

`PlayerStatusDisplayService.avatar()` 使用 `<head:玩家名>` 生成头像；存活头像默认 `<reset>`，阵亡头像固定红色，`aliveColor` 可覆盖存活颜色。BossBar 每侧最多显示 `maxHeadsPerSide` 个头像，默认和上限均为 5；模块应自行决定分队、排序和倒计时文本，不把角色语义写入主插件。

自定义 Sidebar 可调用 `context.playerStatusDisplayService.avatarRows(statuses)` 按每行最多 5 个头像生成 `Component`，再交给 `SidebarBoardRenderer.showComponents(...)`。Component 路径支持头像和物品图标，但不经过只接受字符串行的 `GameSidebarRenderEvent`。

## SidebarBoardRenderer

```kotlin
SidebarBoardRenderer.show(
    player = player,
    objectiveId = "example_${room.id}",
    title = Component.text("示例游戏"),
    lines = listOf(
        "§7房间 §f${room.id}",
        "§7阶段 §f$phase",
        "§a存活 §f${aliveCount}"
    )
)
```

- 最多 15 行。
- 自动处理重复行。
- objectiveId 使用短、稳定并包含 roomId 的名称。
- 不要每 tick 创建新 scoreboard；只在展示值变化或低频刷新时更新。

每次 `SidebarBoardRenderer.show` 创建并替换玩家计分板前会同步触发可取消的 `GameSidebarRenderEvent`。事件提供 `player/objectiveId`，并允许修改 `title/lines/maxLineLength/showHealthBelowName/showHealthInPlayerList/healthLabel`；行列表可原地增删排序，最终仍限制为 15 行且行长会约束在 1–128。取消只跳过本次默认渲染，保留玩家当前计分板，不会隐式调用 `clear`。

该事件对应参考项目 Sidebar 初始化扩展点，但适配 KaGameCenter 的低频无状态渲染器，因此每次 `show` 都会触发。监听器必须保持主线程轻量，并同时校验稳定 `objectiveId` 与玩家当前房间；需要完全接管显示时可以渲染自己的计分板后取消事件。

## RoomBroadcastService

```kotlin
roomBroadcastService.message(room, Component.text("游戏开始"))
roomBroadcastService.localized(room, language, "example.started", room.id)
roomBroadcastService.actionBar(room, Component.text("剩余 10 秒"))
roomBroadcastService.title(
    room,
    Component.text("开始"),
    Component.empty(),
    includeSpectators = true
)
```

- message 默认包含观战者。
- ActionBar/Title 默认只发正式玩家。
- 玩法文案使用模块 `ModuleLanguage`。

## 玩家名牌

```kotlin
context.nametagService.set(
    room,
    player,
    PlayerNametag(
        prefix = Component.text("[红队] ", NamedTextColor.RED),
        suffix = Component.text(" 3杀", NamedTextColor.GRAY),
        color = NamedTextColor.RED,
        visibility = NametagVisibility.ALWAYS,
        collisionRule = NametagCollisionRule.NEVER
    )
)
```

操作：

- `set(room, target, nametag, viewers)`。
- `refresh(room, target, viewers)`。
- `refreshViewer(room, viewer)`。
- `refreshRoom(room)`。
- `clear(room, target, viewers)`。
- `clearRoom(room.id)`。

稳定能力是 `前缀 + 原玩家名 + 后缀`，不是真正修改 Mojang 账号名。主插件会在加入、离开、房间关闭和插件关闭时刷新或清理。

Minecraft 同一 scoreboard entry 只能属于一个客户端队伍。名牌、发光颜色和其他 Teams 视觉同时作用于玩家时，需要实服验证；不要在模块中自行发送 Teams 包。

Teams 包中的碰撞规则只描述客户端队伍状态，不能单独替代服务端碰撞判定。需要“同队不碰撞、敌队可碰撞”的玩法应同时启用玩家 `isCollidable`，并把同队 UUID 加入 `collidableExemptions`；无碰撞观战状态应关闭 `isCollidable` 并清空临时例外。KaGameCenter 的完整玩家快照和 `PlayerRuntimeStateService` 都会保存、恢复碰撞开关与例外集合。

## PacketDispatchService

当前业务接口：

```kotlin
packetService.disguisePlayerAsBlock(target, material, viewers, durationSeconds)
packetService.disguisePlayerAsMob(target, entityType, viewers, durationSeconds)
packetService.clearDisguise(target, viewers)
packetService.showBlockGlow(viewer, location, durationSeconds, color)
packetService.showPlayerGlow(viewer, target, durationSeconds)
packetService.showPrivateDrop(viewer, location, itemStack, durationSeconds)
packetService.showPrivatePickup(
    viewer,
    location,
    itemStack,
    glowing,
    color,
    durationSeconds,
    scale
) { picker ->
    // 再次校验 picker 的房间、角色、阶段和存活状态。
}
packetService.showBeaconBeam(viewer, location, color, durationSeconds)
packetService.clearViewer(viewer)
```

模块不直接使用 `sendPlayerNametag/clearNametagTeam`；它们是 `PlayerNametagService` 的底层接口。

## 方块和生物伪装

- 方块伪装使用只对指定 viewer 可见的 BlockDisplay。
- 固定旋转，避免方块随玩家视角倾斜。
- 2 tick 跟随并使用客户端插值，不每 tick teleport。
- 生物伪装使用 PacketEvents 假实体和移动/旋转/head look 包。
- 真实玩家通过 viewer metadata overlay 保持隐身，避免移动后短暂现形。

## 发光和私有拾取

- 方块轮廓通过无碰撞 BlockDisplay + glowing team 实现，不修改真实方块。
- 玩家发光是指定 viewer 可见。
- 私有拾取物每个 viewer 有自己的显示实体，但奖励唯一性必须由模块共享道具 ID 控制。
- 拾取回调可能晚于状态变化，必须重新检查 session。
- 房间关闭前主动清理长期视觉，不完全依赖过期计时。

## 依赖和降级

```kotlin
requiredPlugins = listOf("PacketEvents")
```

PacketEvents 不存在时 PacketDispatchService 视觉为空操作。核心玩法依赖伪装或私有视觉时应设为 required；纯提示增强可以 optional 并提供降级效果。

## 图标文本

主插件显示层支持解析物品和玩家头像图标文本。具体语法以当前 `IconTextParser` 和菜单渲染器为准；图标并非所有客户端文本位置都保证可显示，BossBar、Title、sidebar 等应分别实测。
