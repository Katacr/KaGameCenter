# 06 队伍、聊天与观战

更新时间：2026-07-13

## 注册队伍

```kotlin
context.teamAssignmentService.registerTeams(
    room.id,
    listOf(
        GameTeam("red", "红队", NamedTextColor.RED, maxPlayers = 8),
        GameTeam("blue", "蓝队", NamedTextColor.BLUE, maxPlayers = 8)
    )
)
```

分配方式：

```kotlin
teamAssignmentService.joinSmallestTeam(room.id, player, listOf("red", "blue"))
teamAssignmentService.assignRoundRobin(room.id, room.players, listOf("red", "blue"))
teamAssignmentService.assignRatio(room.id, room.players, "hunter", "hider", 0.25)
```

服务只理解队伍 ID 和人数，不理解猎人、躲藏者等玩法语义。模块必须把返回队伍同步到自己的 PlayerState。

动态转队：

```kotlin
teamService.join(room.id, player, "red")
```

再次 join 会覆盖该玩家原队伍。离开房间和关闭房间由主插件清理通用队伍记录。

## 聊天频道

- 玩家不在房间：服务器默认聊天。
- 玩家在房间且有队伍：普通聊天只发给同房间同队伍成员。
- 玩家在房间但无队伍：普通聊天发给当前房间玩家和观战者。
- `/a <消息>`：默认请求当前房间频道，玩法可通过 Session 路由钩子进一步限制或冷却。
- `/g <消息>`：本服全部在线玩家。

`/a` 不是跨房间或跨服全局，`/g` 当前也只是本服全局。

## 模块聊天格式

```kotlin
context.registerChatFormatter { chat ->
    when (chat.channel) {
        GameChatChannel.TEAM -> language.getMessage(
            "example.chat_team",
            chat.team?.displayName ?: "-",
            chat.player.name,
            chat.message
        )
        GameChatChannel.ROOM -> language.getMessage(
            "example.chat_room",
            chat.room.id,
            chat.player.name,
            chat.message
        )
        GameChatChannel.GLOBAL -> null
    }
}
```

- 格式器按模块 ID 注册，不影响其他模块。
- 返回 null 时使用主插件默认格式。
- 抛异常时主插件记录警告并回退默认格式。
- 格式文本放模块私有语言文件。

## 玩法路由

`GameSession.routeChat(player, message, requestedChannel)` 在主线程执行。默认实现返回原频道；玩法可返回 `GameChatRoute(channel, message, variant, audience)`，用于阶段聊天、喊话冷却或观战者隔离。`audience` 中的 UUID 会被限制在当前房间，返回 `null` 表示消息已被玩法拒绝；格式器可读取 `chat.variant` 选择同频道下的不同文本样式。

## 聊天串台防护

- 受众从当前 `room.id` 和 team 成员现算。
- 不用玩家名作为身份键，使用 UUID。
- 不缓存跨 tick 的在线 Player 列表。
- 玩家转队后立即更新 `GameTeamService`。
- 默认情况下观战者可以看到 `/a`，但玩法可将观战输入和受众隔离为私有观战频道。

## 管理员旁听

```yaml
chat:
  enabled: true
  spy:
    enabled: false
```

同时要求 `kagamecenter.chat.spy`。阵营隐藏玩法默认关闭旁听，避免泄露信息。

## 观战策略

```kotlin
override fun defaultDefinition() = GameDefinition(
    id = id,
    displayName = displayName,
    spectatorPolicy = SpectatorPolicy(
        enabled = true,
        mode = SpectatorMode.MANAGED,
        allowDuringRunning = true,
        allowFreeFly = true,
        allowFollowPlayer = true,
        revealHiddenPlayers = false,
        delaySeconds = 0
    )
)
```

模式：

- `VANILLA`：使用原版观察者模式。
- `MANAGED`：主插件管理飞行/跟随和观战快捷栏。

玩法需要按地图、玩家权限或其他单局数据限制外部观战时，可覆盖玩家级准入钩子：

```kotlin
override fun canSpectate(room: GameRoom, player: Player): Boolean {
    return roomAllowsSpectators(room) || player.hasPermission("example.admin")
}
```

该方法默认返回 `true`，并在主插件捕获快照、写入 `room.spectators` 和应用观战模式之前执行；它不影响玩法内部把已参赛玩家标记为淘汰。

托管观战快捷栏提供：

- 跟随下一个玩家。
- 打开房间菜单。
- 离开房间。

`SpectatorPolicy.hotbarItems` 可用 `SpectatorHotbarItem` 覆盖默认布局。每项支持 `material/slot/enchanted/displayName/lore`，并选择一个内建 `SpectatorAction` 或玩家命令：

```kotlin
hotbarItems = listOf(
    SpectatorHotbarItem("follow", Material.PLAYER_HEAD, 0, action = SpectatorAction.FOLLOW),
    SpectatorHotbarItem("leave", Material.RED_BED, 8, command = "kagamecenter leave")
)
```

槽位只接受 `0..8`，空气材质会被忽略，重复槽位以后配置覆盖前项，命令会移除开头 `/` 并限制为 256 字符。项目同时配置动作和命令时只执行动作；命令只从主插件写入的 `spectator_command` PDC 读取，客户端名称或 Lore 不能触发命令。策略在进入观战时捕获布局快照，运行中的配置变化不会改写已发放的快捷栏。

## 模块观战回调

```kotlin
override fun onSpectatorJoin(player: Player) {
    // 补发模块显示、传送到观战点、隐藏敏感信息。
}

override fun onSpectatorLeave(player: Player) {
    // 清理模块只对观战者显示的对象。
}
```

主插件负责通用模式和快捷栏；模块负责玩法专属限制，例如延迟观战、隐藏角色、只跟随存活玩家。

需要过滤快捷栏跟随目标时覆盖 Session 钩子；主插件仍会先限制目标必须属于当前房间：

```kotlin
override fun canSpectatorFollow(spectator: Player, target: Player): Boolean {
    return states[target.uniqueId]?.let { it.alive && !it.respawning } == true
}
```

## 观战目标事件

`SpectatorService.follow` 在托管传送或原版第一人称镜头提交前触发可取消的 `GameSpectatorTargetSelectEvent`。事件提供 `roomId/spectator/target/mode`；`TELEPORT` 表示 `MANAGED` 模式传送，`FIRST_PERSON` 表示 `VANILLA` 模式设置 `spectatorTarget`。取消后保留原目标、镜头和位置，托管模式的 Bukkit 传送失败也不会提交目标。

实际目标改变或清除后触发不可取消的 `GameSpectatorTargetChangedEvent`，提供前后目标 UUID、可空在线 Player 和相同模式。初始自动跟随、快捷栏循环、切换玩家、原版潜行退出、目标死亡/离房、观战退出和在线房间清理都走统一路径；重复选择同一目标仍允许执行选择动作，但不会伪造 changed 事件。

原版第一人称镜头提交或清除后还会发布不可取消的 `GameSpectatorFirstPersonFeedbackEvent`。事件以 `ENTER/LEAVE` 区分反馈，允许替换或置空 `title/subtitle`，并修改默认 0/40/10 tick 的淡入、停留和淡出时长；最终值限制为 0–72000。进入前拒绝继续使用选择事件，因而不会出现反馈监听器取消已经提交镜头的情况。切换目标和重复选择可再次显示进入标题，潜行退出、目标失效、观战退出和在线房间清理显示退出标题；托管传送模式不发布。

这些事件只覆盖 `SpectatorService` 管理的目标。模块不要直接写 `player.spectatorTarget` 或自行维护另一个跟随集合；玩法只通过 `canSpectatorFollow` 过滤候选目标，具体切换继续交给主插件。

## 淘汰转观战

模块判定玩家淘汰后使用统一服务；默认保持原版观战模式，需要参考玩法快捷栏时可传入托管策略：

```kotlin
eliminationService.eliminate(
    room,
    player,
    spectatorLocation,
    spectatorPolicy = SpectatorPolicy(mode = SpectatorMode.MANAGED)
)
```

托管淘汰只登记观战表现，不会把历史参赛者从 `room.players` 移到 `room.spectators`。快捷栏继续提供跟随、房间菜单和离开；离房、结算恢复或关房时必须让通用生命周期清除淘汰与观战状态。

模块仍需：

- 在 session 内将玩家标记为淘汰。
- 停止伤害、拾取和玩法输入。
- 确保统计只记录一次。

不要直接把玩家从 `room.players` 移到 `room.spectators` 而跳过生命周期；这会绕过显示、快照和观战服务。
