# 09 并发隔离与资源清理

更新时间：2026-07-13

## 多房间状态归属

必须属于 `GameSession`：

- 玩家状态 `Map<UUID, PlayerState>`。
- 当前玩法 phase 和计时器。
- 存活/淘汰/完成集合。
- 模块未交给 `RoomResourceScope` 托管的临时实体 UUID、道具 ID 和方块恢复数据。
- 当前世界中的箱子、检查点和动态区域。
- 获胜者和结算标记。

可以属于模块级服务：

- 只读模块配置。
- 托管游戏配置读写器。
- 语言管理器。
- 无单局状态的编辑器和 listener。

主插件通用服务可以按 `roomId` 保存纯资源生命周期数据，例如淘汰观战表现和 `RoomResourceScope`；玩法存活、角色、阶段和胜负状态仍必须留在 Session。

禁止：

- Provider 保存玩家列表。
- ConfigService 保存当前房间。
- Listener 保存某局 phase。
- 用玩家名称代替 UUID。
- 用世界名称推断所有玩法身份而不验证 room。

## Listener 路由模板

```kotlin
private fun session(player: Player): ExampleGameSession? {
    val room = roomManager.getPlayerRoom(player) ?: return null
    return room.session as? ExampleGameSession
}
```

实体事件还应校验：

```kotlin
val ownership = entityOwnershipService.record(entity.uniqueId) ?: return
val room = roomManager.getRoom(ownership.roomId) ?: return
val session = room.session as? ExampleGameSession ?: return
```

不能只根据实体 PDC type 就遍历所有房间尝试处理。

## 回调二次校验

延迟任务、私有拾取和异步结果回调执行时，原状态可能已经变化：

```kotlin
val currentRoom = roomManager.getPlayerRoom(player) ?: return@callback
if (currentRoom.id != room.id) return@callback
if (room.session !== this) return@callback
if (phase != ExamplePhase.RUNNING) return@callback
if (player.uniqueId !in alivePlayers) return@callback
```

不要捕获旧 GameRoom 后无条件使用。

## Bukkit 主线程

只能在主线程：

- 传送玩家。
- 修改背包、游戏模式、药水和计分板。
- 创建/删除世界、方块和实体。
- 调用大部分 Bukkit/Paper API。
- 修改主插件房间结构。

可以异步：

- 数据库、Redis、HTTP 和文件 IO。
- 纯 DTO 序列化。
- 不触碰 Bukkit 对象的计算。

异步结果需要用 Bukkit scheduler 切回主线程，再检查房间仍存在。

## 高频逻辑

- `GameSession.onTick()` 每房间每 tick 调用，保持常数级轻量操作。
- 区域触发优先在 PlayerMoveEvent 中比较 block 坐标变化，避免每 tick 扫描所有区域和玩家。
- 计分板、BossBar 和名牌只在内容变化或固定低频刷新。
- 多个同类视觉对象尽量共享调度，不为每个对象永久创建任务。
- 不在 tick 中扫描服务器全部玩家、世界或实体。
- 空间遮挡计算使用固定上限采样并允许提前结束。BedWars 爆炸只检查 27 条射线，达到 22 条阻挡立即成功，剩余射线已不可能达到阈值时立即失败，不按世界体积扩张扫描。

## 玩家离开

`onPlayerLeave` 至少检查：

- 从模块 states/alive/finished 集合移除。
- 清理其私有伪装、发光、拾取物和名牌设置。
- 恢复临时方块和删除命中盒。
- 取消玩家专属任务。
- 处理“离开是否算淘汰/失败”。
- 动态队伍/角色变化是否影响胜负。

主插件会恢复完整 PlayerSnapshot，但模块仍需恢复自己创建的外部对象。

使用断线重连钩子时，临时断线不能立即执行上述最终离开清理。模块应在 `onPlayerDisconnect` 只暂停输入，在 `onPlayerReconnect` 恢复状态，并在 `onPlayerReconnectExpired` 或 `onClose` 才释放玩家私有资源。

## 房间关闭

推荐 `onClose()`：

```kotlin
override fun onClose() {
    playerRuntimeStateService.restoreRoom(room.id, room.players.mapNotNull(Bukkit::getPlayer))
    playerRuntimeStateService.clearRoom(room.id)
    states.clear()
}
```

使用 `RoomResourceScopeService.open(room.id)` 后，任务、已登记实体、实体归属、已捕获方块、Packet viewer 和房间名牌由 `GameRoomManager.closeRoom()` 自动清理。模块不要再重复维护同一批 UUID/BlockData 集合。

根据模块实际资源调整，不要重复统计或再次调用关闭。

## Provider 卸载

- `onUnload()` 关闭模块私有连接、executor 和静态缓存。
- context 注册的 listener/task/formatter/data source 自动清理。
- 插件关闭前 `GameRoomManager.stop()` 会关闭房间。
- 热重载尚不承诺安全；不要设计依赖 `/reload` 的工作流。

## 常见串台故障

| 故障 | 根因 |
| --- | --- |
| A 房间道具被 B 房间拾取 | 回调只检查玩家类型，未检查 roomId |
| 一个房间结束取消所有模块任务 | 使用全局任务列表而非 RoomTaskService |
| 不同房间玩家收到同队聊天 | 模块自行广播，未使用 GameChatService |
| 编辑坐标运行时失效 | 配置保存了编辑世界名 |
| 关闭后临时方块残留 | 原 BlockData 未按 session 保存和恢复 |
| 玩家回大厅仍隐身/飞行 | 离开路径没有统一恢复 |
| 旧菜单关闭新房间 | 点击使用已失效 GameRoom 引用 |

## 压力测试建议

- 同一模块同时开启至少 3 个房间。
- 不同模块同时运行。
- 玩家在等待、倒计时、运行、结算阶段退出。
- 观战者加入/离开/跟随。
- 强制管理员关闭房间。
- 插件停止时存在活动房间和编辑世界。
- 检查 Bukkit task、实体、临时世界目录和玩家状态是否归零。
