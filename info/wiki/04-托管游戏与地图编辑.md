# 04 托管游戏与地图编辑

更新时间：2026-07-14

## 两个不同概念

管理员创建托管游戏：

- 定义一个可重复开房的具体玩法配置。
- 创建独立 yml。
- 从公共模板复制一份私有地图快照。
- 后续编辑只修改私有快照。

玩家创建房间：

- 选择已有托管游戏。
- 创建四位房间 ID。
- 从该托管游戏私有快照复制临时运行世界。
- 对局结束后删除运行世界，不删除托管游戏。

## 目录

```text
公共模板：plugins/KaGameCenter/maps/<module>/<map>/
托管配置：plugins/KaGameCenter/modules/<module>/games/game/<localId>.yml
私有快照：plugins/KaGameCenter/modules/<module>/games/map/<localId>/
```

公共模板至少包含：

```text
level.dat
region/*.mca
```

不要依赖 `session.lock` 作为模板有效性条件；它是运行时锁文件。

## 托管游戏基础字段

```yaml
id: test
module: example
selector-group: default
display-name: "测试游戏"
enabled: true
shared-map-template: "example/default"
runtime-map-template: "modules/example/games/map/test"
min-players: 1
max-players: 16
description: ""
```

模块私有字段放在自己的节点：

```yaml
example:
  lobby: {}
  spectator-spawn: {}
  play-region: {}
  item-spawns: []
```

坐标不保存运行世界名。房间世界随机生成，运行时把模板绝对坐标应用到 `room.world`。

`selector-group` 是通用房间选择器分组，默认 `default`。`default` 与参考 BedWars 语义一致，表示不限制分组；其他值应使用最多 32 字符的稳定单词 ID。`/kgc selector <moduleId> <group>` 会筛选同模块的该组托管玩法，分组同时写入 Velocity 房间标签；旧端未提供标签时安全视为 `default`。

## ModuleGameEditor

```kotlin
interface ModuleGameEditor {
    val moduleId: String

    fun populateDefaults(
        config: YamlConfiguration,
        localId: String,
        displayName: String,
        sharedMapTemplate: String
    )

    fun openEditor(player: Player, game: ManagedGameConfig)

    fun handleAction(
        player: Player,
        game: ManagedGameConfig,
        action: String,
        variables: Map<String, String>
    ): Boolean
}
```

- `populateDefaults` 创建玩法字段空结构。
- `openEditor` 生成模块编辑菜单。
- `handleAction` 处理设置点位、区域、列表增删和世界保存。

注册：

```kotlin
context.registerGameEditor(ExampleManagedGameEditor(...))
```

## 模块管理命令

模块可通过 `context.registerAdminCommand(...)` 注册 `/kgc admin <module> ...`，权限由主命令统一要求 `kagamecenter.admin`。管理命令应复用 `ModuleGameEditor` 和 `MapEditorService`，不能另写一套点位与快照修改路径。

BedWars 当前提供 `reload/list/edit`，以及仅在对应私有编辑世界内可用的 `setlobby/setspectator/setvoidy/setmaxbuildy/save/close/validate/preview`。`list` 同时显示托管玩法是否启用、私有快照是否存在和配置缺失项数量；`edit <bedwars:localId>` 打开标准托管编辑菜单。模块卸载时上下文会自动移除管理命令。

BedWars 房间准备前会执行与 `validate` 相同的关键点校验；缺少大厅、观战点、两队完整点位或铁/金/钻石/绿宝石生成器，存在归一化后重复队伍 ID，或坐标为非有限数/超出 Minecraft 水平范围时不会创建临时世界。副本加载后还会确认全部点位位于实际世界高度和边界内、每个床点对应真实床方块；失败时立即卸载该临时世界并拒绝本次加入。

BedWars 模块级人数限制在 2–100 且保证 `min <= max`；每队容量限制在 1–100。房间准备时会把托管游戏的最小/最大人数收敛到实际队伍总容量，避免菜单和 Velocity 广告人数超过可分配席位。

## 打开编辑世界

```kotlin
mapEditorService.openEditorDirectory(
    player,
    game.globalId,
    game.runtimeMapFolder
) { world -> world.spawnLocation }
```

编辑器会：

- 关闭玩家原编辑会话。
- 保存原位置和模式。
- 从私有快照创建 `kgc_edit_*` 世界。
- 传送管理员并允许修改方块。

设置字段后调用：

```kotlin
mapEditorService.saveIfEditing(game.globalId)
```

关闭时根据需求保存或放弃：

```kotlin
mapEditorService.closeCurrentSession(player, save = true)
```

## 编辑会话事件

`GameMapEditSessionStartedEvent` 只在共享会话及 `kgc_edit_*` 世界首次创建、首位编辑者完成状态切换和传送后发布。事件提供稳定 `sessionId/worldName/editorId/editor`；其他管理员加入既有会话或同一管理员重新打开时不会重复发布。

`GameMapEditSessionClosedEvent` 在会话索引移除、在线编辑者状态恢复、保存尝试和临时世界清理均结束后发布。事件提供不可变的全部编辑者 UUID，以及 `saveRequested/saveSucceeded/restoreEditorsRequested/worldCleanupSucceeded`。关闭时会清除在线和离线编辑者的会话索引；`closeSession` 只有在请求的保存及世界清理都成功时才返回 `true`，但无论哪一步失败都会发布关闭结果，便于外部告警。

两个事件都不可取消。关闭监听器不能再访问编辑世界；需要读取或修改地图内容时应在显式保存操作之前完成。

## 石斧选区

主插件 `SelectionListener` 提供石斧两点选区：

```kotlin
val region = context.selectionService.getSelection(player) ?: return
val portable = context.managedMapPointService.portable(region)
```

通用点位读写：

```kotlin
val points = context.managedMapPointService.readNamedPoints(section, "item-spawns")
val point = context.managedMapPointService.fromLocation(player.location)
context.managedMapPointService.upsertNamedPoint(config, "example.item-spawns", "item_1", point)
```

建议：

- 区域使用整数 min/max。
- 点位使用方块对齐坐标，需要站立中心时运行时加 `0.5`。
- 运行时区域判断忽略编辑世界名。
- 列表 ID 使用稳定编号，删除后不要依赖数组下标作为身份。
- 单点、命名点位列表和无世界选区优先使用 `ManagedMapPointService`，不要在模块重复实现 YAML 转换。

石斧未指向方块时也可以完成选点：

- 左键空气把 `pos1` 设置为玩家脚下的整数方块坐标。
- 右键空气把 `pos2` 设置为玩家脚下的整数方块坐标。
- 指向方块点击时仍优先使用目标方块坐标。

这适合配置虚空高度、空气区域或难以点击到实体方块的边界。

## 骨头连续采点

需要连续添加出生点、容器或方块位置时，模块应通过 `editorPointCaptureService` 启动采集模式：

```kotlin
context.editorPointCaptureService.beginPositionCapture(player, context.id) { editor, location ->
    // 保存玩家脚下的整数位置；返回 true 继续采集。
    true
}

context.editorPointCaptureService.beginBlockCapture(player, context.id) { editor, location ->
    // 保存左键目标方块；返回 true 继续采集。
    true
}
```

- 进入模式时主插件关闭当前 Dialog/箱子菜单并自动发放带标记的骨头。
- 方块模式使用骨头左键目标方块，适合箱子、刷新方块和容器。
- 位置模式使用骨头右键，记录玩家脚下整数坐标并保留朝向。
- 回调返回 `false`、玩家退出、编辑世界关闭或模块卸载时自动结束。
- 模块重新打开编辑菜单时应主动调用 `cancel(player)`，避免旧采集模式继续接收点击。
- 连续采集的稳定 ID 由模块配置服务生成，不要求管理员逐个输入编号。

## 世界边界与区块

`TemporaryWorldService` 会根据模板 region 文件计算边界，并应用 world border/区块生成限制。模块不要通过玩家移动监听实现大范围边界阻挡，除非玩法需要比模板边界更小的动态区域。

## 保存安全

- 只保存到托管游戏私有快照。
- 保存前确保世界区块落盘。
- 清理运行时 UUID、session.lock 和玩家数据。
- 文件操作必须由 `minecraft` 用户可读写。
- 地图复制失败时不要继续创建可玩的房间。
- 编辑器异常退出后依赖主插件启动清理遗留 `kgc_edit_*` 世界。
