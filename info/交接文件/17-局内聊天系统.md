# 17-局内聊天系统

更新时间：2026-07-13

## 已完成

- 新增 `GameChatService`。
- 新增 `GameChatListener`。
- 新增 `/a <消息>` 房间聊天命令，命令名为 `allchat`，别名为 `a`。
- 新增 `/g <消息>` 服务器全局聊天命令，命令名为 `globalchat`，别名为 `g`。
- 玩家不在房间时，聊天保持服务器默认行为。
- 玩家在房间内时，默认聊天优先进入队伍频道：
  - 如果玩家属于某个队伍，只发送给同房间同队伍成员。
  - 如果玩家没有队伍，回退到房间聊天。
  - 不广播到其他房间或大厅玩家。
- 玩家在房间内如需向房间内玩家和观战者聊天，使用 `/a <消息>`。
- 普通聊天默认优先进入队伍频道；没有队伍时才回退为房间频道。
- 玩家在房间内如需和房间外玩家互动，使用 `/g <消息>`。
- 可选管理员旁听已实现：配置开启且玩家拥有 `kagamecenter.chat.spy` 时，可收到自己不在受众内的房间/队伍聊天副本。

## 当前配置

```yaml
chat:
  enabled: true
  spy:
    enabled: false
```

旁听默认关闭，避免阵营玩法泄露队伍信息。需要同时满足：

- `chat.spy.enabled: true`
- 旁听玩家拥有 `kagamecenter.chat.spy`

## 当前语言键

```yaml
chat:
  global_usage: "用法: /{0} <消息>"
  global_format: "§7[全局] §f{0}: §r{1}"
  room_format: "§8[§e房间 {0}§8] §7{1} §f{3}: §r{4}"
  team_format: "§8[§b队伍 {2}§8] §f{3}: §r{4}"
  spy_format: "§8[§7旁听 {0}§8] §7{1}"
```

`room_format` 参数：

- `{0}` 房间 ID
- `{1}` 房间名称
- `{2}` 游戏名
- `{3}` 玩家名
- `{4}` 消息

`team_format` 参数：

- `{0}` 房间 ID
- `{1}` 房间名称
- `{2}` 队伍名
- `{3}` 玩家名
- `{4}` 消息

## 技术说明

- 使用 Paper `AsyncChatEvent`。
- 监听器在异步事件中只判断是否需要接管聊天。
- 真正发送房间聊天回到 Bukkit 主线程执行，避免异步访问 Bukkit 房间/玩家对象。
- 主插件只提供通用队伍与聊天能力，不包含任何具体小游戏身份逻辑。
- 房间聊天和队伍聊天都会输出到控制台，便于后台审计。
- 旁听只发送给不在原始受众内、且有 `kagamecenter.chat.spy` 权限的在线玩家。

## 模块接入

小游戏模块如果希望默认聊天进入队伍频道，需要自行：

- 通过 `GameModuleContext.teamService` 注册队伍。
- 在玩家身份/队伍变化时调用 `teamService.join(room.id, player, teamId)`。
- 在玩家离开、房间关闭时无需额外清理，`GameRoomManager` 会清理房间队伍数据。
- `/a <消息>` 默认请求房间频道；玩法可通过 `GameSession.routeChat` 调整、冷却或拒绝。
- `/g <消息>` 始终是服务器全局频道。

小游戏模块如果希望自定义聊天格式，需要调用：

```kotlin
context.registerChatFormatter { chat -> ... }
```

规则：

- 格式器按模块 ID 生效，不会影响其他小游戏模块。
- 返回字符串表示模块接管格式。
- 返回 `null` 时回退主插件默认格式。
- 模块卸载时自动注销。
- 具体小游戏格式应放在模块私有语言文件内，主插件只保留通用默认格式。
- 如果模块格式器抛出异常，主插件会记录警告并回退默认格式，避免聊天中断。

需要按玩法阶段改变频道或受众时覆盖 `GameSession.routeChat`。返回的 `GameChatRoute` 可改写频道、消息、格式变体和显式 UUID 受众；主插件会把非全局显式受众限制在当前房间。返回 `null` 表示玩法已经拒绝消息，适合冷却提示。未覆盖该方法的模块维持“有队伍则队伍频道，否则房间频道”的原行为。
