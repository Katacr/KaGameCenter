# 玩家名牌服务

更新时间：2026-07-13

## 用途

`PlayerNametagService` 为小游戏模块提供按房间隔离的玩家头顶名牌能力：

- 前缀
- 后缀
- 队伍颜色
- 名牌可见性
- 碰撞规则
- 指定 viewer 可见

实现位于 `org.katacr.kaGameCenter.nametag`，底层通过 `PacketDispatchService` 发送 PacketEvents Teams 包，不依赖玩家当前 sidebar 记分板。

## 调用

```kotlin
context.nametagService.set(
    room,
    player,
    PlayerNametag(
        prefix = Component.text("[猎人] ", NamedTextColor.RED),
        suffix = Component.text(" 3杀", NamedTextColor.GRAY),
        color = NamedTextColor.RED,
        visibility = NametagVisibility.ALWAYS,
        collisionRule = NametagCollisionRule.NEVER
    )
)
```

常用操作：

- `set(room, target, nametag, viewers)`
- `refresh(room, target, viewers)`
- `refreshViewer(room, viewer)`
- `refreshRoom(room)`
- `clear(room, target, viewers)`
- `clearTarget(targetId)`
- `clearViewer(viewer)`
- `clearRoom(roomId)`

## 生命周期

- 模块设置后，配置按 `roomId + target UUID` 保存。
- 新玩家/观战者加入房间时补发已有名牌。
- 目标离开时清除其名牌，viewer 离开时清除其客户端队伍缓存。
- 房间关闭和插件关闭时统一清理。
- 重发前先移除同名客户端队伍，避免重复 CREATE。
- Teams 碰撞字段仅维护 viewer 看到的客户端队伍规则；需要真实实体碰撞时，模块还必须同步 Bukkit `isCollidable` 与 `collidableExemptions`。

## 边界

- 稳定支持的是 `prefix + 原玩家名 + suffix`，不能替换 Mojang 账号名。
- 真正改名涉及玩家信息/profile 包、皮肤与客户端缓存，不属于当前服务。
- Minecraft 同一 scoreboard entry 只能属于一个队伍；名牌、发光颜色和其他 Teams 视觉同时作用于同一玩家时需要实服验证，后续可考虑统一队伍视觉状态。
- `CollisionRule.PUSH_OTHER_TEAMS` 不能凭单目标私有 Teams 包实现完整服务端同队判定。模块需要“同队不碰撞、敌队可碰撞”时应使用同队 UUID 例外，并由运行状态和完整玩家快照恢复原碰撞开关及例外集合。
- 强依赖名牌的模块应声明 `PacketEvents` 为 required plugin。
