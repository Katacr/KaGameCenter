# 跨服房间摘要与通讯

更新时间：2026-07-13

## 当前结论

跨服层只维护房间摘要和加入流程，局内玩法始终由目标 Paper 游戏服本地运行。当前主插件已经实现 Redis 侧桥接，不再只是接口预留。

实现：

- `VelocityBridgeService`
- `NoopVelocityBridgeService`
- `RedisVelocityBridgeService`
- `VelocityRoomSnapshot`
- reservation request/response
- join intent
- proxy join request

## 房间摘要

摘要包含协议版本、服务器 ID、房间 ID/名称、游戏 ID/显示名、地图、状态、玩家数、上限、观战数、是否可加入和更新时间。

触发更新：

- 创建房间。
- 准备/开始和状态变化。
- 玩家或观战者加入/离开。
- 房间关闭。
- 定时心跳刷新 TTL。

菜单读取本地缓存的全局摘要，不在玩家打开菜单时同步等待 Redis。

## 远程加入闭环

```text
Paper 菜单点击远程房间
  -> 写 proxy join request
  -> Velocity 消费请求
  -> 写目标服 reservation request
  -> 目标 Paper 回主线程校验房间
  -> 写 reservation response + join intent
  -> Velocity 转服
  -> 目标 Paper 在 PlayerJoinEvent 消费 intent
  -> GameRoomManager.joinRoom
```

目标服检查房间存在、仍可加入且未满。请求和 intent 都有 TTL，避免玩家没有完成转服时永久占位。

## Redis Key

前缀默认为 `kgv`：

```text
kgv:server:<serverId>
kgv:room:<serverId>:<roomId>
kgv:reserve:req:queue:<serverId>
kgv:reserve:req:<requestId>
kgv:reserve:res:<requestId>
kgv:join:req:queue
kgv:join:req:<requestId>
kgv:intent:<intentId>
kgv:intent:player:<playerId>
```

reservation 队列按目标服务器拆分，避免多个 Paper 实例竞争并误消费其他服务器请求。当前使用 Redis List 保存 request ID，不使用 `KEYS` 扫描。

## 配置

```yaml
velocity:
  enabled: false
  server-id: game-1
  snapshot-ttl-seconds: 15
  heartbeat-interval-seconds: 5
  room-list-poll-interval-seconds: 1
  reservation-poll-interval-ms: 250
  join-intent-ttl-seconds: 15
  redis:
    enabled: true
    host: 127.0.0.1
    port: 6379
    password: ""
    database: 0
    ssl: false
    key-prefix: kgv
```

## 线程边界

- Redis IO、JSON 序列化和缓存刷新在异步执行器。
- 房间校验和玩家加入切回 Bukkit 主线程。
- 不在主线程等待 Redis/Velocity 响应。
- 不同步玩家坐标、方块、实体、计时器、显示或 PacketEvents 视觉。
