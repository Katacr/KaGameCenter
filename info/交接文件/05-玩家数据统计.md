# 玩家数据统计

更新时间：2026-07-13

## 当前模型

主插件统一保存每个玩家、每种模块的基础统计：

- `plays`
- `wins`
- `losses`
- `kills`
- `deaths`
- `points`
- `updated_at`

数据库表为 `kgc_player_stats`，主键由玩家 UUID 和 `game_id` 组成。

玩法专属整数计数保存于 `kgc_player_metrics`，联合主键为玩家 UUID、`game_id` 和 `metric_id`；例如 BedWars 使用 `final-kills`、`final-deaths` 和 `beds-destroyed`。

## 存储后端

- 默认 SQLite：`plugins/KaGameCenter/data/kagamecenter.db`。
- 可配置 MySQL。
- HikariCP 管理连接池。
- 数据库禁用或初始化失败时回退内存仓库，并记录日志。

当前写入是服务调用时直接保存，不应把它描述为已有异步写入队列。

## 模块调用

优先使用 `GameResultService`：

```kotlin
resultService.recordKill(room, killerId, victimId, points = 1)
resultService.recordDeath(room, playerId)
resultService.recordWin(room, playerId, points = 3)
resultService.recordLoss(room, playerId)
resultService.recordWinLoss(room, participants, winners, winPoints = 3)
resultService.addMetric(room, playerId, "beds-destroyed")
val beds = resultService.metric(room, playerId, "beds-destroyed")
```

房间加入成功会由主插件记录 `play`。模块不要直接操作 `StatsRepository` 或自行拼接统一表的 `game_id`。

玩家战绩菜单由 `GameCenterMenuService.openStatsMenu` 统一生成，可从主菜单、房间菜单和 `/kgc stats [gameId]` 打开。房间内默认展示当前玩法，概览页合并基础记录与只有扩展指标的历史玩法。

## 边界

- 当前未实现完整成就、赛季、连胜、MVP 或排行榜系统。
- 可累加整数优先使用通用扩展指标；路线成绩、宝箱明细等非计数数据仍由模块私有存储，并在卸载时关闭连接。
- 经济、物品和权限奖励不属于当前基础统计服务。
