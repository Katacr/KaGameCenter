# 多房间游戏框架

更新时间：2026-07-13

## 设计目标

模块化运行需要保证：

- 同一个小游戏可同时开多个房间。
- 不同小游戏可同时运行。
- 房间 ID 当前为全局唯一 4 位数字，便于玩家快捷输入加入。
- 玩家可创建房间；创建房间不是管理员专属能力。
- 每个房间独立状态、计时器、队伍、世界、显示组件。
- 玩家只能属于一个 active room。

- `COUNTDOWN`
- `RUNNING`

## 模块模型

`GameModule` 表示一种游戏，例如 `dropper`、`bedwars`。

关键字段：

- `id`
- `displayName`
- `minPlayers`
- `maxPlayers`

关键方法：

- `createSession(room: GameRoom): GameSession`

## 房间模型

`GameRoom` 表示一次运行中的房间。

关键字段：

- `id`
- `module`
- `mapTemplate`
- `name`
- `players`
- `spectators`
- `state`
- `world`
- `session`

## 房间管理器

`GameRoomManager` 当前负责：

- 注册 tick loop。
- 创建房间。
- 准备房间。
- 加入房间。
- 观战房间。
- 离开当前房间。
- 启动房间。
- 关闭房间。
- 查询房间列表和状态。
- 调用统计服务记录击杀、死亡、胜利、失败。
- 读取模块默认 `GameDefinition` 与托管游戏配置包。
- 对接临时世界模板复制。
- 对接玩家快照恢复。

已接入：

- 已接入 `ManagedGameModuleService`，按 `plugins/KaGameCenter/modules/<game>.jar` 与 `plugins/KaGameCenter/modules/<game>/config.yml` 的结构托管小游戏模块。

## 当前状态补充

- 房间创建时按游戏定义初始化 `GameSession`。
- 玩家加入时会记录快照并附加显示层。
- 玩家离开时会恢复快照并清理显示层。
- 房间关闭时会清理 BossBar、Scoreboard、世界实例和会话状态。
- 房间准备只对 `WAITING/COUNTDOWN/RUNNING` 返回幂等成功；准备回调或提交异常会立即关房，不残留 `PREPARING` 房间。
- 关房按步骤隔离模块回调、玩家恢复、通用资源、代理和世界清理异常，单步失败不会中断后续回收。
- 房间 UI 已包含浏览、加入、观战、详情和成员管理入口。
- `GameRoom.state` 真实变化后会同步触发不可取消的 `GameRoomStateChangeEvent`，重复状态不会重复通知。
- 启动房间时先由模块 `onStart()` 决定倒计时或失败状态，仅在模块仍停留 `WAITING` 时回退为 `RUNNING`。

## 加入/观战幂等规则

`GameRoomManager` 当前需要保证同房间重复操作不会破坏房间状态：

- 已在房间内的玩家再次加入同一房间：直接返回成功，不执行离开/重进。
- 已在房间内的观战者再次观战同一房间：直接返回成功。
- 同一房间内“观战 -> 加入”会从 `spectators` 移到 `players`，不会触发房间自动关闭。
- 已作为正式玩家加入任何房间时，观战请求会被拒绝；玩家必须先正常离开房间，再进入观战。

这条规则是为了避免菜单重复点击导致房间人数瞬间清零、世界被卸载、玩家又被加入旧 room 对象的问题。
