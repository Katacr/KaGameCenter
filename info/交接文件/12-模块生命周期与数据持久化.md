# 12-模块生命周期与数据持久化

更新时间：2026-07-14

## 模块生命周期

`ManagedGameModuleService.load()` 当前加载流程：

1. 兼容检查主插件 jar 内的旧模块配置资源；当前主插件不再内置玩法配置。
2. 扫描 `plugins/KaGameCenter/modules/*.jar`，若模块 jar 根目录包含 `config.yml` 或 `lang/`，运行目录缺失时释放到模块私有目录。
3. 扫描 `plugins/KaGameCenter/modules/*/config.yml`，按配置加载所有启用模块。

因此新增小游戏模块不再需要修改主插件代码。新模块必须把默认 `config.yml` 和 `lang/` 放进自己的 jar，主插件不打包玩法私有资源。

语言文件只释放缺失文件，不合并已有文件；`ModuleLanguage` 会按外部当前语言、JAR 当前语言、外部英文、JAR 英文顺序逐键回退，所以模块升级新增键立即可用且不会覆盖管理员定制。字符串和字符串列表共享该顺序，`getMessageList` 兼容旧标量键。模块 Provider 传入 `"lang"` 时资源路径就是 `lang/<locale>.yml`。

地图模板和预设托管游戏包通常较大，不放进 jar；它们仍按运行目录结构手动部署：

- `plugins/KaGameCenter/maps/<game>/<map>/`
- `plugins/KaGameCenter/modules/<game>/games/`

已补充 `GameModuleContext` 对模块资源的跟踪：

- `registerModule(module)`：注册玩法及默认定义，并记录到模块上下文。
- `registerListener(listener)`：注册 Bukkit listener，并记录到模块上下文。
- `registerAdminCommand(command)`：注册模块自己的管理子命令。
- `registerGameEditor(editor)`：注册托管游戏编辑器。
- `registerChatFormatter(formatter)`：注册模块聊天格式器。
- `registerChestMenuDataSource(type, source)`：注册带模块命名空间的动态数据源。
- `trackTask(task)`：记录模块创建的 BukkitTask。
- `runTaskTimer(delayTicks, periodTicks, action)`：用 KaGameCenter 插件实例创建并记录循环任务。
- `cleanup()`：取消任务，并注销监听器、聊天格式器、箱子菜单数据源、管理命令、托管游戏编辑器、玩法及默认定义。

注册表资源按对象实例注销；旧上下文不会仅凭相同 ID 删除后来注册的替代实例。`provider.onLoad(context)` 中途抛出异常时，加载器会按正常卸载顺序回滚已经启动的 Provider 和上下文资源，最后关闭 classloader，因此失败模块不会留下半注册的监听器、命令、数据源、编辑器或玩法。

模块管理命令统一位于 `/kgc admin <module> ...`，主命令先校验管理员权限，再分发给 `ModuleAdminCommand`。BedWars 已注册 `reload/list/edit` 和私有编辑世界快捷动作；点位、校验、预览与保存继续委托同一个 `ModuleGameEditor`，避免命令与 GUI 产生不同配置格式。

`ManagedGameModuleService.unload()` 当前顺序：

1. `provider.onUnload()`
2. `context.cleanup()`
3. `classLoader.close()`

如果模块绕过 `GameModuleContext` 自己注册资源，需要在 `onUnload()` 中自行清理。

### 房间故障隔离

`GameRoomManager` 的主 tick 任务不直接在集合迭代中执行全部模块回调，而是复制房间快照后逐房处理：

- `GameSession.onTick()` 或该房间显示刷新抛异常时，只关闭故障房间并执行统一成员、快照、资源和世界清理。
- 故障房间关闭导致集合变化时，不影响同一 tick 中其他仍有效房间。
- Velocity 心跳逐房发布；单个房间序列化或后端发布失败只记录该房间警告，后续房间和下个周期继续。
- `startRoom()` 把 `onStart()`、最终状态、显示和代理发布视为一个提交边界；异常会关闭房间，模块正常进入 `COUNTDOWN/RUNNING` 后才返回成功。
- 模块若正常返回但主动进入 `ENDING/CLOSED` 等失败状态，核心不强制改写为 `RUNNING`。
- `createSession()` 抛异常、返回其他房间实例或初次代理发布失败时不暴露房间；已创建 Session 会进入统一关闭路径。
- 准备状态事件和无世界回滚显示也属于准备事务；重复加入/观战刷新失败按致命显示错误关闭对应房间。
- 观战策略、正式/观战准入预检事件抛异常时以 `CALLBACK_FAILED` 拒绝，不写入成员或快照；拒绝通知自身异常不反向破坏结果。
- `resolveKiller/onPlayerKill/onPlayerDeath` 与统计提交异常会在死亡事件结束后的下一 tick 关闭对应房间，避免同步恢复死亡中的 Player。
- `routeChat` 异常会抑制单条消息，`canSpectatorFollow` 异常会排除单个目标；两者都不回退到更宽的受众。

这些保护只隔离故障，不能把 Bukkit API 移出主线程；模块的 tick 回调仍必须有界且不得执行阻塞 IO。

### BedWars 配置重载

`BedWarsConfigService.reload()` 不再使用静默加载后直接覆盖正式文件。当前顺序：

1. 从 `config.yml` 严格解析；仅在正式文件缺失时读取中断遗留的 `config.yml.tmp`。
2. 在候选配置上补齐默认值与旧键迁移，并构造完整 `BedWarsConfig` 验证运行时读取。
3. 先写同目录临时文件，再以原子移动替换正式文件；文件系统不支持原子移动时回退同目录替换。
4. 任一解析、类型化或写入步骤失败时恢复旧内存配置，正式文件保持原状；管理命令返回本地化错误。

因此不得再用 `YamlConfiguration.loadConfiguration(file)` 后无条件 `save(file)` 实现模块重载，这会在损坏 YAML 被静默解析为空配置时覆盖管理员文件。已经创建的 BedWars Session 持有准备时的规则快照；成功重载只影响服务级读取和后续准备的房间，失败重载不改变两者。

## 地图编辑会话

主插件已新增通用地图编辑会话服务：

- `MapEditorService`

当前职责：

- 为管理员打开模板对应的编辑世界
- 记录并恢复管理员原位置 / 原游戏模式
- 保存编辑世界并回写到模板目录
- 关闭编辑世界并清理会话

`TemporaryWorldService` 也已补充：

- `createEditorWorldFromTemplate(...)`
- `saveWorldToTemplate(...)`

这部分属于主插件公共基础设施，不应由单个小游戏模块各自重复实现。

## 数据持久化

新增统计仓库层：

- `StatsRepository`
- `MemoryStatsRepository`
- `SqlStatsRepository`
- `DatabaseConfig`

`PlayerStatsService` 现在会：

- 启动时从仓库加载已有统计。
- 记录 play/win/loss/kill/death/points 后立即保存。
- 关闭时关闭仓库连接。

默认配置：

```yaml
database:
  enabled: true
  type: sqlite
  sqlite:
    file: data/kagamecenter.db
  mysql:
    host: 127.0.0.1
    port: 3306
    database: kagamecenter
    username: root
    password: ""
  pool:
    maximum-size: 5
```

当前表：

```sql
kgc_player_stats(
  player_id,
  game_id,
  plays,
  wins,
  losses,
  kills,
  deaths,
  points,
  updated_at
)

kgc_player_metrics(
  player_id,
  game_id,
  metric_id,
  metric_value,
  updated_at
)
```

`kgc_player_metrics` 由 `GameResultService.addMetric/metric` 访问，用于多个玩法都可能需要的专属整数计数；复杂对象仍保留在模块私有存储。

数据库初始化失败时会回退到内存统计。

### 玩家状态快照

`PlayerSnapshotService` 不再只依赖进程内存。玩家首次进入正式房间或外部观战前，会把完整快照保存到：

```text
plugins/KaGameCenter/data/player-snapshots/<uuid>.yml
```

保存内容包含位置、游戏模式、生命属性、吸收生命、经验、环境状态、速度、飞行/隐身/无敌/碰撞、背包、护甲、额外槽位和末影箱。写入先落到同目录 `<uuid>.yml.tmp`，再以原子移动替换正式文件；不支持原子移动的文件系统回退为普通同目录替换。

恢复规则：

- 玩家仍在有效断线宽限内时优先恢复原房间 Session，不提前应用大厅快照。
- 没有活动席位时，登录事件先恢复内存、正式 YAML 或进程中断遗留的 `.tmp`，成功后才消费 Velocity 加入意图。
- 原世界仍按 UUID、名称解析；世界不存在时传送到首个已加载世界的出生点，不把旧坐标套用到错误世界。
- 传送和所有 Bukkit 状态全部成功后才删除快照；中途异常、未知版本、损坏 YAML 或删除失败都会保留文件并记录警告。
- 仍有待恢复文件时拒绝正式加入和观战，避免新快照覆盖玩家真实大厅状态。

主插件停服时先关闭全部房间，再卸载模块。在线玩家会立即尝试恢复；离线玩家的 YAML 保留到下次登录。重连宽限到期的玩法回调和各项公共清理相互隔离，单个扩展异常不会阻断成员、队伍和待恢复标记释放。

## 后续建议

- 增加数据库迁移版本表。
- 增加异步写入队列，避免高频统计更新阻塞主线程。
- 增加模块热重载命令，先关闭该模块房间，再卸载资源并重新加载 jar。
- 为模块热重载增加独立测试 Provider，自动覆盖部分加载失败和同 ID 替代实例的回归。
- 为玩家快照增加 MockBukkit 序列化、损坏文件和停服重启自动化测试；当前项目测试任务仍为 `NO-SOURCE`。
