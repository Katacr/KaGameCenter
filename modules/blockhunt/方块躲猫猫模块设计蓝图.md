# 方块躲猫猫模块设计蓝图

本文档记录 `blockhunt` 模块的第一版设计。当前阶段只做立项与架构设计，不开始写代码。

## 模块定位

模块 ID：

```text
blockhunt
```

显示名称：

```text
方块躲猫猫
```

`blockhunt` 是 KaGameCenter 的外置小游戏模块，后续构建产物为：

```text
plugins/KaGameCenter/modules/blockhunt.jar
```

模块私有目录为：

```text
plugins/KaGameCenter/modules/blockhunt/
```

主插件只负责模块加载、房间、临时世界、地图编辑、选区、菜单、发包抽象、观战、基础数据统计。方块躲猫猫的玩法配置、可伪装方块、猎人/躲藏者规则、胜负结算、专属菜单和语言文件都放在模块内部。

## 核心玩法

方块躲猫猫是队伍非对称玩法：

- 躲藏者开局选择或随机获得一种方块外观。
- 躲藏者可以伪装成方块，在地图中移动、静止、躲藏。
- 猎人在准备时间结束后进入地图寻找躲藏者。
- 猎人攻击/识别躲藏者后使其淘汰。
- 躲藏者坚持到倒计时结束则躲藏者胜利。
- 猎人在倒计时结束前淘汰所有躲藏者则猎人胜利。

第一版目标是跑通核心闭环，不做过复杂职业、技能或商店。

## 房间流程

### 创建房间

玩家从游戏中心选择已经配置好的“方块躲猫猫”游戏创建房间。

房间创建后：

- 使用该游戏的私有地图快照创建临时世界。
- 等待玩家加入。
- 房主或自动倒计时触发游戏开始。

### 准备阶段

准备阶段包含两段：

1. 公共等待阶段
2. 躲藏准备阶段

公共等待阶段：

- 玩家在等待大厅。
- 可显示当前人数、游戏名称、地图名。
- 玩家可以离开房间。

躲藏准备阶段：

- 分配猎人和躲藏者。
- 躲藏者传送到游戏区域。
- 猎人可以留在猎人等待点，或被临时冻结/关在等待区域。
- 躲藏者获得伪装选择菜单或随机方块。
- 显示倒计时 Title。

### 游戏阶段

游戏开始后：

- 猎人进入游戏区域。
- 躲藏者保持方块伪装。
- 躲藏者可移动，但长时间静止后可进入“稳定伪装”状态。
- 猎人攻击伪装对象时，若命中真实玩家则淘汰躲藏者。
- 计分板显示剩余时间、猎人数、躲藏者存活数、当前身份。
- BossBar 显示游戏剩余时间。
- ActionBar 可显示当前伪装状态、冷却、提示。

### 结束阶段

结束条件：

- 猎人淘汰全部躲藏者：猎人胜利。
- 时间结束仍有躲藏者存活：躲藏者胜利。
- 房间人数不足：可按配置提前结束。

结束后：

- 显示结算 Title。
- 显示结算 Dialog，包括胜利队伍、玩家表现、点数预览。
- 写入基础统计：胜利、失败、击杀、死亡、点数。
- 所有玩家退出房间或进入短暂结算等待。
- 关闭房间并卸载临时世界。

## 队伍设计

第一版固定两队：

```text
hunters   猎人
hiders    躲藏者
```

分配规则：

- 默认按玩家数量自动分配。
- 可配置猎人比例，例如 `hunter-ratio: 0.25`。
- 至少 1 名猎人。
- 玩家数过少时可禁止开始。

后续可扩展：

- 房主指定猎人。
- 玩家自选队伍。
- 权重随机，上一局猎人降低下一局猎人概率。

## 地图配置

每个托管游戏一份私有配置和私有地图快照：

```text
plugins/KaGameCenter/modules/blockhunt/games/game/<游戏名>.yml
plugins/KaGameCenter/modules/blockhunt/games/map/<游戏名>/
```

公共模板只作为创建游戏时的源模板：

```text
plugins/KaGameCenter/maps/blockhunt/default/
```

创建游戏后：

- 主插件复制公共地图模板到模块私有地图目录。
- 后续编辑只修改私有地图快照。
- 公共模板不被修改。

## 管理菜单

模块自己的游戏内管理面板建议使用内置箱子菜单。

面板上方显示当前配置状态：

```text
正在编辑 [方块躲猫猫测试]
等待大厅 已设置
猎人等待点 已设置
躲藏者出生点 已设置
游戏区域 已设置
可伪装方块 5 个
```

按钮：

- 打开编辑世界
- 保存私有快照
- 关闭编辑世界
- 设置等待大厅
- 设置猎人等待点
- 设置躲藏者出生点
- 设置游戏区域
- 添加手持方块为可伪装方块
- 移除手持方块
- 预览游戏区域

## 发包需求

方块躲猫猫高度依赖发包能力。

第一版需要使用主插件 `PacketDispatchService` 提供：

- 玩家对其他玩家伪装为方块。
- 真实玩家对指定 viewer 保持隐身。
- 伪装方块跟随玩家移动。
- 可选：被命中或暴露时显示玩家发光。
- 可选：只对猎人显示某些提示。

当前主插件已有基础能力：

- `disguisePlayerAsBlock(...)`
- `showPlayerGlow(...)`
- `showBlockGlow(...)`
- `showPrivatePickup(...)`
- `showBeaconBeam(...)`
- `clearViewer(...)`

但正式实现方块躲猫猫时，建议继续补强发包抽象：

- 创建“伪装会话”对象，而不是只传持续秒数。
- 支持模块主动更新伪装材质。
- 支持按房间清理视觉对象。
- 支持只对某个队伍显示伪装。
- 支持隐藏真实玩家碰撞或配合 Bukkit 队伍禁碰撞。

## 伪装状态设计

每个躲藏者维护一个状态：

```text
playerId
blockMaterial
solid
lastMoveMillis
lastChangeMillis
alive
revealedUntilMillis
```

状态说明：

- `blockMaterial`：当前伪装方块。
- `solid`：是否进入稳定伪装状态。
- `lastMoveMillis`：最后移动时间。
- `lastChangeMillis`：最后切换方块时间。
- `alive`：是否仍存活。
- `revealedUntilMillis`：被攻击或暴露后的短暂发光结束时间。

第一版可以不实现真正“变成地图方块”，只用 `BlockDisplay` 伪装玩家。

## 攻击与淘汰

第一版建议使用 Bukkit 事件判定：

- 猎人攻击玩家实体时，如果目标是躲藏者，淘汰目标。
- 躲藏者被淘汰后转为观战。
- 猎人击杀数 +1。
- 躲藏者死亡数 +1。

如果真实玩家对猎人完全隐身导致难以点击命中，需要后续评估：

- 保留一个可命中的真实玩家碰撞体。
- 使用 PacketEvents 做命中检测辅助。
- 或使用短距离射线检测猎人准星附近的躲藏者。

第一版先优先使用 Bukkit 事件，降低复杂度。

## 显示层

计分板：

```text
方块躲猫猫
身份: 躲藏者/猎人
剩余: 04:35
猎人: 2
躲藏者: 6
存活: 5
淘汰: 1
```

BossBar：

- 显示游戏剩余时间。
- 躲藏准备阶段使用黄色。
- 游戏阶段使用绿色。
- 结束阶段使用红色。

Title：

- 分配身份时显示身份。
- 猎人释放时显示开始寻找。
- 胜负结算时显示胜利队伍。

ActionBar：

- 躲藏者显示当前伪装方块、稳定状态。
- 猎人显示剩余躲藏者数量或命中提示。

## 观战

被淘汰的躲藏者进入观战。

第一版建议使用主插件托管观战模式：

- 不允许与游戏交互。
- 可使用观战道具切换跟随玩家。
- 观战者不参与胜负判定。
- 房间关闭时恢复原状态。

配置预留：

```yaml
spectator:
  enabled: true
  mode: managed
```

## 数据统计

第一版写入基础统计：

- 猎人胜利：猎人 `win +1`，躲藏者 `loss +1`
- 躲藏者胜利：躲藏者 `win +1`，猎人 `loss +1`
- 猎人淘汰躲藏者：猎人 `kill +1`，躲藏者 `death +1`
- 点数仅显示预览，后续接经济或经验

后续应支持模块私有统计：

- 作为猎人胜利次数
- 作为躲藏者胜利次数
- 最长存活时间
- 伪装击杀/发现次数
- 常用伪装方块

## 多房间隔离

每个房间独立：

- 临时世界：`kgc_<roomId>`
- 方块躲猫猫 Session 实例
- 玩家身份与伪装状态
- 猎人/躲藏者队伍
- 计时器与结算状态
- 发包视觉对象

需要注意：

- 发包视觉最好增加房间作用域，避免后续清理只能按 viewer 清理。
- 统计应记录具体托管游戏 ID，而不是只记录模块 ID。
- 方块伪装跟随任务需要合并调度，避免每个玩家每个 viewer 一个长期任务导致性能压力。

## 第一版实现范围

第一版建议只做：

1. 模块骨架：`blockhunt.jar`
2. 模块配置与语言文件
3. 管理员编辑面板
4. 私有地图快照接入
5. 等待大厅、猎人等待点、躲藏者出生点、游戏区域配置
6. 自动分配猎人/躲藏者
7. 躲藏者随机方块伪装
8. 猎人攻击淘汰躲藏者
9. 胜负结算
10. 基础计分板、BossBar、Title、ActionBar

暂不做：

- 职业系统
- 技能系统
- 商店系统
- 复杂道具
- 多轮积分赛
- 跨服同步

## 待确认问题

- 躲藏者是否允许主动选择方块，还是第一版先随机分配。
- 躲藏者是否允许中途换方块。
- 猎人攻击错误方块是否需要惩罚扣血。
- 躲藏者静止后是否需要“固定成真实方块”视觉。
- 游戏中是否允许破坏地图。
- 是否需要给猎人指南针或周期性提示。
- 第一版最低人数建议为 2，是否接受。
