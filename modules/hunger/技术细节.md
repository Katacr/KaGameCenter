# 饥饿游戏模块技术细节

更新时间：2026-07-13

## 模块定位

`hunger` 是 KaGameCenter 的外置经典 Survival Games 模块，产物为：

```text
modules/hunger/build/libs/hunger.jar
```

运行时目录约定：

```text
plugins/KaGameCenter/modules/hunger.jar
plugins/KaGameCenter/modules/hunger/config.yml
plugins/KaGameCenter/modules/hunger/lang/
plugins/KaGameCenter/modules/hunger/games/game/<游戏名>.yml
plugins/KaGameCenter/modules/hunger/games/map/<游戏名>/
```

模块不使用 `plugin.yml`，由 `HungerModuleProvider` 通过 GameCenter 外置模块加载器注册。主插件只提供通用房间、地图、任务、状态恢复、统计、广播、发包和名牌能力，不包含 Hunger 专属规则。

## 经典规则

默认流程：

```text
WAITING -> COUNTDOWN -> PROTECTION -> RUNNING -> DEATHMATCH -> RESULT -> CLOSING
```

- 最少 6 人、最多 24 人。
- 开局把每名贡品随机分配到不同的固定出生台，并在 60 秒倒计时内冻结位置。
- 倒计时结束后解除移动限制，进入 60 秒保护期；保护期内禁止所有玩家伤害和 PVP。
- 生存阶段持续 900 秒，启用原版饥饿和 PVP。
- 地图容器首次打开时生成一份房间共享的 27 格虚拟物资栏，同一箱子对所有玩家显示相同内容。
- 生存阶段开始 300 秒后清空房间箱子缓存，下一次打开时重新生成物资；默认只补货一次。
- 存活人数降至 4 人时，将生存阶段剩余时间最多压缩为 60 秒。
- 生存阶段结束后，把存活者随机传送到不同的固定死亡竞赛出生点，死亡竞赛默认持续 300 秒。
- 玩家死亡、离开或跌落到淘汰高度后失去参赛资格并进入观战；临时世界启用立即重生，最后一名存活者获胜。
- 死亡竞赛超时或点位不足时按无人获胜结算。

不包含地图投票、赏金经济、跨服跳转、服务器重启、动态缩圈或安全区外伤害。

## 核心类

| 类 | 用途 |
| --- | --- |
| `HungerModuleProvider` | 创建模块依赖、注册监听器、管理命令和托管游戏编辑器 |
| `HungerGameModule` | 提供游戏定义，并为每个房间创建独立 Session |
| `HungerGameSession` | 保存并驱动一局游戏的全部运行状态 |
| `HungerConfigService` | 读取模块配置，读写托管游戏的 Hunger 私有字段 |
| `HungerManagedGameEditor` | 通过管理菜单编辑地图点位、区域和私有快照 |
| `HungerAdminCommand` | 提供模块管理子命令 |
| `HungerListener` | 将 Bukkit 事件路由到所属房间 Session |
| `HungerModels` | 定义模块配置、地图配置、玩家状态、阶段和坐标模型 |

## 模块配置

`config.yml` 的主要字段：

```yaml
game:
  min-players: 6
  max-players: 24
  countdown-seconds: 60
  protection-seconds: 60
  duration-seconds: 900
  refill-after-seconds: 300
  force-deathmatch-players: 4
  force-deathmatch-delay-seconds: 60
  deathmatch-seconds: 300
  result-display-seconds: 10
  close-delay-seconds: 5
  void-y: -64.0
  max-health: 20.0
  allow-monsters: false
  win-points: 3

loot:
  min-items-per-chest: 1
  max-items-per-chest: 10
  container-materials: [CHEST, TRAPPED_CHEST, BARREL]
  entries: []

blocks:
  break-allowed: []
  place-allowed: []
  auto-prime-tnt: true
  tnt-fuse-ticks: 40
  explosion-block-damage: false
  fire-spread: false

tracker:
  enabled: false
  range: 100.0
```

`loot.entries` 是平面加权表。每项包含 `material`、`min-amount`、`max-amount` 和正整数 `weight`。每个箱子独立抽取配置数量的物品，槽位随机且同一物品允许重复抽中。

`tracker.enabled` 开启后，存活贡品可右键自己获得的指南针，将指针指向范围内最近的存活贡品；模块不会自动发放指南针。

## 托管游戏配置

托管游戏配置位于 `modules/hunger/games/game/<游戏名>.yml`，Hunger 私有字段如下：

```yaml
hunger:
  map-id: default
  lobby: {}
  spectator-spawn: {}
  play-region: {}
  tribute-spawns:
    - id: tribute_1
      point: {}
  deathmatch-spawns:
    - id: dm_1
      point: {}
  supply-chests:
    - id: chest_1
      point: {}
  void-y: -64.0
```

所有坐标不绑定世界名。房间启动时，`TemporaryWorldService` 从托管游戏私有快照或公共模板创建临时世界，再把配置坐标映射到该世界。

启动配置校验要求：

- `lobby`、`spectator-spawn`、`play-region` 已设置。
- `tribute-spawns` 数量不少于开局玩家数。
- `deathmatch-spawns` 数量不少于 `min(force-deathmatch-players, 开局玩家数)`。

`supply-chests` 可为空。显式配置的点位若不是容器方块，运行时临时替换为木桶，并在房间关闭前恢复原方块。为兼容旧配置，读取时仍接受 `chest-spawns`，新写入统一使用 `supply-chests`。

## 管理入口

推荐通过 `/kgc admin manage` 打开托管游戏编辑器。模块命令可用于快速设置：

```text
/kgc admin hunger reload
/kgc admin hunger setlobby
/kgc admin hunger setspectator
/kgc admin hunger setregion
/kgc admin hunger setvoidy
/kgc admin hunger addtribute [编号]
/kgc admin hunger removetribute <编号>
/kgc admin hunger adddeathmatch [编号]
/kgc admin hunger removedeathmatch <编号>
/kgc admin hunger addchest [编号]
/kgc admin hunger removechest <编号>
/kgc admin hunger preview
```

除 `reload` 外，命令要求管理员位于对应托管游戏的私有编辑世界。`setregion` 使用 `SelectionService` 的当前选区；`preview` 使用 `PacketDispatchService` 私有显示区域边缘和各类点位。

## Session 状态

每个房间只创建一个 `HungerGameSession`。以下数据全部属于 Session，不放在 Provider、Listener 或模块全局对象中：

- 阶段、阶段计时器、补货计时器和结算标记。
- 参赛者集合、每名玩家的存活状态、击杀数、开箱数和冻结位置。
- 房间共享箱子 Inventory、配置箱坐标和单玩家已开箱集合。
- 当前房间的 `RoomResourceScope` 句柄；临时方块和 TNT 生命周期由主插件作用域隔离。
- 胜者、补货完成状态和提前死亡竞赛触发状态。

因此多个房间可以并行运行，不共享玩家、物资、淘汰名单、计时器或实体归属。

## 事件路由

`HungerListener` 不保存玩法状态，只按玩家所属房间或事件世界定位 `HungerGameSession`：

- 伤害事件：保护期禁伤、PVP 身份和阶段校验。
- 移动事件：倒计时冻结、游戏区域限制、淘汰高度。
- 交互事件：共享补给箱和可选指南针追踪。
- 方块事件：破坏/放置白名单和 TNT 自动点燃。
- 饥饿事件：等待、倒计时和保护期保持满饱食。
- 爆炸、燃烧、生物生成事件：按当前房间配置保护地图。
- 拾取、丢弃事件：淘汰观战者不能操作局内物品。

投射物的攻击者通过 Bukkit shooter 解析；模块生成的 TNT 通过 `RoomResourceScope.trackEntity` 同时登记实体生命周期和拥有者。

## 通用服务

- `TemporaryWorldService`：创建临时世界和托管游戏私有地图快照。
- `SelectionService`：读取管理选区。
- `ManagedMapPointService`：读写大厅、出生点、补给箱点和无世界选区。
- `SpawnAssignmentService`：为开局贡品和死亡竞赛存活者随机分配不重复点位。
- `PlayerEliminationService`：处理立即重生、观战传送和淘汰输入限制。
- `RoomResourceScopeService`：统一清理任务、TNT、实体归属、临时木桶、Packet viewer 和名牌。
- `PlayerRuntimeStateService`：进入房间时捕获、离开或结束时恢复玩家状态。
- `GameResultService`：记录离线淘汰死亡、胜负和胜利点数；正常死亡和击杀由主插件通用死亡事件链记录。
- `RoomBroadcastService`：广播消息、Title 和房间玩家集合。
- `PacketDispatchService`：清理玩家私有视觉，并为编辑器提供点位预览。
- `PlayerNametagService`：显示存活状态和本局击杀数，淘汰或关闭时清理。

## 地图规则

- 默认禁止自然怪物生成、火焰蔓延和爆炸破坏地图。
- 仅存活贡品可在保护期、生存阶段和死亡竞赛中操作白名单方块。
- 放置 TNT 时立即转换为带玩家来源和房间归属的已点燃 TNT。
- 玩家不能离开 `play-region`，移动事件会取消越界移动。
- 地图内符合 `container-materials` 的容器均可作为共享补给箱；显式 `supply-chests` 还用于补齐地图上不存在的容器。

## 统计规则

- Bukkit 正常死亡和击杀由 GameCenter 通用玩家死亡监听器记录，模块只更新本局击杀显示和淘汰状态，避免重复统计。
- 生存阶段主动离开没有 Bukkit 死亡事件，模块通过 `GameResultService.recordDeath` 补记一次死亡。
- 结算时调用 `recordWinLoss`，赢家获得配置的 `win-points`，其余开局参赛者记录失败。
- 倒计时前离开不计死亡或失败；开局后迟加入者只观战，不进入参赛者集合。

## 清理路径

`onEnd()` 恢复仍在线玩家并清理其私有视觉和名牌。`onClose()` 清空模块玩法集合，随后主插件关闭资源作用域：

1. 模块清空共享箱子、玩家状态、参赛者集合和运行时快照。
2. `RoomResourceScope` 取消任务、删除实体、清实体归属并恢复临时方块。
3. 主插件清除淘汰标记、Packet viewer 和房间名牌。
4. 临时世界最终由 GameCenter 房间关闭流程卸载删除。

## 验收清单

- 两个房间并发时，箱子内容、补货、倒计时、淘汰和结算互不影响。
- 出生点不足或必填地图字段缺失时，房间给出错误并自动关闭。
- 倒计时不能离开贡品台，保护期不能受到伤害，保护结束后 PVP 和饥饿正常。
- 同一房间同一箱子内容共享，不同房间内容独立；补货后重新生成。
- 存活人数达到阈值时压缩生存时间，死亡竞赛按固定点位分散传送。
- 死亡、离开、跌落均正确淘汰，观战者不能拾取、丢弃或修改地图。
- 最后一人获胜，超时为平局，统计不重复。
- 结束后背包、属性、模式、位置、名牌、视觉、任务、实体、临时方块和世界均完成恢复或清理。
