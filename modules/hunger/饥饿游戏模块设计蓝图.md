# 经典饥饿游戏模块设计蓝图

更新时间：2026-07-13

## 模块定位

`hunger` 是 KaGameCenter 的经典个人淘汰制 Survival Games 模块。目标是还原固定贡品出生台、开局冻结、保护期、地图搜刮、共享补给箱、定时补货、低人数提前决赛、固定决赛出生点和最后一人生还的经典流程。

模块保持为 KaGameCenter 外置模块，不写 Bukkit `plugin.yml`，不在主插件加入 hunger 专属规则。

## 经典规则提炼

保留的核心规则：

- 等待人数满足后，由房主开始房间。
- 每名贡品分配一个固定出生台，不使用随机散点。
- 出生台倒计时期间锁定位置并免疫全部伤害。
- 倒计时结束后解除移动锁定，进入全伤害保护期。
- 保护期结束后开启环境伤害和玩家 PVP。
- 地图中的箱子首次打开时生成共享随机物资，同一箱子对所有玩家保持同一内容。
- 游戏中途统一补货一次，补货后箱子再次打开会重新生成物资。
- 存活人数降到配置阈值时，把常规阶段剩余时间压缩为决赛预告时间。
- 常规阶段结束后把存活贡品传送到固定死亡竞赛出生点。
- 死亡竞赛结束仍有多人存活则平局。
- 玩家死亡或运行中离开都算淘汰；最后一名存活玩家获胜。
- 等待、倒计时和保护期保持满饱食；正式游戏和死亡竞赛启用真实饥饿。
- 只允许配置白名单中的方块被破坏或放置。
- 可选 TNT 自动点燃、爆炸不破坏地图、禁止火焰蔓延。
- 可选玩家追踪器：右键指南针寻找范围内最近存活贡品。

## 不迁移的旧单服功能

以下能力由 KaGameCenter 或服务器基础设施替代，不放入 hunger：

- 地图投票：托管游戏创建房间时已经确定地图。
- 全服单局状态、MOTD 和在线人数控制：KaGameCenter 支持多房间并发。
- 插件自行重启服务器或跳转 Bungee 大厅：房间结算后只关闭当前房间。
- 模块私有 MySQL：统一使用 `GameResultService`。
- 旧赏金经济：当前主插件没有可安全扣减玩家点数的通用经济事务 API。
- NMS ActionBar、Title、Hologram：使用主插件广播、显示和 Packet 服务。
- 静态全局玩家列表与任务：所有单局数据归 `HungerGameSession`。

## 运行目录

```text
plugins/KaGameCenter/modules/hunger.jar
plugins/KaGameCenter/modules/hunger/config.yml
plugins/KaGameCenter/modules/hunger/lang/
plugins/KaGameCenter/modules/hunger/games/game/<游戏名>.yml
plugins/KaGameCenter/modules/hunger/games/map/<游戏名>/
```

公共模板只用于创建托管游戏。房间始终从托管游戏私有快照复制临时世界。

## 阶段状态机

```text
WAITING
  -> COUNTDOWN
  -> PROTECTION
  -> RUNNING
  -> DEATHMATCH
  -> RESULT
  -> CLOSING
```

### WAITING

- 玩家在大厅等待。
- 玩家状态、背包和显示初始化。
- 允许加入正式玩家。
- 不允许玩法伤害、饥饿、方块操作和补给箱操作。

### COUNTDOWN

- 玩家已被传送到固定贡品出生台。
- 每个玩家的冻结位置存入自己的 `HungerPlayerState`。
- 移动事件只在位置坐标变化时拦截，允许转动视角。
- 全部伤害关闭，饱食保持满值。
- 箱子不可打开，方块不可操作。

### PROTECTION

- 解除位置冻结。
- 箱子和白名单方块规则生效。
- 全部伤害仍关闭，包括跌落、火焰、怪物和玩家伤害。
- 饱食保持满值。
- 保护期结束时进入 `RUNNING`。

### RUNNING

- 所有正常伤害和 PVP 生效。
- 真实饥饿生效。
- 首次打开地图容器时生成共享物资。
- 补货计时到达后清空房间箱子缓存；下一次打开重新生成。
- 存活人数小于等于 `force-deathmatch-players` 时，将剩余时间压缩至 `force-deathmatch-delay-seconds`。
- 只剩一人时立即结算。

### DEATHMATCH

- 存活玩家按顺序分配固定死亡竞赛出生点。
- 继续启用伤害、PVP、饥饿、箱子和白名单方块规则。
- 不再补货。
- 只剩一人时立即结算。
- 时间结束仍有多人存活则平局。

### RESULT / CLOSING

- 统一记录胜负一次。
- 展示胜者、个人击杀和结算 Title。
- 停止玩法输入并进入观战状态。
- 结果展示结束后关闭当前房间。

## 模块配置

```yaml
game:
  display-name: "饥饿游戏"
  min-players: 6
  max-players: 24
  countdown-seconds: 60
  protection-seconds: 60
  duration-seconds: 900
  refill-after-seconds: 300
  force-deathmatch-players: 4
  force-deathmatch-delay-seconds: 60
  deathmatch-seconds: 300
  result-display-seconds: 10
  close-delay-seconds: 5
  void-y: -64.0
  allow-monsters: false
  win-points: 3

loot:
  min-items-per-chest: 1
  max-items-per-chest: 10
  container-materials:
    - CHEST
    - TRAPPED_CHEST
    - BARREL
  entries:
    - material: WOODEN_SWORD
      min-amount: 1
      max-amount: 1
      weight: 5

blocks:
  break-allowed:
    - COBWEB
    - OAK_LEAVES
  place-allowed:
    - COBWEB
    - TNT
  auto-prime-tnt: true
  tnt-fuse-ticks: 40
  explosion-block-damage: false
  fire-spread: false

tracker:
  enabled: false
  range: 100.0
```

物资使用平面加权表。`weight <= 0` 的条目忽略；物品数量在 `min-amount..max-amount` 内随机。模块不解析旧版数字物品 ID。

## 托管游戏配置

```yaml
hunger:
  map-id: default
  lobby: {}
  spectator-spawn: {}
  play-region: {}
  tribute-spawns:
    - id: tribute_1
      point: {}
  deathmatch-spawns:
    - id: dm_1
      point: {}
  supply-chests:
    - id: chest_1
      point: {}
  void-y: -64.0
```

规则：

- `tribute-spawns` 数量必须不少于开局正式玩家数。
- `deathmatch-spawns` 建议至少等于 `force-deathmatch-players`。
- `supply-chests` 是可选点位，用于没有预置容器的地图；运行时会在这些位置放置木桶。
- `play-region` 限制哪些地图容器会成为补给箱，也用于防止玩家离开有效地图。
- 坐标不保存编辑世界名。

## Session 数据归属

`HungerGameSession` 独占：

- `participants`：本局正式参赛 UUID，离开后仍保留用于记录失败。
- `states`：玩家存活、击杀、开箱数、冻结位置、统计标记。
- 当前 `phase` 和各阶段计时器。
- `supplyChests`：位置到共享 Inventory 的房间箱子缓存。
- `resources`：当前房间的通用资源作用域句柄，托管临时方块和 TNT 生命周期。
- 补货是否完成、强制决赛是否触发、胜者和结算标记。

Provider、ConfigService、Editor 和 Listener 不保存任何单局状态。

## 固定出生点分配

- 开局时打乱贡品出生点，避免房间加入顺序固定对应位置。
- 随机且无重复的配对由主插件 `SpawnAssignmentService` 提供。
- 每名玩家只分配一个不重复点位。
- 数量不足时拒绝开始并关闭无效房间，不回退随机散点。
- 死亡竞赛优先使用不重复固定点位；点位不足时拒绝进入决赛并以当前存活者平局结算，避免玩家重叠。

## 共享补给箱

- 只拦截 `play-region` 内且材质在 `container-materials` 中的容器。
- `supply-chests` 配置点会在临时世界创建木桶并纳入同一系统。
- 首次打开时创建一个 27 格共享 Inventory 并缓存。
- 后续玩家打开同一位置时看到相同 Inventory，物品拿走后不会为其他玩家复制。
- 补货时清空缓存；下一次打开才重新抽取，避免一次性扫描全部地图区块。
- 每名玩家用 `openedChests` 集合统计独立开启过的箱子数量。

## 淘汰和观战

- 原版死亡由主插件先记录 kill/death，再调用 Session；模块不重复记录。
- 跌落高度通过原版死亡事件记录；运行中离开没有死亡事件，由模块补记一次 death。
- 淘汰玩家保留在房间正式玩家集合，Session 标记为非存活，再由 `PlayerEliminationService` 进入观战状态。
- 外部观战者使用 KaGameCenter `SpectatorPolicy.MANAGED`。
- 观战者不能打开补给箱、拾取、丢弃、攻击或操作方块。

## 统计和名牌

- 主插件记录原版击杀和死亡。
- 模块记录离开/高度淘汰产生的死亡。
- 结算调用 `recordWinLoss`，胜者获得 `win-points`。
- `PlayerNametagService` 显示存活贡品前缀和本局击杀后缀。
- 淘汰、离开和关闭时清理名牌。

## Listener 路由

`HungerListener` 只负责查找当前房间并转发：

- `PlayerMoveEvent`：冻结和高度淘汰。
- `EntityDamageEvent` / `EntityDamageByEntityEvent`：阶段伤害和 PVP。
- `PlayerInteractEvent`：补给箱与追踪指南针。
- `FoodLevelChangeEvent`：阶段饥饿规则。
- `BlockBreakEvent` / `BlockPlaceEvent`：白名单方块规则。
- `EntityExplodeEvent`：爆炸地图破坏和实体归属清理。
- `BlockBurnEvent` / `BlockIgniteEvent`：火焰蔓延。
- `PlayerDropItemEvent` / `EntityPickupItemEvent`：非存活玩家输入保护。

## 清理路径

- `onPlayerLeave`：淘汰判定、视觉清理、状态恢复、胜负检查。
- `eliminate`：只执行一次，停止玩法输入、清背包或保留死亡掉落、进入观战。
- `onEnd`：停止玩法、恢复在线玩家运行时状态、清计分板和名牌。
- `onClose`：模块清箱子缓存和 Session 集合；主插件随后关闭 `RoomResourceScope` 并清淘汰观战状态。

## 验收标准

- 6 至 24 人固定出生点开局，倒计时期间不能移动位置。
- 保护期内所有伤害无效，结束后 PVP、环境伤害和饥饿正常。
- 同一箱子内容对所有玩家共享，取走后不会复制。
- 补货后箱子重新生成且只发生一次。
- 存活人数降到阈值时触发提前决赛预告。
- 决赛固定点传送、最后一人生还、超时平局正确。
- 原版死亡、离开和高度淘汰统计不重复。
- 至少三个 hunger 房间并发时箱子、阶段、出生点、实体和结算不串房。
- 强制关闭、停服和玩家退出后无任务、名牌、实体、临时方块或玩家状态残留。
