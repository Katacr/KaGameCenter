# 空岛战争模块技术细节

更新时间：2026-07-13

## 模块形态

运行目录：

```text
plugins/KaGameCenter/modules/skywars.jar
plugins/KaGameCenter/modules/skywars/config.yml
plugins/KaGameCenter/modules/skywars/lang/
plugins/KaGameCenter/modules/skywars/games/game/<游戏名>.yml
plugins/KaGameCenter/modules/skywars/games/map/<游戏名>/
```

入口类为 `SkyWarsModuleProvider`。Provider 只注册模块、监听器、聊天格式、管理员命令和编辑器，不保存单局玩家数据。

## 源码结构

```text
SkyWarsModuleProvider.kt       模块装配入口
SkyWarsGameModule.kt           GameModule 元数据和 Session 工厂
SkyWarsGameSession.kt          阶段、队伍、箱子、职业、淘汰和结算
SkyWarsListener.kt             Bukkit 事件房间路由
SkyWarsModels.kt               配置与单局状态模型
SkyWarsConfigService.kt        模块配置和托管字段读写
SkyWarsManagedGameEditor.kt    托管游戏可视化编辑面板
SkyWarsAdminCommand.kt         管理员快捷命令
```

## Session 生命周期

- `onPrepare()`：加载模块和托管配置，从私有快照创建临时世界，启用立即重生并准备箱子方块。
- `onPlayerJoin()`：捕获玩家运行状态；等待阶段加入参赛，开局后加入观战。
- `onStart()`：校验地图、动态注册队伍、分配岛屿、应用职业、填充箱子并进入出生倒计时。
- `onTick()`：推进倒计时、PVP 保护、运行、补货、结算和关闭阶段。
- `onPlayerDeath()`：只更新模块存活状态；通用死亡统计由主插件记录。
- `onPlayerLeave()`：运行中离开按淘汰处理，等待阶段直接移除状态。
- `onClose()`：清空模块集合；通用资源和临时世界随后由主插件释放。

## 队伍和胜负

开局根据玩家数与 `team-size` 计算队伍数：

```text
teamCount = ceil(playerCount / teamSize)
```

模块动态注册 `team_1`、`team_2` 等房间队伍，再通过 `TeamAssignmentService` 随机轮转分配。岛屿点按队伍而不是玩家分配，因此岛屿数量至少等于队伍数。

胜负检查只读取 Session 内存活状态：

- 没有存活玩家：平局。
- 只剩一个存活队伍：该队所有开局参赛者获胜。
- 仍有多个队伍但总时间结束：平局。

`resultRecorded` 保证 `recordWinLoss` 每局只执行一次。

## 淘汰和统计

- Bukkit 正常死亡由主插件记录 kill/death，Session 只更新局内击杀显示与存活状态。
- 虚空、离开和断线超时没有可靠的 Bukkit 死亡事件，由模块补记统计。
- 每次有效敌方伤害保存攻击者 UUID 和时间；虚空或离开淘汰时，仅在 `kill-attribution-seconds` 内归因。
- 同队攻击在写入攻击归因之前取消。
- 断线宽限期间保留房间席位、队伍、背包和位置；超时后离线淘汰。

## 物资箱

托管配置中的箱子结构：

```yaml
skywars:
  chests:
    - id: island_1
      tier: island
      point:
        x: 10.0
        y: 70.0
        z: 10.0
```

地图点不是容器时，准备阶段临时替换为木桶，并交给 `RoomResourceScope` 保存原方块。箱子使用世界真实容器库存，所以同一房间所有玩家共享内容，不同房间因临时世界不同而天然隔离。

补货会先关闭正在查看相关容器的玩家，清空并按 `refill-multiplier` 提高价值预算重新生成。

## 方块和世界规则

- 只有存活玩家且处于 `GRACE`/`RUNNING` 阶段才能修改方块。
- 放置与破坏位置必须位于托管 `play-region`。
- 箱子、屏障、基岩等 `protected-materials` 始终受保护。
- 爆炸方块列表会过滤到游戏区域内，并排除受保护方块。
- 火焰蔓延和怪物生成由模块配置控制。
- 玩家低于 `void-y` 时直接进入淘汰观战，不等待原版虚空死亡动画。

## 托管配置

```yaml
skywars:
  map-id: default
  team-size: 1
  next-island-index: 1
  next-chest-index: 1
  lobby: {}
  spectator-spawn: {}
  play-region: {}
  island-spawns: []
  chests: []
  void-y: -64.0
```

### 连续采集

- “连续添加岛屿出生点”调用 `beginPositionCapture`，骨头右键读取玩家脚下整数坐标。
- “连续添加物资箱”调用 `beginBlockCapture`，骨头左键读取目标方块坐标。
- 每次点击都重新读取最新托管配置，通过 `addNextManagedIslandSpawn` 或 `addNextManagedChest` 分配编号并立即保存 YAML。
- `next-island-index` 和 `next-chest-index` 是持久化单调计数器；已有旧配置没有计数器时，从当前最大数字后缀继续。
- 采集前验证玩家仍在对应托管游戏编辑世界，防止坐标写入错误地图。

## 构建与验收

```text
sh ./gradlew :modules:skywars:jar
```

产物必须包含 `config.yml` 和 `lang/`，且不能包含 `plugin.yml`。首次实服测试应至少覆盖：单人四岛、双人组队、多房间并发、虚空攻击归因、箱子补货、断线重连和管理员强制关闭。

## 当前限制

- 模块不内置地图；必须先提供 Paper 世界模板，再通过管理面板创建托管游戏私有快照。
- 第一版职业支持普通物品、护甲和权限，不包含经济扣费、药水元数据或自定义附魔解析。
- 每局按配置时间统一补货一次，暂不支持多轮独立箱型补货计划。
- 第一版不提供地图投票；具体地图由玩家创建房间时选择的托管游戏决定。
- 运行超时按平局结算，不按击杀数、血量或存活人数强制选出胜者。
