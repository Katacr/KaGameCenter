# BedWars 实服回归矩阵

更新时间：2026-07-15

## 安全边界

- 只在独立测试实例和复制地图上执行，不自动部署到生产服。
- 源码、构建资源和 JAR 内 `config.yml` 必须继续保持 `enabled: false`；测试实例只修改其外部管理员配置。
- 未取得明确测试窗口时，不复制 JAR、不修改服务、不重启或热重载服务器。
- 不覆盖外部配置、语言、菜单、地图、数据库和日志；每轮使用新的托管游戏 local ID。
- 任一启动异常、世界清理失败、跨房间串状态或玩家状态无法恢复时立即停止后续用例并保留日志。

## 最小阵容

- 客户端 A、B：不同队伍的存活玩家。
- 客户端 C：A 的队友，用于队伍聊天、资源分摊、升级和陷阱。
- 客户端 D：外部观战者，用于第一人称目标、隐藏装备、Tab 和 Sidebar。
- 第二房间至少保留一名玩家，用于任务、聊天、计分板、实体和统计隔离检查。

## 对局主流程

| 编号 | 操作 | 预期 |
| --- | --- | --- |
| G01 | 创建房间并加入 A/B/C，在等待阶段分别点击战绩、离开及自定义命令快捷物品；运行阶段在 `party` 不在/已在白名单及管理员权限下执行普通子命令和 `party home/sethome`，并复测大小写、连续空白及 `插件名:party` 形式 | 只准备一次临时世界，队伍容量和倒计时正确；快捷命令均在下一 tick 最多执行一次，离开命令不在交互事件中重入且不会损坏剩余房间状态，回调前离房、关房或进入倒计时则不再执行旧命令；普通 `party` 子命令遵循管理员权限和白名单，`home/sethome` 在所有列举形式下始终拒绝且管理员不能绕过 |
| G02 | 倒计时中退出并重进 C | 队伍不重复分配，开局装备只发一次 |
| G03 | 开局后检查四槽护甲和木剑 | 队色、永久 PDC、不可损坏和团队强化一致 |
| G04 | 普通死亡后复活 | 非永久物品按配置掉落，护甲/剪刀保持，镐斧正确降级 |
| G05 | 破床后普通死亡 | 只最终淘汰一次，死亡分类、广播、统计和事件不重复 |
| G06 | 仅剩一队 | 胜负、榜单、奖励、经验、金币和结果倒计时只结算一次 |
| G07 | 结果结束或最后成员离开 | 玩家状态完整恢复，世界、任务、实体、计分板和名牌清理 |
| G08 | 对非白名单命令及大小写、连续空白、命名空间形式的 `party home/sethome` 解除模块取消；再由高优先级监听器把允许命令改写为上述禁用命令，并把禁用命令改写为允许命令 | 模块已拒绝的事件在 MONITOR 仍取消且只提示一次；最终文本新变为禁用命令时同样拒绝，不能通过改写或管理员权限执行队伍传送；模块已经接管的拒绝不能通过后置改名翻转为允许 |
| G09 | 在环境死亡、普通击杀和最终击杀的高优先级监听器中重新加入永久装备、武器工具、普通物品及四类资源，并分别开启/关闭 `vanilla-death-drops` | MONITOR 再次清除永久 PDC 物品；经典模式环境死亡只留资源、普通击杀只留直送背包装不下的资源、最终击杀死亡点无残留，资源直送、消息、末影箱清空和基地回收不重复；原版掉落模式仅强制移除永久物品 |
| G10 | 将 `min-players` 设为 2、`auto-start-min-players` 设为 4：依次加入 1–4 人，倒计时中降回 3 人，再补回 4 人；让参赛者和外部观战者保持房间详情 Dialog 打开并等倒计时结束 | 1–3 人始终留在大厅且不生成商店、生成器、床提示或开局装备；第 4 人加入后只进入完整等待倒计时，降到 3 人立即取消并恢复等待物品，重新达到 4 人后重开倒计时；结束时全部房间成员 Dialog 关闭，随后才一次性传送到队伍出生点、生成实体、发放装备并进入 `RUNNING` |
