# BedWars 模块技术细节

更新时间：2026-07-14

## 当前定位

`bedwars` 是 KaGameCenter 外置小游戏模块。当前已完成第二百一十阶段陷阱分类内容移植，模块默认 `enabled: false`，已经具备模块加载、地图编辑、核心对局、建筑资源循环、商店强化、自定义显示、可配置重连宽限、经典特殊商品及玩家快捷购买。

参考输入固定为 `modules/BedWars1058-master.zip`，压缩包提交为 `669872626ec4160b6896755ba1d79bbed96787fb`。参考项目使用 GPL-3.0；当前实现只做玩法行为和数据模型映射，没有复制其 Java 类或 NMS 实现。若后续直接复用源码，必须先确认 KaGameCenter 的分发许可证兼容性。

## 架构映射

| BedWars1058 概念 | KaGameCenter 实现 |
| --- | --- |
| Arena | 每房间一个 `BedWarsGameSession` |
| ArenaConfig | 托管游戏 yml 的 `bedwars` 节点 |
| BedWarsTeam | `BedWarsTeamConfig` + `GameTeamService` |
| OreGenerator | session 内资源点状态和房间任务 |
| Shop/Upgrades | 模块箱子菜单数据源和商品配置 |
| Arena restore | 托管私有快照 + `TemporaryWorldService` |
| Spectator | 外部可配置 `MANAGED/VANILLA`，最终淘汰固定 `MANAGED` |

所有局内玩家、床、生成器、商店实体、临时方块和任务必须属于 session 或对应 roomId，禁止放入 Provider 静态集合。

所有 `GameRoom.state` 真实变化会由主插件同步发布 `GameRoomStateChangeEvent`。开始房间时模块先从 `WAITING` 进入内部 `COUNTDOWN`，主插件不再预写入瞬时 `RUNNING`，因此外部监听器看到的公共状态顺序与实际 BedWars 阶段一致；重复写入相同状态不会产生事件。

参考竞技场启用、禁用和重启服务事件按 KaGameCenter 临时房间模型映射为不可取消的 `GameRoomPreparedEvent` 与 `GameRoomClosedEvent`。BedWars `onPrepare()` 完成私有地图、点位、生成器和商店初始化并进入 `WAITING` 后才发布准备事件；准备失败不发布。关闭事件在历史成员离场通知、房间资源作用域和运行世界清理、`CLOSED` 状态提交后发布，并保留可空世界名及世界清理结果；监听器不能在该回调中继续访问已卸载世界。

参考 `SetupSessionStart/CloseEvent` 映射为通用 `GameMapEditSessionStartedEvent` 与 `GameMapEditSessionClosedEvent`。BedWars 托管地图首次打开私有编辑世界时发布启动事件，共享会话后续加入不重复发布；显式关闭或主插件停机关闭会在可选保存、编辑者恢复和世界清理结束后发布不可取消结果。关闭快照保留全部编辑者 UUID 及保存/清理状态，离线编辑者索引也会移除，避免下次上线误绑定已关闭会话。

`/kgc admin bedwars` 提供独立模块管理入口：`reload` 重读模块配置与语言，`list/arenaList` 列出全部 BedWars 托管玩法及分组、启用、私有地图和校验状态，`edit/setup <globalId>` 打开托管编辑菜单。编辑菜单可保存通用 `selector-group`，并在私有编辑世界中继续提供 `setlobby/setspectator/setvoidy/setmaxbuildy/save/close/validate/preview`；这些命令全部委托既有 `BedWarsManagedGameEditor`，与 GUI 共用校验、保存和地图会话语义，不维护第二套点位写入逻辑。配置重载先严格解析和构造完整类型化视图，再把默认值与兼容迁移通过同目录 `config.yml.tmp` 原子提交；损坏 YAML、解析或写入失败时保留原文件及旧内存配置并返回双语错误，正式文件缺失但存在完整临时文件时可继续恢复。成功重载立即影响服务级读取，已经创建的 session 仍保留其准备阶段规则快照。

`ModuleLanguage` 不覆盖或合并运行目录中的管理员语言文件，但加载时按“外部当前语言 → JAR 内当前语言 → 外部英文 → JAR 内英文 → 主插件”查找每个键。因此旧 BedWars 语言文件缺少后续阶段新增键时会直接使用当前模块 JAR 的同语言默认值，而不会显示键名；管理员已经修改或显式留空的值仍优先。模块资源目录统一传入 `lang`，核心已修正旧版误拼接为 `lang/lang/<locale>.yml` 的路径。

## 托管配置结构

```yaml
bedwars:
  lobby: {}
  spectator-spawn: {}
  void-y: -64.0
  max-build-y: 180
  world-border: 300
  allow-spectate: true
  allow-map-break: false
  island-radius: 17
  disable-generator-for-empty-teams: false
  disable-npcs-for-empty-teams: true
  vanilla-death-drops: false
  use-bed-hologram: true
  game-end:
    show-eliminated: true
    teleport-eliminated: true
    chat-top: { order-by: KILLS, hide-missing: true }
    sb-top: { order-by: KILLS, hide-missing: true }
  spawn-protection: 5
  shop-protection: 1
  upgrades-protection: 1
  generator-protection: 1
  game-rules:
    - "doDaylightCycle:false"
    - "announceAdvancements:false"
    - "doInsomnia:false"
    - "doImmediateRespawn:true"
    - "doWeatherCycle:false"
    - "doFireTick:false"
  teams:
    red:
      display-name: "红队"
      color: RED
      max-players: 1
      spawn: {}
      bed: {}
      kill-drops: {}
      shop: {}
      upgrade-shop: {}
      generators:
        iron:
          type: IRON
          interval-ticks: 40
          point: {}
        gold:
          type: GOLD
          interval-ticks: 120
          point: {}
  generators:
    diamond-1:
      type: DIAMOND
      interval-ticks: 600
      point: {}
```

点位节点包含 `x/y/z/yaw/pitch`，不保存世界名。开始前至少需要大厅、观战点、两个完整队伍、一个钻石生成器和一个绿宝石生成器，且每队包含出生点、床、两个商店点和铁/金生成器。

托管地图 `bedwars.world-border` 默认 300 格，与参考竞技场一致；旧地图缺失时回退模块 `game.world-border-size`，任一有效值设为 `0` 都可只使用 KaGameCenter 模板边界。运行世界创建完成后，模块仅在主插件根据 region 文件生成的边界更大时，以等待大厅为中心收窄到地图值，绝不会放大已有模板安全边界。

## 地图编辑器

管理员从托管游戏管理界面打开 BedWars 编辑器。编辑器支持：

- 自动从公共模板创建私有地图快照，并打开、保存或关闭编辑世界。
- 使用稳定 `team_id` 新建、更新和删除队伍。
- 为选中队伍设置出生点、床、物品商店、升级商店和铁/金生成器。
- 可选设置最终掉落回收点；旧地图未配置时自动使用队伍铁生成器、首个队伍生成器或出生点。
- 使用稳定 `generator_id` 设置或删除公共钻石/绿宝石生成器。
- 以管理员当前脚下高度设置 `void-y` 和 `max-build-y`。
- 编辑岛屿半径、空队生成器、空队商店 NPC、原版死亡掉落和床全息五项地图规则。
- 保存地图规则时校验岛屿半径为 1 至 128，并要求布尔值使用不区分大小写的 `true` 或 `false`。
- 编辑世界边界、外部旁观、普通模板方块破坏，以及出生点、物品商店、升级商店和生成器保护半径。
- 世界边界限制为 0 至 60000000 的整数，保护半径限制为 0 至 32 的数字；摘要展示地图有效值，旧地图缺失字段时展示模块级回退值。
- 编辑结算显示淘汰者、传送淘汰者开关，以及分号分隔的 `name:value` 原版游戏规则列表。
- 保存游戏规则时按 Bukkit 注册表校验名称及布尔/整数值类型并规范化；留空保存空列表，只保留模块固定的房间隔离基线规则。
- 分别编辑聊天榜和 Sidebar 榜的排序统计项及零值隐藏开关；支持普通击杀、最终击杀、死亡、最终死亡和破床数。
- 地图缺失任一榜单字段时独立回退模块 `game-end` 配置，编辑器摘要和输入框展示实际有效值。
- 校验所有必需字段，并用临时信标光柱或方块高亮预览点位。

队伍颜色和值类型输入不区分大小写；ID 会转换为小写并把非法字符替换为 `-`。删除操作始终使用稳定 ID，不依赖菜单顺序。

## 核心对局状态

- `WAITING`：首次加入时自动分配当前人数最少且未满的队伍；玩家可在 KaGameCenter 通用房间菜单中主动换队。
- `COUNTDOWN`：玩家锁定在队伍出生点，禁止伤害和地图修改。
- `RUNNING`：床存活时死亡进入配置秒数的复活倒计时；床被破坏后再次死亡即最终淘汰。
- `RESULT`：只剩一个仍有成员存活的队伍时记录整队胜负，显示结果并进入观战。
- `CLOSING`：结果展示和关闭延迟结束后通过 `GameRoomManager.closeRoom` 统一清理房间。

从倒计时进入 `RUNNING` 时，在线参赛者完成生存模式、初始装备和队伍强化发放后逐人发布不可取消的 `GamePlayerFirstSpawnedEvent`。玩家状态中的 `firstSpawned` 保证每局只发布一次；倒计时期间断线并跨过开局时刻的玩家在运行期重连时会先补发完整木剑、护甲和永久工具再发布，修复旧路径只有护甲、没有初始武器工具的问题。普通运行期重连继续保留背包，不重复清空或发布。

模块级 `spectator.enabled` 是外部观战总开关，默认开启；关闭后所有未参加本局的玩家（包括管理员）都会被通用策略层拒绝。开启时，托管地图 `bedwars.allow-spectate` 与参考默认值一致为 `true`，控制单张地图是否允许外部旁观；地图关闭时拥有 `kagamecenter.admin` 的管理人员仍可检查房间。床毁后的最终淘汰属于参赛者内部状态，不受两个外部准入开关影响并始终进入托管观战。

在线人数达到最低人数后会自动开始 `countdowns.game-start-regular` 倒计时，参考默认值为 40 秒；人数达到房间容量一半且高于最低人数时，剩余时间最多缩短到 `game-start-half-arena` 的 25 秒，满员后最多缩短到 `game-start-shortened` 的 5 秒。倒计时只会缩短，人数下降不会重新延长；低于最低人数时立即取消、释放预生成实体并把在线玩家送回等待大厅。旧版 `game.countdown-seconds` 会在首次重载时迁移为 regular 值，保留服主原有时长。

等待大厅支持参考默认开启的 `lobby-settings.void-tp`，玩家低于 `void-height`（默认 0）时回到地图大厅点，关闭后允许地图自行处理负高度区域。复活倒计时中的玩家低于 Y=0 时回到队伍出生点，外部观战者和最终淘汰玩家则回到地图观战点；两类观战状态都会重新获得飞行，且不会触发正式参赛者的死亡、资源转移或击杀归因。

聊天通过主插件新增的 `GameSession.routeChat` 房间级钩子保持统一审计和串台防护。等待及倒计时阶段普通消息发送给本房间；运行期多人队伍默认仅队友可见，单人队伍按参考行为发送给参赛者和观战者。消息以 `!`、大小写不敏感的 `shout`、当前语言 `bedwars.chat_shout_prefix`（中文默认“喊话”）开头，或者使用 `/a` 时进入喊话频道并去除前缀，`chat.shout-cooldown-seconds` 默认 30 秒且四种入口共享冷却。四类入口统一要求 `kagamecenter.bedwars.shout`；该权限默认开放以保持现有开箱行为，但权限插件可显式拒绝。`kagamecenter.bedwars.shout.bypass` 默认仅 OP，拥有者和 `kagamecenter.admin` 不读取也不写入冷却状态，对齐参考独立 bypass 语义。`chat.format` 默认开启 BedWars 专属队伍、房间、喊话和观战格式，关闭后动态回退 KaGameCenter 通用房间/队伍格式；首次加载兼容参考 `chat-settings.format` 和旧 `formatChat`。专属格式继续兼容既有 `{0}/{1}/{2}`，并支持参考 `{vPrefix}/{vSuffix}/{playername}/{player}/{level}/{team}/{message}`；前后缀复用 Tab 的可选 PlaceholderAPI/Vault 解析，缺插件或扩展时为空，旧式样式码在当前纯文本聊天输出中转为无控制符文本。token 通过单次模板匹配展开，玩家消息或显示名中出现相同字面 token 不会被递归替换。参考 `chat-settings.global` 不移植为跨房收件人开关，因为 KaGameCenter 是共享多玩法服务器，所有非显式全局频道始终保留房间边界。外部观战者、最终淘汰玩家和结算玩家只能向同房间观战群体发言，无法泄露给仍在对局的队伍。

`game.default-item-groups` 按参考实现保存模块级开局物品组，每张托管地图通过 `bedwars.item-group` 选择，未配置或组名不存在时回退 `default`。条目沿用 `MATERIAL,legacy-data,amount,display-name` 格式，现代版本忽略第二列旧数据值，数量限制在材料堆叠上限，显示名支持 `&` 颜色；默认仍为 `WOODEN_SWORD`。这些物品带独立永久标记、不可损坏，并在首次出生和每次正常复活时重发；同一批次只保留第一把剑和第一把弓，队伍锋利升级继续应用。地图编辑器可保存组名，物品列表仍由模块配置统一维护，避免为每张地图复制商品规则。

`game.mark-leave-as-abandon` 与参考默认值一致为 `false`。关闭时，正式开局后的主动离房玩家继续保留在本局历史参与者中，最终结算统一记录胜负；开启时，离场者会从历史参与者集合移除并失去本局最终胜负记录，但不会额外即时增加失败或死亡，避免与结算重复记账。断线宽限使用独立重连流程，不会触发弃赛；宽限到期仍按正常淘汰和最终结算处理。主动离场导致某队失去最后有效成员时会立即触发一次整队淘汰公告和胜负检查。

倒计时在每个 10 秒节点和最后 5 秒向正式玩家播放提示音。与参考 `GameStartingTask` 的有效分支一致，10 秒倍数及 5 秒使用 `game.sounds.countdown`，4、3、2、1 秒分别使用 `game.sounds.countdown-final.<秒数>`；参考配置虽声明 `game-countdown-s5`，当前参考任务在 5 秒实际选择 `game-countdown-others`，因此本模块不生成无效的第五项。所有默认值均为 `ENTITY_CHICKEN_EGG` 并支持 `NONE/volume/pitch`。旧模块配置首次补齐四项时复制当前通用倒计时的声音、音量和音高，保留已有自定义值；进入运行阶段仍播放 `game.sounds.start`（默认 `BLOCK_SLIME_BLOCK_FALL`），ActionBar 每秒更新且受众继续包含观战者。

生命周期反馈继续对齐参考默认值：正常复活或离线期间倒计时结束后的重连只向本人播放 `game.sounds.respawn`（`BLOCK_SLIME_BLOCK_FALL`）；全床销毁、殊死决战和结算开始分别向当前参赛者及观战者播放 `game.sounds.all-beds-destroyed`（`ENTITY_ENDER_DRAGON_GROWL`）、`game.sounds.sudden-death`（`ENTITY_ENDER_DRAGON_FLAP`）和 `game.sounds.end`（`ITEM_TRIDENT_THUNDER`）。四类音效都支持 `NONE`、音量和音高配置，每个事件只在对应状态切换时触发一次。

正式玩家完成队伍分配和传送后播放 `game.sounds.join-allowed`，宽限期重连完成阶段/装备恢复后播放 `game.sounds.rejoin-allowed`，外部观战者完成观战点传送和显示附加后播放 `game.sounds.spectate-allowed`；三者默认与参考实现一致为 `ENTITY_SLIME_JUMP`，只向当事人播放并支持 `NONE`。对应的 `join-denied/rejoin-denied/spectate-denied` 默认均为 `ENTITY_VILLAGER_NO`，由通用 `GamePlayerRoomAdmissionDeniedEvent` 按 `JOIN/RECONNECT/SPECTATE` 路由；加入时玩法队伍总容量不足也补发加入拒绝音。房间状态、人数、观战策略、准备失败和可取消事件拒绝均不会误播成功音，重连取消先播放拒绝反馈再恢复大厅状态。三类拒绝音同样支持 `NONE`、音量和音高；不存在目标房间和代理预留不属于在线 BedWars Session，不播放模块音效。

`allow-hunger-depletion.waiting` 与 `allow-hunger-depletion.ingame` 均与参考默认值一致为 `false`。前者控制等待、倒计时、结果和关闭阶段，后者只控制正式运行阶段；外部观战者和最终淘汰玩家始终禁止饥饿变化。玩家加入、开局和复活时仍初始化为满饥饿与饱和度，允许消耗后由原版机制自然变化，离房时由主插件玩家快照恢复原值。

托管观战者选择有效跟随目标时播放参考 `spectator-gui-click` 反馈，模块配置路径为 `game.sounds.spectator-target-click`，默认 `ENTITY_SLIME_JUMP`。监听发生在 `GameSpectatorTargetSelectEvent` 的 MONITOR 阶段并只接受 `TELEPORT`：与参考头像点击一致，即使外部监听器取消选择、重复选择当前目标或后续 Bukkit 传送失败仍播放；`VANILLA` 自动首目标、目标清除和其他模块事件不会误播。音效支持 `NONE`、音量和音高。

基础生存限制继续与参考默认值一致：`inventories.disable-crafting-table`、`disable-enchanting-table`、`disable-furnace`、`disable-brewing-stand` 和 `disable-anvil` 默认全部开启；对应地图工作站不可打开，铁砧同时覆盖普通、开裂和损坏变体，禁用合成还会清空工作台及玩家个人 2×2 合成栏结果。服主可单独关闭任一限制。

竞技场环境在 BedWars 房间内独立锁定：创建运行世界时关闭自然生物生成和火焰蔓延，后续天气事件不能重新开启降雨；非 `CUSTOM` 原因的生物生成会被拒绝，因此模块商店村民、床虫、梦境守卫和末影龙仍可正常创建。默认情况下，火焰燃烧、冰融化、仙人掌物理更新和生物踩踏耕地均不会改写模板或玩家建筑；等待、倒计时和结算阶段产生的地面物品会被丢弃，运行阶段额外过滤所有床物品和小麦种子，正常资源、死亡掉落和玩家主动丢弃不受影响。

每张托管地图支持参考格式的 `bedwars.game-rules` 字符串列表。新地图和未配置旧地图默认应用参考的六项规则：关闭昼夜、进度公告、失眠、天气与火焰 tick，并开启立即复活；应用前仍先设置 `keepInventory=false` 和 `doMobSpawning=false` 作为当前死亡掉落与房间隔离基线，列表中的同名显式项可按顺序覆盖原版规则。非法名称、值或缺少冒号的条目会记录警告并跳过，模块级模板保护事件不因原版规则放宽。

玩家进入 BedWars 后会像参考 `PlayerGoods` 一样把局内经验等级、进度和总经验重置为零；大厅经验已在 KaGameCenter 快照中保留，离房或关房时完整恢复。任何房间阶段的玩家死亡都会关闭原版死亡广播并把经验掉落设为零，只保留模块按击杀来源和最终淘汰状态发送的双语消息，避免重复聊天以及大厅经验在房间内通过经验球转移。

BedWars 玩家初始化同时把生命缩放设为参考值 20，避免大厅自定义血条比例干扰对局。主插件 `PlayerSnapshot` 现在同时保存 `healthScaled` 开关和精确 `healthScale`，恢复时先还原缩放再恢复生命；大厅原有的关闭状态或自定义比例都不会被模块覆盖。药水效果仍由既有 `PlayerRuntimeStateService` 单一负责，避免两个快照来源重复恢复。

实际 `Attribute.MAX_HEALTH` 基础值也在所有 BedWars 重置入口固定为 20，当前生命最多恢复到 20，避免大厅插件只修改真实生命属性而绕过显示缩放。通用 `PlayerSnapshot` 保存入房前基础值，离房时先还原基础属性和原装备，再按恢复后的有效上限恢复精确生命，兼容装备属性提供的额外生命且不会触发超上限异常。

吸收生命是玩家独立数值而非普通药水效果。主插件快照会记录入场前精确 `absorptionAmount`，BedWars 每次玩家初始化和复活都将其清零，使大厅黄心不能带入对局、金苹果产生的局内黄心也不能带回大厅；离房和关房恢复顺序位于真实生命之后，不改变既有生命缩放或药水职责。

开局、复活和等待重置还会清除燃烧、冻结、缺氧、身体箭矢、蜂刺、摔落距离和残余速度，避免上一条命的视觉实体或运动量带入新生命；其中身体箭矢与参考死亡清理一致。通用 `PlayerSnapshot` 同步保存并恢复这七项状态，因此入房前大厅中的环境状态不会因模块隔离永久丢失。

同一统一重置路径把步行和飞行速度固定为原版标准 `0.2/0.1`，因此大厅权限、其他玩法或管理工具设置的加速与减速不会带入 BedWars 等待、开局、复活或重连。`PlayerRuntimeStateService` 已在入房前保存两项值并在退出时恢复，模块归一化只影响房间生命周期。

玩家重力、服务端碰撞和碰撞例外集合由 `PlayerRuntimeStateService` 保存并在离房时恢复，主插件完整快照也保存后二者以覆盖断线超时后的延迟恢复。BedWars 重置期间恢复重力并清空临时碰撞例外：等待、倒计时、复活中、淘汰、结算和外部观战状态禁用碰撞；运行期存活成员启用碰撞，并把同队 UUID 加入 `collidableExemptions`，因此只与敌队发生服务端碰撞。每次重置同时结束滑翔、潜行和冲刺，防止传送前姿态或速度判定带入等待点与出生点，之后仍由玩家正常输入重新触发。

完整玩家快照在首次正式加入或观战前同步原子写入 `plugins/KaGameCenter/data/player-snapshots/<uuid>.yml`，因此正常停服关房时离线玩家、进程异常退出以及插件重载后都不依赖旧内存 Session。写入使用同目录 `.tmp` 和原子移动；若进程在移动前中断，登录恢复仍会识别临时文件。恢复按 UUID、名称重新解析已加载世界，原世界不存在时回退服务器首个世界出生点；传送及全部 Bukkit 状态应用成功后才同时删除正式、临时文件。损坏或无法删除的快照会保留并记录警告，新房间准入和 Velocity 加入意图都会暂停，避免覆盖尚未恢复的大厅状态。

不会经过方块破坏事件的模板交互也受保护：玩家无法进入任何床或操作盔甲架；普通及发光物品展示框、画不能被攻击或由实体移除。已有物品的展示框禁止旋转，空展示框仍允许首次放入普通物品，但永久护甲、工具和剪刀会被独立 PDC 规则拒绝，避免把死亡后重发物品锁进模板实体造成复制。

运行世界复制模板时会携带 `entities` 区域数据。Session 在初始化已加载区块及后续 `EntitiesLoadEvent` 中移除所有未登记的模板实体，只保留玩家、画、普通/发光物品展示框和当前房间 `trackedEntities`。本局商店、全息、资源、TNT、投射物、召唤物与末影龙的 UUID 会保留到关房，避免区块暂时卸载时被误判失效；模板遗留怪物、掉落物、载具和设置标记则无法在远端区块重新出现。

床在运行世界中按两个床方块建立索引。玩家只能破坏敌队床，破坏事件不会生成床物品。虚空会进入标准 Bukkit 死亡流程，因此击杀、死亡和复活语义不会绕过主插件事件链。

手动破床在受害队 `bedAlive`、双床方块索引和破床持久指标全部更新后发布不可取消的 `GameObjectiveDestroyedEvent`。目标类型固定为 `bed`，目标 ID 与目标队伍 ID 均使用受害队稳定 ID，并携带破坏者及其队伍 ID；同一床的另一半方块已从索引移除，因此不会重复触发。

同一手动破床路径随后在默认聊天和受害队标题发送前发布 `GameObjectiveDestroyedFeedbackEvent`，复用相同目标、破坏者、双方队伍和 `sourceId=player` 上下文。`message` 面向破坏者、其他队伍和观战者，并作为聊天总开关；`targetMessage` 按参考 `PlayerBedBreakEvent` 面向仍存活的受害队成员，为 `null` 时回退普通消息，而 `message=null` 时整体抑制聊天。监听器可独立替换或置空受害队 `targetTitle/targetSubtitle`；事件不取消已提交的床状态、破床统计、经验和前述后置事件，也不改变敌我破床音效。新增属性不改变事件原 10 参数 JVM 构造器。时间线自动销毁没有参考玩家反馈事件，因此只发布不可变目标销毁观察事件。

时间线全床销毁先筛选仍存活的队伍床，统一提交 `bedAlive=false`、移除世界床方块并清空索引，再按队伍发布同一目标事件。正常床销毁阶段使用 `sourceId=beds-destroy`，若配置使殊死决战先到则使用 `sourceId=sudden-death`；两者 `actor/actorTeamId` 均为空，已经由玩家破坏的床不会重复通知。主插件继续保留旧六参数事件构造签名，已有外置监听器无需重新编译。

手动破床时，仍存活的受害队成员收到“床已被摧毁 / 无法再次复活”个体标题及 `game.sounds.own-bed-destroyed` 警报；破床者、其他队伍和观战者播放 `game.sounds.bed-destroyed` 普通音效。默认分别为 `ENTITY_WITHER_DEATH` 与 `ENTITY_ENDER_DRAGON_GROWL`，均支持 `NONE`、音量和音高配置。

地图级 `bedwars.use-bed-hologram` 与参考默认值一致为 `true`，旧地图缺失时回退模块 `game.use-bed-hologram`。倒计时开始后为每名在线参赛玩家在己方床上生成一个仅本人可见的无碰撞盔甲架名称提示；其他玩家和观战者通过 Bukkit viewer 隐藏。运行阶段本人进入己方床四格范围时也会隐藏提示，离开后重新显示，避免名称遮挡近距离防守和放置。床被破坏或定时销毁后提示切换为已破坏文本，断线、离房和关房均解除实体及资源登记。

`game.respawn-invulnerability-seconds` 默认 4 秒，与参考实现的 4000ms 一致。完成普通复活或运行期重连复活后，玩家在房间对局 tick 截止前免疫环境、玩家、召唤物和末影龙伤害；主动对敌方造成有效攻击会提前解除自身保护。剩余时间优先显示在 ActionBar，死亡、淘汰和新一局初始化都会清空旧截止值。

复活倒计时清零后，session 先把 `respawning` 设为 `false`，再恢复生存模式、装备、队伍强化、出生位置和复活保护，最后发布不可取消的 `GamePlayerRespawnedEvent`。在线死亡倒计时与运行期重连倒计时使用相同完成语义；较早的 Bukkit `PlayerRespawnEvent` 只负责临时位置和观战模式，不会提前发布完成事件。该 Bukkit 入口按参考 `DamageDeathMove` 使用 MONITOR 优先级，只为仍处于普通复活中的 BedWars 玩家最终指定队伍出生点，因此其他插件在较高优先级写入的外部重生点不能把玩家送出竞技场；最终淘汰者不走该覆盖，继续由核心淘汰服务使用观战点。

最后一名有效成员被淘汰或重连宽限到期后，session 只广播一次整队淘汰并登记空队状态。地图级 `bedwars.disable-generator-for-empty-teams` 与参考默认值一致为 `false`，旧地图回退模块 `game.disable-empty-team-generators`；启用后，该队铁/金生成器及高阶锻炉绿宝石停止产出，公共钻石和绿宝石生成器不受影响。

`eliminatedTeams` 首次登记稳定队伍 ID 后会发布不可取消的 `GameTeamEliminatedEvent`，随后才进入胜负检查。最终死亡、主动离场和重连宽限到期共用同一入口，重复回调或后续成员清理不会再次发布。

基础击杀/死亡由主插件 `GamePlayerListener` 统一记录；BedWars 覆盖 `GameSession.resolveKiller`，把敌方玩家造成的有效伤害用于延迟死亡归因：虚空、火球、TNT 和断线等路径回溯 15 秒，死亡态摔落按参考 `PLAYER_PUSH` 单独回溯 10 秒；Bukkit 当前直接击杀者仍优先。模块累计五类局内数据，并通过 `GameResultService.recordWinLoss` 记录最终胜负和 `game.win-points`。全部统计写入成功后会发布不可取消的 `GameResultRecordedEvent`，其中获胜组为稳定队伍 ID，获胜者包含历史队员，`activeWinners` 仅包含未被最终淘汰者；平局三类获胜字段为空。最终击杀、最终死亡和破床同时使用 `kgc_player_metrics` 的 `final-kills/final-deaths/beds-destroyed` 持久计数，普通死亡、特殊召唤物和断线宽限路径均只在各自唯一事件点写入，不与基础战绩重复。

每次运行阶段死亡在统计、复活/淘汰状态和本地化消息提交后发布不可取消的 `GamePlayerDeathResolvedEvent`，并先于整队淘汰与整局赛果事件。在线事件携带同一份已解析 Bukkit 伤害原因，床虫和梦境守卫额外携带模块来源 ID；重连超时保留受害者/击杀者 UUID、允许在线 Player 与伤害原因为空，并使用 `disconnect` 来源。`finalDeath` 只表示死亡时队伍床已经失效，与床仍存活但宽限到期后永久离场的状态相互独立。

运行阶段的在线死亡与重连超时在状态、击杀统计和经验提交后，先发布不可取消的 `GamePlayerDeathFeedbackEvent`，再按事件结果播放击杀者音效、向正式玩家和观战者广播消息，最后发布上述不可变结果事件。事件复用完整 UUID/可空 Player、双方队伍、Bukkit 原因、模块来源和最终死亡上下文；监听器可替换或以 `null` 抑制 `message`，也可关闭 `playKillerSound`。队伍与归因保持只读，避免显示监听器改写已提交统计；床虫/梦境守卫没有玩家击杀者，运行期断线来源固定为 `disconnect`，倒计时超时仅保留普通提示而不伪造死亡事件。

死亡聊天使用上述分原因攻击者窗口，按参考实现区分无来源/有来源爆炸、自然掉入/被击落虚空、自然摔落/10 秒内被击落高处及投射物击杀，并分别提供普通复活和最终淘汰双语文本；普通近战、环境未知原因以及床虫/梦境守卫继续使用各自既有消息。模块强制虚空 `health=0` 和手动火球伤害在同步致死调用期间携带私有原因标记，调用返回立即移除，避免 Bukkit 残留的上一条伤害原因或后续死亡被误分类。

合法敌方击杀只向击杀者本人播放 `game.sounds.kill`，默认与参考实现一致为 `ENTITY_EXPERIENCE_ORB_PICKUP`；普通 PvP、投射物、爆炸及最近攻击归因统一覆盖，断线宽限到期的有效击杀也会在攻击者在线时补播。该规则支持 `NONE`、音量和音高配置，环境死亡、自杀、友军或无有效归因者不会触发。

地图级 `bedwars.vanilla-death-drops` 与参考默认值一致为 `false`，旧地图回退模块 `game.vanilla-death-drops`。无有效敌方击杀者时只在死亡点保留铁、金、钻石和绿宝石；最后伤害为摔落且玩家或模块召唤物在参考 10 秒击落窗口内造成过有效攻击时，同样只把四类货币留在死亡点，不直送击杀者或投放到基地回收点。床仍存活的其他普通击杀会把四类货币直接放入击杀者背包并清除其他掉落，背包放不下的余量仍落在死亡点。床已毁后的其他敌方击杀显示最终击杀消息并累加最终击杀数，背包中的普通方块、资源和消耗品连同个人末影箱内容投放到受害队 `kill-drops` 回收点；永久装备和武器工具不会成为最终掉落。启用原版掉落开关后跳过上述货币过滤和基地回收，但永久装备仍由模块剔除以避免复活复制。

等待阶段的选队复用 `kgc:join-team <roomId> <teamId>`，不维护模块私有菜单。通用队伍服务负责容量校验和同队重复选择幂等；BedWars session 每 tick 同步实际选择，刷新名牌和计分板并向玩家确认。开始倒计时后选队入口锁定，`onStart()` 再以通用队伍服务中的最终结果覆盖内部状态，随后固定出生点、队色装备和胜负归属。

所有菜单选队、自动补队和开局兜底分配都经过主插件 `GameTeamService.join`，因此会在容量校验后、成员映射写入前触发可取消的 `GamePlayerTeamAssignEvent`。事件取消保持原队伍；同队重复选择不会重复发布。事件只携带 `roomId` 以保持底层服务解耦，外部监听器须同时校验房间玩法和目标队伍。

## 建筑与爆炸

- 只有 `blocks.place-allowed` 中的材料可由存活且非复活中的玩家放置。
- `blocks.breakable-map-blocks` 默认覆盖参考实现允许清理的高草、蕨、海草、甘蔗、双层植物和土径；这些模板方块可被运行阶段存活玩家清除但不会掉落物品，也不会放宽其他地图方块保护。
- `blocks.allow-fire-extinguish` 默认与参考实现一致为 `true`，允许运行阶段存活玩家清除模板火焰且不产生掉落；关闭后火焰继续按普通模板方块保护。
- 托管地图 `bedwars.allow-map-break` 与参考默认值一致为 `false`。开启后，存活玩家可手动破坏未处于出生点、商店或生成器保护区的普通模板方块并获得原版掉落，敌队床仍走专用破床流程；自然燃烧可以改写除床外的地图方块。运行世界来自私有临时副本，关房不会污染模板。
- 放置点必须低于托管游戏 `max-build-y` 或模块默认 `game.max-build-y`。
- 每张托管地图分别支持 `spawn-protection`、`shop-protection`、`upgrades-protection` 和 `generator-protection`，新地图默认分别为参考值 5/1/1/1 格；未配置的旧地图继续回退 `blocks` 中的全局半径，升级商店回退物品商店值。
- 保护区按参考 `Cuboid` 的整数方块边界计算，不再使用球形距离。商店在基础半径外向下扩展 1 格、向上扩展 4 格，生成器中心上移 1.3 格后再向下扩展 2 格、向上扩展 5 格；空队且禁用空队 NPC 时不创建该队两个商店保护区，出生点和生成器仍保持保护。
- 每个放置方块以世界 UUID 和整数坐标记录在当前 session；玩家只能破坏本局记录的方块。
- 普通放置只在事件最终未取消后登记；自动点燃 TNT 也在同一后置路径才替换方块并生成实体。普通破坏、敌床销毁和万圣节蜘蛛网经验同样等待最终成功后提交，后续插件取消时不会提前释放建筑登记、改变床状态或发放奖励。
- 破坏己方床仍只提示并拒绝；若玩家当前脚部方块本身属于床标签，则按参考 `BreakPlace` 行为原地上移 0.5 格，避免取消破坏后继续卡在床碰撞箱内。站在床外的普通误操作不会触发传送。
- 会原地改变方块类型或关键 `BlockData` 的现代右键交互统一按模板破坏规则处理：斧头去皮、刮除铜氧化层或蜂蜡，铲子压路或熄灭营火，锄头耕地，蜂蜜脾给铜块和告示牌打蜡，剪刀雕刻南瓜或采集蜂巢，以及玻璃瓶取蜜均受保护。`allow-map-break: false` 下不能改写地图原生方块，关键点范围始终禁止，只有本局登记方块或显式开放地图破坏时才放行。
- 己方床 viewer 私有全息若使原版 `BlockCanBuildEvent` 判为不可放置，正式玩家仍可在任一床方块正上方搭建防御；其他不可建造位置不会被放宽。
- 实体与方块爆炸默认过滤原始地图、床和未追踪方块，只允许破坏本局玩家建筑；开启 `allow-map-break` 后可同时破坏未受关键点保护的模板方块。遮挡判定按参考实现从爆点周围 `-0.73/0/0.73` 三轴组合发出 27 条射线，以 0.3 格步长采样；至少 22 条遇到有效遮挡才保护目标，避免单条中心射线在斜角或薄墙处过度保护。
- 爆炸普通处理阶段只过滤 Bukkit 方块清单，不提前释放房间建筑或活动蜘蛛网；事件最终未取消后再按最终清单提交释放。其他插件从清单移除的方块和整场被取消的爆炸继续保留登记，避免后续同坐标建筑被误判。
- 玻璃方块本体始终不受爆炸破坏；`blocks.blast-proof-glass-blocks-rays` 默认开启，玻璃会计入 27 条射线的遮挡数量，关闭后仅保留玻璃本体防爆。未开放地图破坏时，射线上的未追踪模板方块同样计为遮挡；开放后不再计入。
- 放置 TNT 可按配置立即转换为带玩家来源的点燃实体，关闭房间时统一清理。
- `blocks.tnt-fuse-ticks` 默认与参考实现一致为 45 tick；该值只影响新生成或缺少字段的配置，已有显式自定义值不会被迁移覆盖。
- `specials.tnt` 与参考默认值一致，分别以 1/5/10 点覆盖自伤、队友伤害和敌方伤害；值设为 `-1` 时保留 Bukkit 原始伤害。TNT 不走普通同队免伤，自爆时使用参考项目的重心、强度衰减和 Y 轴衰减公式覆盖玩家速度，保留经典 TNT 跳跃；敌方伤害继续参与击杀归因、隐身解除和复活保护解除。
- `specials.tnt.spoil-carriers` 默认与参考 `spoil-tnt-players` 一致为 `true`。运行阶段携带至少一个 TNT 且未隐身的有效参赛者会在头顶 2.6 格处每 tick 产生一个红色 `DUST` 标记；携带者本人看不到，当前房间其他参赛者和观战者可见。实现每 tick 从最多 16 名正式玩家的当前背包直接推导，不维护参考项目的跨房间静态玩家链表，丢弃、放置、死亡和换容器后无需额外清理事件。
- 水桶倒水使用 Bukkit 实际受影响方块执行建筑高度和关键点保护校验；校验阶段不提前修改房间状态，只有事件经过其他插件且最终未取消时，才在 `MONITOR` 路径把原始方块写入 `RoomResourceScope` 与玩家建筑集合，并按参考时序在 3 tick 后移除生成的空桶。取水只允许回收本局登记的水源，也只在最终成功后释放登记；地图模板原生液体不可被带走，后续监听器取消倒水或取水不会造成虚假水源、错误放行或空桶误删。

## 资源与阶段

铁和金生成器使用托管地图中的 `interval-ticks`，数量与附近资源堆积上限来自模块配置。钻石和绿宝石在一阶使用地图间隔，二、三阶使用 `generators.<type>.tiers` 的开始时间、间隔、数量和上限。

生成物是当前房间世界中的真实掉落物，拾取延迟为零；以生成点为中心的 3 格立方范围内，同材料掉落实体数量达到上限时跳过本次生成。每种公共资源升级只广播一次，不会按每个生成点重复广播。最后一个三级生成器事件完成后，`countdowns.beds-destroy` 开始计时，到期会移除所有床并关闭全队复活能力。

活动且非 AFK 的玩家拾取带 `kgc_bedwars_resource` 标签的独立地面资源前，会触发可取消的 `GameResourceCollectEvent`。取消后底层拾取停止，MONITOR 清理因原事件已取消而不会释放仍存在的房间实体；普通死亡掉落、玩家丢弃物和基地回收物不触发。`team-split` 直接发入附近玩家背包的完整产量与参考语义一致，也不触发地面拾取事件。

钻石或绿宝石资源类型首次进入更高等级并写入 `announcedGeneratorTiers` 后，会发布不可取消的 `GameResourceTierChangedEvent`。`resourceId` 使用小写 `diamond/emerald`，事件包含前后等级、配置绝对秒数和实际对局秒数；同类多个公共生成点只由第一个完成状态切换的点触发全房间单次通知，后续点只同步自身生成状态。

主事件时间线按参考实现连续推进：最后一个钻石或绿宝石三级升级完成后等待 `countdowns.beds-destroy`（默认 360 秒），再等待 `dragon-spawn`（600 秒）进入殊死决战，最后等待 `game-end`（120 秒）强制平局结算。参考默认生成器阶段下对应开局后 1800、2400、2520 秒；Sidebar 仍使用计算后的绝对截止时间与生成器升级共同选择最近事件。已有配置若未配置新键且仍包含 `game.beds-destroy-seconds`、`game.sudden-death-seconds` 或 `game.duration-seconds`，会继续按旧版绝对时间读取且不会自动写入新键，避免升级后改变现服对局长度；新配置只生成连续倒计时键。

Sidebar 与 `GameTimelineStageChangedEvent` 共用 `BedWarsTimelineEntry` 和同一个最早绝对截止时间选择器。进入 `RUNNING` 首次确定下一事件时发布 `previousStageId=null`，每个边界提交后只在稳定 ID 变化时发布一次，最终 `game-end` 到点时发布 `nextStageId/nextStageAtSeconds=null`。稳定 ID 为 `diamond-tier-2/3`、`emerald-tier-2/3`、`beds-destroy`、`sudden-death` 和 `game-end`，倒计时取消、重新开始和关房都会清理旧跟踪状态。

结算后的 `RESULT` 阶段使用参考 `countdowns.game-restart`，默认保留胜负标题、前三击杀榜和观战画面 45 秒；随后进入 `CLOSING`，由 `game.close-delay-seconds` 默认再等待 5 秒并调用主插件 `closeRoom`，对应参考任务额外预留的实体、生成器和世界清理窗口。已有配置若未设置新键但包含 `game.result-display-seconds`，继续使用旧结果展示时长且不会自动写入 45 秒键；新配置不再生成旧键。房间提前无人时仍由主插件立即关闭，不空跑完整重启倒计时。

进入 `RESULT` 的同一 tick 会关闭全部参赛者和观战者仍打开的商店或容器，清空尚存活获胜者的战斗背包，并移除运行世界中的全部地面物品。已登记的资源、死亡回收物和断线掉落同时从 Session 与 `RoomResourceScope` 释放，之后非运行阶段物品生成过滤会阻止重新落地；玩家进入房间前的真实背包仍由最终快照恢复，不受结算清场影响。

每张托管地图的 `bedwars.game-end.show-eliminated` 与 `teleport-eliminated` 均参考默认开启。结算时历史获胜成员仍用于胜负记录和胜利标题，但只有尚未最终淘汰的在线获胜者保留在场内并设为无敌；淘汰参赛者在开启显示时清除通用淘汰标记，临时切为可飞行、无敌的 `ADVENTURE` 并恢复队伍名牌，因此能被获胜者看见。传送开关开启时，淘汰参赛者和外部观战者会移动到随机在线获胜者上方并反向观看；平局或无在线获胜者时安全回退地图观战点。关闭显示时保持原版 `SPECTATOR`，两项状态最终都由 `closeRoom` 和玩家快照恢复。

`generators.stack-items` 与参考默认值一致为 `false`。关闭时每个资源生成一个独立实体，并通过实体 scoreboard tag 阻止它与生成器资源或玩家普通掉落物自然合并；开启时一次产量保留为单个物品堆。标签只存在于实体，不写入 `ItemStack` 元数据，因此玩家拾取后不会得到带自定义名称或内部标记的货币。队伍分摊及三、四阶锻炉绿宝石的背包溢出物复用相同生成路径。

生成器资源落地后立即清除 Bukkit 随机初速度，与参考实现一样固定留在配置点。资源被完整拾取、自然消失或允许自然合并时，会同步从 Session 和 `RoomResourceScope` 解除已结束实体；部分拾取仍保留剩余实体追踪，合并则把房间追踪和生成器标签转移到最终保留实体，避免长局持续积累无效 UUID 或在区块重载时误删有效资源。

运行阶段按房间独立维护 AFK 计时，`game.afk-seconds` 默认 45 秒，与参考阈值一致；设为 `0` 可关闭。只有在线、未淘汰、非复活中的有效参赛者累计，任意移动事件（包括视角变化）、方块/物品交互或聊天会立即清零并解除 AFK。AFK 玩家仍留在对局且不会自动死亡或踢出，但无法拾取带房间标签的生成器资源，从而阻止挂机占用生成器；玩家丢弃物和死亡回收物不受 AFK 规则扩张影响。恢复活动后无需等待即可重新拾取。加入、主动离开、断线、重连、新局初始化和房间关闭都会清理对应私有状态，不会跨房或跨局残留。

AFK 集合首次达到阈值或由玩家活动真实移除时，会发布不可取消的 `GamePlayerAfkStateChangedEvent`，分别携带 `afk=true/false` 和当次空闲秒数；阈值后的每秒 tick 不重复发布。离房、断线、新局和关房属于身份生命周期清理，不伪造“恢复活动”事件。

`levels` 默认开启，并对齐参考奖励：有效在线参赛者每完整运行分钟 10 XP，胜利 100、破床 15、普通击杀 10、最终击杀 15，每个历史队伍成员按参考完整队伍人数乘以 5 发放队友奖励。普通在线死亡与重连超时归因击杀共用唯一奖励点；胜利和队友奖励位于 `resultRecorded` 防重后的整局结算入口，平局仍有队友奖励但没有胜利奖励。全部数值可设为 0 单独关闭。

经验只持久化为 `kgc_player_metrics` 中的累计 `level-experience`，等级由 `rankup-costs: [1000, 2000, 3000, 3500]` 和之后每级 `default-rankup-cost: 5000` 派生，因此不会出现等级与当前 XP 分步保存后的不一致。离线历史成员仍按 UUID 结算；一次大额奖励可连续跨越多级，计算在显式曲线后用除法处理，不会随高等级线性循环。

持久化完成后先在跨级时发布不可取消的 `GamePlayerLevelUpEvent`，再发布 `GamePlayerExperienceGainedEvent`；两者携带来源、累计值、最终等级和级内进度，Player 允许为空。在线玩家收到双语来源反馈，Sidebar 在等级系统开启时显示 `等级（当前/下一阈值）`；关闭 `levels.enabled` 后不写经验、不发事件且隐藏该行。

`money-rewards` 独立对齐参考 Vault 奖励默认值：每完整运行分钟 5、多人队地图的团队支持 30、胜利 90、破床 60、普通击杀 10、最终击杀 40。每分钟只奖励仍可行动的在线参赛者；胜利和团队支持位于 `resultRecorded` 防重后的唯一结算入口，团队支持按地图是否存在容量大于 1 的队伍判断并固定发放一次，不按实际队员数相乘；断线超时归因仅在击杀者仍在线时奖励。任一值设为 `0` 可单独关闭。存款通过可选 Vault Economy 的 `depositPlayer` 执行，只有 `transactionSuccess()` 明确成功才发送双语反馈；缺 Vault、缺经济提供者或事务失败时静默跳过，不影响胜负、统计和 XP。

`generators.holograms.enabled` 默认开启。公共钻石和绿宝石点会显示与参考实现一致的等级、资源类型和实际剩余生成秒数，并在下方旋转对应资源方块；队伍铁/金锻炉不生成公共全息。阶段升级会刷新罗马数字等级，所有显示实体登记到当前房间资源作用域，重新准备或关闭房间时统一移除。

`performance-settings.rotate-generators` 与参考默认值一致为 `true`，控制公共生成器资源方块是否每 tick 更新头部姿态。关闭时等级、类型、生成倒计时和静态资源方块仍保留，仅停止旋转计算与实体元数据更新；生成周期、掉落实体和队伍锻炉不受影响，适合高并发多房间服务器。

公共资源升阶除单次聊天广播外，还向参赛者和观战者播放参考默认音效：钻石使用 `ENTITY_PLAYER_LEVELUP`，绿宝石使用 `ENTITY_GHAST_WARN`。`generators.sounds.<type>-upgrade` 可分别调整 `sound`、`volume` 和 `pitch`，将 `sound` 设为 `NONE` 可关闭该类音效；非法名称安全回退默认值。

`generators.team-split.enabled` 与参考默认值一致为 `true`，范围 `radius` 默认为 1 格。队伍生成器同一时刻附近至少有两名有效参赛者时，每人直接获得完整本次产量并播放拾取音；恰有一名存活成员的队伍、关闭开关或公共生成器继续生成地面资源。三、四阶锻炉产生的绿宝石复用相同分摊规则；背包溢出物在玩家脚下生成并登记到房间资源作用域，原有生成器堆积上限仍先于分摊生效。

## 商店与永久装备

每个队伍配置的 `shop` 和 `upgrade-shop` 点会在倒计时开始时生成无 AI、无碰撞且不可受伤的村民。NPC、资源掉落物和 TNT 都由当前 session 跟踪并在关房时清理。

地图级 `bedwars.disable-npcs-for-empty-teams` 与参考默认值一致为 `true`，旧地图回退模块 `game.disable-empty-team-npcs`：开局没有任何参赛成员的配置队伍不会生成物品商店和升级商店；曾有成员的队伍后续被淘汰时不即时移除 NPC。该规则与空队生成器开关相互独立。

`shop.holograms.enabled` 默认开启。商店村民上方显示与参考实现一致的两行“商店类型 / 右键点击”全息，并按队伍容量区分单挑商店、单挑升级、队伍商店和队伍升级；关闭后回退为村民单行名称。村民和全息都属于当前房间资源作用域，重复准备或关闭房间时会显式解除登记并移除。

活动玩家点击本房间真实商店村民、默认箱子菜单打开前，会触发可取消的 `GameShopOpenEvent`。物品与升级商店稳定 ID 分别为 `item`、`upgrade`，事件同时提供玩家队伍和 NPC；取消后可由监听器接管界面，原版村民交互仍会被模块拦截。普通 `PlayerInteractEntityEvent` 和带命中坐标的 `PlayerInteractAtEntityEvent` 共用同一入口，避免客户端发送 `INTERACT_AT` 时遗漏商店或展示框保护。翻页、全部商品/快捷购买页签、选槽和菜单刷新都不重复发布打开事件。

物品商店使用 `ChestMenuService` 与模块动态数据源 `bedwars:shop_items`。商品来自 `shop.items`，支持：

普通商品和队伍升级都会在资格与余额检查通过后、实际扣款前触发主插件 `GamePurchaseEvent`。外部监听器取消事件时不会扣款；设置 `handled = true` 时仍正常扣款并发送成功反馈，但跳过模块默认发放或升级行为。事件返回后会再次检查并扣除货币，避免监听器同步修改背包产生免费购买；还会确认玩家仍属于当前 Session、沿用同一状态对象且仍是活动参赛者，监听器同步离房、淘汰或关房时不会继续扣款和发货。点击处理结束后只刷新玩家当前仍打开的原商店 Holder，监听器主动关闭商店或切换自定义界面时不会渲染过期菜单。核心箱子菜单会先取消所有 Holder 点击，BedWars 随后只对匹配当前房间菜单 ID 的点击执行专用购买、导航和快捷偏好逻辑；确认处理后按事件对象身份记录，并在 MONITOR 保持取消，因此高优先级监听器误放行时不会把菜单图标移动进背包或在单次购买外产生第二份物品。

活动参赛者持物进行主手或副手的左/右键空气、方块交互时，会在默认特殊商品逻辑前触发主插件 `GameItemUseEvent`。模块生成的 `SPECIAL` 商品把商品 ID 作为 `itemId`，其他物品允许为空并可由外部监听器检查自己的 PDC；取消或设置 `handled = true` 都会阻止模块与原版继续处理。接管监听器负责行为、反馈和对应手的物品消耗，未接管时现有火球、桥蛋、召唤物和魔法牛奶语义不变。模块按 Bukkit 事件对象身份记录事件取消、外部接管或默认特殊商品执行，并在 MONITOR 重申取消；后续高优先级监听器误解除取消时，蛋、雪球、火焰弹等材料不会在模块行为之后再产生第二次原版投射或方块交互，普通未接管物品不受影响。

火球、桥蛋和床虫雪球完成 Bukkit 实体生成及基础属性配置后，会在默认物品消耗、冷却和房间追踪前发布可取消的 `GameProjectileLaunchedEvent`，稳定来源分别为 `fireball/bridge-egg/bed-bug`。取消后实体立即移除，物品不会消耗，火球也不会进入冷却；不取消时监听器可以直接调整事件中的实际投射物。

物品、永久装备、队伍升级和陷阱购买成功时，只向购买者播放 `shop.sounds.bought`，默认与参考实现一致为 `ENTITY_VILLAGER_YES`；资源不足、重复购买、越阶购买或陷阱队列已满时播放 `shop.sounds.insufficient`，默认为 `ENTITY_VILLAGER_NO`。两类规则均支持 `NONE`、音量和音高配置，成功消息与全队升级广播不受音效开关影响。

余额不足的实际点击反馈与参考 `CategoryContent/MenuUpgrade` 一致，显示当前价格减去背包余额后的缺口数量和本地化货币名；菜单 lore 继续使用简短“资源不足”状态。队伍升级成功广播中的主体是实际购买者玩家名，而不是其队伍显示名；商品 ID、扣款、事件和全队效果应用顺序不变。

参考 `CategoryContent.content-settings.weight` 的通用分类门槛通过商品 `category/category-id` 与 `weight/category-weight` 映射。玩家在同一分类买过较高权重后，较低权重商品会保持锁定且不扣款；等权重、更高权重和其他分类不受影响。门槛属于整局玩家状态，普通死亡和宽限重连不会清除，只在新对局初始化时复位；未配置分类的旧商品保持原行为。内置三阶护甲显式使用 `armor` 分类和 `1/2/3` 权重，同时继续由 `armorTier` 负责穿戴与复活恢复。

商品或升级的 `currency` 除 Bukkit 材料名外也接受 `vault/economy`，内部使用 `Material.AIR` 作为 `GamePurchaseEvent.currency` 的兼容标记。菜单余额按参考普通商店语义向下取整；模块通过 Bukkit 服务注册表反射调用可选 Vault Economy，不增加运行时硬依赖。未安装 Vault、没有经济提供者或扣款响应失败时拒绝购买并显示经济服务不可用，不会发放免费商品；事件返回后仍重新查询余额并执行 Economy 扣款。

购买永久护甲并完成自动穿戴时，购买者额外收到 `shop.sounds.auto-equip`（默认 `ITEM_ARMOR_EQUIP_GENERIC`）；任一队伍陷阱触发时，守方全部在线成员收到 `shop.sounds.trap-trigger`（默认 `ENTITY_ENDERMAN_TELEPORT`）。两者均不向入侵者或观战者误播，并支持 `NONE`、音量和音高配置。

- 普通方块、TNT 和非永久武器，按铁、金或绿宝石扣费。
- 商品发放沿用参考 `colourItem`：任意颜色的床、羊毛、玻璃、染色玻璃板和陶瓦都会转换为购买者队色，顶层商品、`buy-items`、药水和特殊商品共用同一入口；放置白名单按材质族接受重染后的变体。现代参考映射为 `GREEN→LIME`、`AQUA→LIGHT_BLUE`、`GRAY→LIGHT_GRAY`，同时修正对应羊毛和绿色皮甲颜色。
- 永久护甲、四阶镐、四阶斧和剪刀；永久物品默认不可丢弃、不可通过光标/Shift 点击/数字键/副手交换/拖拽存入外部容器，且不会成为死亡掉落。出生默认剑是参考语义的唯一丢弃例外：丢弃事件移除目标物后，背包仍有同级或更强剑才允许落地；无替代品或只有较弱剑时继续拦截。从容器取回异常遗留永久物品仍被允许。对局中的四个护甲槽始终禁止普通点击、数字键交换和拖拽覆盖；现代右键装备交换与发射器自动穿戴事件也会取消，因此活动玩家不能取下或替换模块自动穿戴的队色护甲。
- 出生、复活和重连均装备完整四件队色护甲；头盔和胸甲固定为队色皮甲，商店护甲只升级护腿与靴子材质。队伍保护强化覆盖四个护甲槽，并与隐身时的四槽 viewer 私有隐藏保持一致。
- 与参考数据模型一致，“不可损坏”和“永久”是独立属性：购买的石/铁/钻石剑不会消耗耐久，但仍可主动丢弃并在死亡后失去；出生木剑、护甲、工具和剪刀额外携带模块 `bedwars_permanent` PDC 标记，永久保护识别该标记并为同时带 `bedwars_default_item` 的出生剑应用上述条件例外。默认物品组还写入独立 `bedwars_default_item` PDC；购买顶层或 `buy-items` 剑时只移除伤害等级不高于新剑的出生默认剑，不再误删玩家已购买、命令发放或其他自定义低阶剑。拾取任意地面剑只在事件最终未取消、且玩家仍属于当前 Session 并可活动时移除出生默认剑；后置取消或同步离房不会让玩家在没有获得新剑时丢失出生剑。丢弃最后一把非永久剑也只在最终成功后检查并恢复出生剑，后置取消不会因原剑回到背包而产生额外默认剑。把最后一把普通剑移入箱子后关闭库存时同样从当前地图物品组恢复首个出生剑；两条恢复路径都复用配置数量、名称、默认/永久标记及队伍锋利强化，而不是硬编码木剑。
- 镐和斧死亡后降一级，护甲与剪刀保持；复活时重新发放当前永久等级。
- 默认工具附魔与参考商店一致：镐效率为 `0/II/III/III`，金镐额外锋利 II；斧效率为 `I/I/II/III`。对应四阶列表位于 `shop.tools.pickaxe-efficiency-levels`、`pickaxe-sharpness-levels` 和 `axe-efficiency-levels`，购买、复活、降级及重连均使用同一映射。
- 队伍锋利强化按参考 `BuyItem` 语义覆盖剑和斧，不覆盖镐。升级购买会更新现有武器，新购买、复活和重连重发的任意阶斧也会读取当前队伍锋利；金镐仍只保留其商品自带锋利 II。

内置方块分类与参考 `ShopManager` 的 7 项默认内容一致：16 羊毛/4 铁、16 橙色陶瓦/12 铁、4 防爆玻璃/12 铁、16 末地石/24 铁、16 梯子/4 铁、16 木板/4 金和 4 黑曜石/4 绿宝石。陶瓦同步加入新配置的放置白名单；`ensureDefaults()` 只在整个 `shop.items` 缺失时写入这套列表，已有管理员列表不会因升级被追加、重排或覆盖。

配置商品支持参考 `BuyItem` 的通用扩展字段：`enabled` 可保留但临时隐藏活动商品，`item-name` 设置发到背包中的物品名称，`unbreakable` 设置不可损坏，`enchantments` 接受 `{ KNOCKBACK: 2 }` 映射或 `KNOCKBACK 2, FIRE_ASPECT 1` 字符串。字段应用于 `ITEM`、`POTION` 和 `SPECIAL` 的最终物品；附魔名称按 Bukkit `minecraft` 命名空间解析，非法名称会被安全忽略。

参考 `ContentTier.tier-item` 的预览元数据与实际发货字段分离：`icon-amount/tier-item-amount` 控制菜单堆叠数，`icon-enchanted/enchanted` 控制隐藏附魔 lore 的光效，`potion-display` 接受 `minecraft:` NBT 名称及 `speed/swiftness`、`jump/leaping` 等旧新别名，`icon-potion-color` 控制预览瓶的 24 位颜色；没有独立颜色时复用商品 `potion-color`。全部商品和快捷购买页共用同一预览模型，而购买后的数量、附魔、效果和颜色仍只读取顶层或 `buy-items` 发货字段。为此主插件 `ChestMenuItemBuilder` 已原生支持 `enchanted/potion-display/potion-color`，其他模块动态菜单也可复用。

商品 `display-lore/item-lore/lore` 接受 YAML 列表或多行字符串；存在时按管理员声明顺序完整接管通用 Lore，并支持参考 `{tier}/{color}/{cost}/{currency}/{buy_status}/{quick_buy}` 六类动态占位符。等级 `1..10` 转为 `I..X`，其他值保留十进制；价格和货币按铁白、金金、钻石水绿、绿宝石/Vault 深绿着色并使用模块本地化资源名；购买状态实时反映余额、拥有、越阶和陷阱容量。`{quick_buy}` 在全部/快捷/选槽页面分别使用对应操作提示。没有自定义 Lore 的旧商品继续显示通用价格、状态和操作提示；快捷移除双语文案已同步说明右键与 Shift 点击。

菜单名称保留 `&`/`§` 样式及 `{color}/{tier}` 动态显示；购买成功和队伍升级广播则按参考反馈语义移除颜色与菜单专用 token，再通过纯文本商品名插入语言消息，避免控制码或花括号泄漏。快捷分配反馈会从真实配置条目解析名称并保留当前罗马等级，自定义商品不再回退原始 ID。重复购买、越阶、资源不足、Vault 不可用和快捷增删反馈统一通过 Legacy 组件解析，语言中的 `&`/`§` 颜色不会作为字面字符发送。

商品可显式配置参考 `ContentTier.buy-items` 的命名映射或 YAML 列表；支付一次后按声明顺序发放全部有效子项，子项各自支持 `material/amount/name/enchants/potion/potion-color/auto-equip/unbreakable`。存在 `buy-items` 时顶层 `item` 只保留为图标回退而不重复发放；无该节点的既有扁平商品保持原路径。顶层及子项 `name/item-name` 与参考 `BuyItem` 一致先应用样式重置，再把 `&` 或 `§` 旧式颜色转换为 Adventure 显示名，避免继承前一组件样式。商品级 `permanent/is-permanent` 与 `unbreakable` 继承到所有子项，固定护甲、镐、斧和剪刀还会按当前等级在复活时解析同一组子项，工具降级后自动选择降级等级配置。镐和斧接受参考 `is-downgradable` 及扁平别名 `downgradable`：默认经典工具为 `true`，死亡时只有二阶以上降低一级，一阶保底工具继续保留；显式设为 `false` 时当前阶保持不变。顶层商品同时接受参考字段 `material/name/enchants`，并继续兼容既有 `item/item-name/enchantments`。

`auto-equip` 可让通用 `ITEM` 护甲按实际头盔、胸甲/鞘翅、护腿或靴子材质进入对应槽位，并应用皮甲队色、当前团队保护和自动装备音效；非护甲材质安全回退背包。`permanent` 与兼容别名 `is-permanent` 为 `ITEM/POTION/SPECIAL` 启用参考永久生命周期：成功购买先登记商品 ID 并阻止重复购买，成品写入独立永久 PDC 且不可损坏，死亡不掉落，出生、复活和重连从当前商品配置重建。永久商品的 `buy-cmds` 与参考 `ShopCache.manageDeath()` 一致会在重建时重放，但不会重复购买音效和成功消息；命令型永久商品即使没有 `item` 也会重放命令。若升级后商品已从有效配置移除则安全跳过，玩家状态仍只保留稳定 ID。固定 `ARMOR/PICKAXE/AXE/SHEARS` 继续使用既有等级、降级和重发字段，不进入自定义 ID 集合，避免双份装备；`GamePurchaseEvent` 取消或 `handled = true` 均不会登记自定义永久商品。

`POTION` 商品支持参考 `potion` 与 `potion-color`：效果使用逗号分隔的 `效果 秒数 Bukkit amplifier`，少于三段时按参考回退 50 秒和 amplifier 1；名称通过现代 MOB_EFFECT 注册表解析，并兼容 `JUMP/SLOW/FAST_DIGGING/SLOW_DIGGING/INCREASE_DAMAGE/HEAL/HARM/CONFUSION/DAMAGE_RESISTANCE` 旧别名。amplifier 是 Bukkit 从 0 开始的原始值，配置 `1` 表示 II 级。颜色接受十进制、`0xRRGGBB` 或 `#RRGGBB`，限制为 24 位并写入 `PotionMeta`；成品明确使用 water 基础药水。三个内置药水已声明为 `SPEED 45 1`、`JUMP 45 4`、`INVISIBILITY 30 0`，因此新配置由字段驱动；旧管理员文件没有 `potion` 时仍按商品 ID 和 `specials.potions` 时长回退，不改变既有 II/V/I 行为。自定义效果继续携带模块药水 PDC，只有消费事件最终未取消时才按参考在 5 tick 后清理生成的空瓶；后置取消不会误删背包中原有的玻璃瓶，隐身外观检测保持原路径。

商品还支持参考 `BuyCommand` 的嵌套 `buy-cmds.as-player/as-console` 字符串列表。正常顺序为余额校验、`GamePurchaseEvent`、扣款、默认物品/永久状态发放、玩家命令、控制台命令、成功音效与消息；事件取消不扣款，`handled = true` 扣款但跳过物品和两类命令。玩家命令自动去除配置中的 `/` 后再以 `/` 进入玩家聊天命令链，因此仍受 `game.allowed-commands` 和其他预处理监听器约束；控制台命令通过 Bukkit 控制台发送者执行。两类命令支持 `{player}`、`{player_uuid}`、`{team}`、`{team_display}`、`{team_color}`、`{arena}`、`{arena_world}`、`{arena_display}`、`{arena_group}`；竞技场分别映射托管游戏 local ID、运行世界、显示名和选择器分组。命令配置只来自管理员模块文件。仅命令商品可省略 `item` 并保留 `icon/type`，此时不会发放图标物品；已有商品同时配置 `item` 和命令时两者都会执行。

非陷阱队伍升级支持参考 `receive` 列表中的 `command:模式,命令` 动作，模式不区分大小写并兼容连字符或下划线：`once-as-console` 单次以控制台执行，`foreach-member-as-console` 为每名仍有效的在线队员以控制台执行，`foreach-member-as-player` 让每名队员进入玩家聊天命令链。先展开 `{buyer}`、`{buyer_uuid}` 及与商品命令相同的七项队伍/竞技场 token，再在逐成员模式展开 `{player}/{player_uuid}`；命令正文首个分隔逗号后的其余逗号会保留。执行顺序为购买事件、二次扣款、升级状态和内置效果、购买音效、命令动作、升级广播；取消或 `handled = true` 不执行命令，后者仍保留成功音效与广播。陷阱继续使用触发时动作，不把升级购买命令错误提前到入队时执行。

同一有序 `receive` 列表还支持参考四类内置动作：`enchant-item:附魔,等级,sword|armor|bow` 把附魔保存到队伍并立即刷新现有物品，后续购买、复活和工具降级重建继续继承；`player-effect:效果,等级,秒数,team|base` 支持永久时长 `0`、有限时长、全队复活恢复及己方基地进出应用/移除；`generator-edit:iron|gold|emerald,间隔秒,数量,地面上限` 精确覆盖队伍生成器参数，首次绿宝石动作会在没有专用点时复用队伍主生成点；`dragon:数量` 设置该队殊死决战精确龙数。旧 Bukkit 附魔和药水名称通过现代注册表别名解析。动作与命令严格按声明顺序位于购买音效和升级广播之间，`GamePurchaseEvent` 取消或接管时全部跳过。

陷阱商品的 `receive` 使用独立触发生命周期：购买时把商品 ID、固定类型和动作快照按顺序加入队列，敌人首次进入有床守方基地时才消费队首并执行。支持 `player-effect:效果,等级,秒数,enemy|enemies|team|base`、`remove-effect:效果` 和 `disenchant-item:附魔,sword|armor|bow`；动作依次作用于入侵者、守方在线成员或基地内守方，移除隐身会同步恢复客户端护甲与名牌。至少一个有效动作时整组替代固定陷阱效果，避免双重施加；未配置或全部非法时继续使用现有失明、反攻、警报、挖掘疲劳逻辑。购买事件被取消或接管不会入队，队列价格递增和容量保持原契约。

`seasonal.halloween.enabled` 默认开启，并兼容参考 `enable-halloween-feature` 旧键；实际活动严格使用参考 Europe/Rome 时区的 10 月 22 日至 11 月 1 日窗口。窗口内即使默认 `halloween-pumpkin` 保持 `enabled: false`，物品商店仍自动加入参考 12 个南瓜 / 4 铁商品；旧管理员商品列表完全缺失该项时使用相同内置回退，显式启用的自定义商品在窗口外仍按普通商品处理。

活动房间的正式加入和重连玩家会在 20 tick 后听到参考洞穴环境音；每名玩家只保留最后一个待执行任务，回调前离房、断线或被新重连任务替代均不误播。房间内通过 `CUSTOM` 原因生成且可装备的生物会获得南瓜头，不影响其他小游戏世界。有效玩家击杀会先在受害者头部空气位置播放恶魂音效，再在非关键保护区生成纳入房间方块作用域的蜘蛛网；蜘蛛网 150 tick 后自然破坏，提前由有效参赛者打破时不掉落并通过统一等级事件获得固定 5 经验，爆炸移除后不会把同坐标后续建筑误判为活动蜘蛛网。

参考 `AutoscaleListener` 与 `ServerPingListener` 只在 BUNGEE 专服分支注册；KaGameCenter 是共享多玩法、多临时房间模型，按需创建和 Velocity 摘要由核心负责，因此 BedWars 模块不会用首个竞技场覆盖整服 MOTD、人数上限或复制静态竞技场对象。

全部商品菜单每页提供 28 个动态槽位，支持模块配置扩充商品和翻页。商品显示名优先读取模块语言，未知自定义商品回退到配置显示名。

快捷购买提供 21 个固定槽位，默认内容来自 `shop.quick-buy-defaults`，其中 `_` 表示保留空槽。参考默认布局会留空第一排全部 7 槽和第二排第 4 槽，其余 13 个商品按原始 raw slot `19..25`、`28..34` 映射到后两排。玩家在全部商品页 Shift 点击商品后选择快捷槽；快捷页左键购买，右键或参考 `MOVE_TO_OTHER_INVENTORY` 的 Shift 点击移除。进入选槽模式后分配判断优先，因此点击同一位置不会被移除分支误拦截。个人槽位立即写入模块私有 `quick-buy.yml`，不占用主插件战绩表；同一逻辑商品移动到新槽时会自动清除旧槽。已有模块配置和个人偏好不会被默认列表覆盖。

快捷槽保存任一镐或斧商品后，会按参考多阶 `CategoryContent` 语义动态显示当前等级的下一阶，而不是固定停在保存时的材料。全部商品页也把每类工具折叠为一个槽，并复用同一下一阶/满级解析；普通商品和三阶独立护甲仍按原始条目显示。每类工具的所有阶级 ID 都映射到按 `tier/id` 排序的最低阶稳定 ID；读取旧 `quick-buy.yml` 时按规范 ID 保留首个槽并隐藏重复阶级，下一次选槽或移除时写回清理后的 21 槽列表。购买成功刷新菜单后两页立即切换到后续阶级；满级时保留最高阶并显示已拥有。

队伍升级菜单按参考 `MenuUpgrade` 以 `BedWarsUpgradeType` 为多阶身份：保护、急迫、锻炉等非陷阱强化各占一个槽，按 `tier/id` 稳定排序显示当前下一阶，满级后保留最后阶并显示已拥有。四种陷阱对应独立 `MenuBaseTrap`，不会按共同的 trap 标记合并，在 `MenuCategory` 陷阱子页分别显示并按各自动态或固定价格模式结算。升级条目支持 `icon-amount/icon-enchanted`，也可直接读取参考嵌套 `display-item.material/amount/enchanted`；`display-lore/item-lore/lore` 复用商品通用 token，并新增 `{tier_n_cost}/{tier_n_currency}/{tier_n_color}`，按序号或实际 tier 显示各阶价格、本地化货币和已解锁绿色/未解锁灰色。购买后的菜单刷新复用同一解析，因此下一阶、逐阶状态、满级、队列容量和动态价格立即同步，预览字段不参与实际强化动作。

升级菜单底部按参考 `MenuTrapSlot` 独立显示当前队伍的只读陷阱队列：槽位数量跟随 `shop.max-queued-traps`，最多 16 个并按行居中；已占用槽使用实际陷阱图标、光效、名称和自定义说明，数量标识触发顺序，空槽显示无陷阱状态、入队说明以及当前队列长度下所有可购陷阱的下一价格。购买后同一 Holder 会同时刷新商品区和队列区。核心箱子菜单新增 `paginate: false` 动态源模式，使队列不参与升级商品翻页，也不会把当前商品页重置为第一页。

升级主菜单按参考 `category-traps` 只显示一个“购买陷阱”入口，默认图标为 `LEATHER`，可通过 `shop.trap-category.icon/amount/enchanted` 调整；名称、Lore 和子页标题从模块语言读取。入口打开独立陷阱子页，返回按钮回到升级与队列主菜单，超过 14 个自定义陷阱时使用子页翻页；队列已满时入口追加满队列状态并拒绝打开。陷阱完成扣款后无论使用模块默认入队还是由 `GamePurchaseEvent.handled` 接管，都按参考返回主菜单；购买取消、余额不足或上下文失效则保留当前子页，不制造成功导航。

升级主菜单在购买区和队列区之间按参考 `MenuSeparator separator-glass` 显示整行玻璃，默认名称为“⬆可购买”，Lore 指向“⬇陷阱队列”；图标、数量和光效可由 `shop.upgrade-separator.icon/amount/enchanted` 配置，文本继续使用双语资源。默认 `on-click.player/console` 为空，因此仍是只读装饰；配置后支持模块节点以及参考根级 `separator-glass.on-click.player/console`，同时兼容 `as-player/as-console` 别名，合并后按声明顺序去重。有效参赛者点击任一分隔槽时以对应身份依次执行命令，展开 `{playername}` 原始名、`{player}` Legacy 显示名和 `{team}` 队伍显示名；其他菜单槽不会误触发。`shop.max-queued-traps` 为 1–14 时布局始终保留该分隔行并动态压缩购买区行数；扩展到 15–16 槽时，六行菜单容量不足以同时容纳购买入口、三行完整队列和分隔行，因此只隐藏装饰分隔条，优先保留全部可交互内容。

陷阱定价同时兼容模块既有字段和参考 `MenuBaseTrap`：既有 `price` 在未声明模式时继续默认随队列按 `shop.trap-price-increment` 递增，避免旧外部配置升级后静默变成固定价；可用 `dynamic-price: false`（别名 `price-scales: false`）显式固定。参考字段 `cost: 0` 自动读取 `shop.trap-start-price` 和缺省 `shop.trap-currency` 后递增，正数 `cost` 自动映射为固定价格；显式商品 `currency` 始终优先。菜单价格、余额状态、空队列槽价格汇总、事件金额和最终扣款全部调用同一价格函数，不会出现预览与结算分叉。

`shop.group-settings.<selector-group>` 可按托管玩法现有 `selector-group` 覆盖 `max-queued-traps/trap-start-price/trap-price-increment/trap-currency`；同时兼容参考根级 `<group>-upgrades-settings` 的 `trap-queue-limit/trap-start-price/trap-increment-price/trap-currency`。存在参考 `default-upgrades-settings` 时它覆盖模块基线默认，同组模块节点再优先于参考组节点，缺项逐字段回退。分组容量参与主菜单布局、队列槽数量、分类入口和最终购买资格；分组起价、增量和缺省货币只作用于继承这些设置的动态陷阱，显式正数成本或货币不被覆盖。当前 Session 使用创建时模块配置快照，重载只影响后续房间，与其他准备阶段规则一致。

`shop.upgrade-menu-content` 复制参考默认 `menu-content` 组件列表；`shop.group-settings.<selector-group>.menu-content` 和参考 `<group>-upgrades-settings.menu-content` 可整表替换，模块同组列表优先。内置 `upgrade-swords/armor/miner/forge/heal-pool/dragon` 映射为六类非陷阱强化并保持声明顺序；`category-traps` 控制陷阱分类入口，`base-trap-1..4` 可把对应陷阱直接放到主菜单，`separator-*` 与 `trap-slot-*` 独立控制分隔条和队列区。参考逗号后的原始槽号用于识别合法组件但不强制 Bukkit 原槽位，实际位置继续由 KaGameCenter 六行分页和队列容量自适应布局管理；缺少分组列表时完整回退默认菜单。

`shop.trap-category.menu-content` 复制参考 `category-traps.category-content` 默认值，参考根节点存在时优先。`base-trap-1..4` 及直接填写的陷阱枚举按声明顺序筛选子页商品，重复类型只保留首次；`separator-back` 独立控制返回按钮，列表省略它时不会由模块强制补回。逗号后的参考槽号同样只用于配置兼容，子页继续使用 14 槽分页和导航；未列出的陷阱不会进入该分类页，但仍可由分组主菜单的直接 `base-trap-*` 组件展示。

远程和特殊商品包括箭、三类弓、速度/跳跃/隐身药水、金苹果、床虫、梦境守卫、火球、末影珍珠、水桶、搭桥蛋和魔法牛奶。火球参数、桥蛋距离、召唤物属性和牛奶免陷阱时长均位于 `specials`；召唤实体与临时桥块纳入房间资源作用域，关房时统一回收。与参考监听器一致，运行阶段有效参赛者消费任意牛奶桶都会取消原版清除药水效果，转为同一陷阱免疫并直接扣除一个牛奶桶，不生成或掉落空桶，因此自定义静态商品无需 PDC 也不会绕过魔法牛奶语义；模块以事件对象身份记录该次手动接管，并在 MONITOR 重新确认取消，后续插件误解除取消时不会再触发原版双重消费。竞技场内蛋糕物品消费同样被拒绝。

搭桥蛋按参考算法使用投掷者当前位置而非投掷起点计算停止条件：水平空间距离超过 `max-distance`（默认 27）或比玩家低超过 `max-vertical-drop`（默认 9）时移除。蛋与玩家距离超过 `start-distance`（默认 4）后才开始建造，每 tick 尝试在蛋下方两格生成中心、X-1、Z-1 三块固定 L 形队色羊毛；保护区和非空气方块继续跳过。投掷者离线、最终淘汰或离开参赛状态时立即终止桥蛋并解除实体追踪。

每个成功生成的桥蛋羊毛会在方块中心向房间世界发送 3 个 `Particle.FLAME`，作为现代 Bukkit 对参考 `MOBSPAWNER_FLAMES` 世界效果的兼容实现；原有投掷者逐块音效继续保留。

桥蛋羊毛完成方块写入与房间追踪后逐块发布不可取消的 `GameStructureBlockPlacedEvent`，`sourceId=bridge-egg`；弹出塔的羊毛和梯子沿同一路径以 `sourceId=pop-up-tower` 发布。事件中的玩家在所有者仍在线时可用，弹出塔离线所有者允许为空；监听器必须保持轻量，不能用后置事件撤销已经放置的方块。

模块火球会取消 Bukkit 的玩家直接命中/爆炸伤害，再对爆点范围内的有效参赛者统一施加击退和配置伤害，避免同一次爆炸重复结算。`specials.fireball.damage-self`、`damage-teammates`、`damage-enemies` 默认与参考实现一致为 `2/0/2` 点；敌方有效伤害继续登记 15 秒击杀归因并解除攻击者复活保护，受保护目标不会被写入错误归因。

`specials.fireball.speed` 默认修正为参考实现的 `10.0`，允许范围扩展到 `0.1..20.0`；冷却仍为 10 tick（0.5 秒），爆炸 yield 仍为 3。已有配置中显式保存的旧速度不会被自动覆盖，避免误改服主平衡参数。

`specials.fireball.make-fire` 与参考默认值一致为 `false`，直接控制新发射火球的 incendiary 属性。开启后爆炸可以生成火焰，但竞技场仍关闭火焰蔓延并拦截方块燃烧，因此不会让临时火焰改写地图模板；玩家手动灭火继续遵循 `blocks.allow-fire-extinguish`。

火球影响范围按参考实现使用 `yield` 作为 X/Y/Z 三轴半径，默认是爆点周围 3 格盒形范围，不再使用放大的 8 格球形范围。水平速度从爆点指向玩家并覆盖旧速度，垂直速度按爆点与玩家的归一化高差及 `vertical-knockback` 计算，保留地面与跳跃状态的不同抛射效果。

床虫和梦境守卫死亡时不产生原版经验或战利品，尤其不会让梦境守卫额外产出铁锭；死亡事件会立即解除召唤物的 Session 与资源追踪。队友不能用近战、投射物或带来源 TNT 伤害己方召唤物，观战、复活和非运行阶段玩家同样不能介入；敌队玩家仍可正常击杀。箭实体使用独立的 Bukkit 拾取事件隔离，副手交换也遵循同一阶段规则，因此只有运行阶段的存活参赛者能拾箭和交换主副手。

召唤物移动速度由 `specials.<bed-bug|dream-defender>.speed` 控制，参考默认均为 `0.25`。床虫默认伤害修正为参考值 4 点；梦境守卫 `damage` 默认 `-1`，表示保留当前服务端原版铁傀儡伤害，设置为非负数时才覆盖事件伤害。两类召唤物的生命和持续时间仍分别由原配置控制。

召唤物有效伤害会覆盖更早的玩家最近攻击，后续玩家有效攻击也会反向覆盖召唤物记录，确保同一玩家只有一个最新伤害来源。15 秒记录窗口内只有最后一次 `EntityDamageByEntityEvent` 的实体 UUID、类型和队伍仍与已登记床虫或梦境守卫一致时，才使用召唤物所属队伍和普通/最终击杀专用消息；召唤物击退后发生的摔落、虚空或其他环境死亡不会误报为召唤物直击，也不会虚构购买者个人击杀或转移资源。

床虫和梦境守卫生成后始终显示本地化实体名称，内容包含所属队伍、向上取整的剩余秒数和十段 `❤/♡` 生命条。名称在生成时立即设置，之后每秒与实体到期检查和目标选择一起刷新；实体死亡、到期或房间关闭仍沿用统一资源清理路径。

两类召唤物完成属性、队伍状态、名称和资源追踪后发布不可取消的 `GameSummonSpawnedEvent`，稳定来源为 `bed-bug/dream-defender`，并提供购买者、队伍和实际生物实体。床虫事件发生在雪球命中并成功生成生物时，投出雪球本身只触发投射物事件；梦境守卫在点击方块生成完成后直接触发。

召唤物每秒从有效敌方参赛者和敌队床虫/梦境守卫中选择距离最近的目标。同队召唤物、队友、复活中玩家、观战者、其他房间玩家及普通模板实体不会被锁定；Bukkit 后续产生的目标事件会再次执行同一敌我校验，避免原版 AI 改写目标后误伤己方。

特殊建造反馈复用 `specials.sounds`：搭桥蛋每成功生成一个桥面方块就向投掷者播放一次 `bridge-block`（默认 `ENTITY_CHICKEN_EGG`）；仍属于本房间且未最终淘汰的正式参赛者，其末影珍珠落地时向全部正式玩家播放一次 `ender-pearl-landed`（默认 `ENTITY_ENDERMAN_TELEPORT`），普通死亡复活中的射手仍保留参考反馈，最终淘汰、外部观战或已离房射手不会用历史 `participant` 误播；弹出塔展开期间每个建造 tick 在塔位置播放 `popup-tower-build`（默认 `ENTITY_CHICKEN_EGG`）。三类规则同样支持 `NONE`、音量和音高配置。

玩家投射物对敌方造成未取消的有效伤害时，模块使用 Bukkit `finalDamage` 计算预计剩余生命，并仅向射手发送目标玩家、队伍和生命值。将模块语言键 `bedwars.projectile_hit_health` 配置为空字符串可关闭该反馈；友军、观战者、复活保护目标和被取消的攻击不会提示。

## 基地箱子

普通箱子和陷阱箱按距离最近的队伍出生点归属，半径由 `blocks.team-chest-radius` 控制，默认与参考实现一致为 17 格。队友可正常共享，敌队只有在该队床已毁且所有成员最终淘汰后才能打开。末影箱继续使用原版个人库存，但加入 BedWars 时会清空为局内空间；主插件 `PlayerSnapshotService` 保存并在离房时恢复玩家原末影箱，避免局内外物品串流。

等待、倒计时、复活、淘汰和外部观战状态的非活动玩家不能打开任何 Bukkit `InventoryHolder` 方块、末影箱、门/活板门等 `Openable` 方块，以及工作台、附魔台、铁砧、锻造台、制图台、砂轮、织布机和切石机。运行阶段的有效参赛者继续按独立工作站开关和基地箱归属规则处理，不会因统一隔离误伤正常末影箱与队伍箱使用。

药水持续时间及受伤是否解除隐身由 `specials.potions` 控制。隐身生效时，敌队和观战者收到四件空护甲的 viewer 私有装备更新，队友继续看到真实装备；与参考 Sidebar 重建行为一致，`PlayerNametagService` 对房间内全部其他 viewer 隐藏目标名牌。隐身玩家尝试点击或拖拽护甲槽、使用现代右键装备交换、或者被发射器装备时，服务端取消物品变化，并立即及下一 tick 向敌方和观战者重发私有空护甲；双次覆盖同时压住客户端预测和取消后的服务端纠正包，队友视图不受影响。效果结束、受伤、死亡和结算都会恢复真实护甲与队伍名牌。模块药水饮用后的空瓶会在 5 tick 后自动清理，末影珍珠落地向房间玩家播放提示音。

敌方隐身外观覆盖首次启用或实际恢复后，会发布不可取消的 `GamePlayerInvisibilityChangedEvent`，提供队伍和最终 `invisible` 状态。自然到期、受伤/死亡移除与结算清理共用同一防重集合，因此每次隐身周期只发布一次启用和一次恢复；单纯重发 viewer 私有装备不会产生事件。

扩展工具包含 3 金海绵和 24 铁袖珍弹出塔。海绵走原版吸水规则；弹出塔按玩家朝向使用同一程序化蓝图逐 tick 展开：下层为削角中空墙环，正前方保留三格高入口，顶层铺设中央留梯子的屋顶，并向四周外扩参考垛口。默认半径 2、墙高 5 时最高方块位于基准点上方 7 格，放置前的建筑高度校验同步覆盖该高度。半径、墙高和每 tick 方块数由 `specials.popup-tower` 控制，其中 `blocks-per-tick` 默认修正为参考值 2；生成方块与普通玩家建筑使用同一破坏、爆炸和关房恢复规则。

## 队伍升级与陷阱

队伍升级使用钻石购买，并立即应用到同队在线玩家及其后续复活装备：

- `SHARPNESS`：全队剑和斧锋利。
- `PROTECTION`：全队护腿和靴子保护 I-IV。
- `HASTE`：全队急迫 I-II。
- `FORGE`：四阶加速队伍铁/金生成，三阶开始生成绿宝石，四阶提高绿宝石数量。
- `DRAGON_BUFF`：Sudden Death 时把队伍末影龙从默认 1 条增加到 2 条。
- `HEAL_POOL`：队伍出生点半径内持续获得生命恢复。
- `TRAP_BLINDNESS`：敌人首次进入基地时获得失明和缓慢。
- `TRAP_COUNTER_OFFENSIVE`：为基地范围内的存活队友提供 15 秒速度。
- `TRAP_ALARM`：敌人首次进入基地时移除隐身并显示发光。
- `TRAP_MINER_FATIGUE`：给予入侵者 15 秒挖掘疲劳。

锻炉间隔倍率、绿宝石间隔、数量和堆积上限位于 `generators.forge`。陷阱按购买顺序排队，后续陷阱价格按 `shop.trap-price-increment` 递增，队列上限由 `shop.max-queued-traps` 控制。与参考竞技场一致，敌人进入、反攻陷阱和治愈池都以队伍床为基地中心，并使用地图级 `bedwars.island-radius` 的三维距离，默认半径为 17 格；旧地图缺失时回退模块 `game.island-radius`，床点缺失时才安全回退出生点。升级前生成的旧模块配置若只有 `shop.trap-radius`，首次加载会迁移为模块回退值，避免静默改变服主已有范围。普通跨方块移动和未取消的同世界传送使用各自事件的目标坐标立即同步基地区域、床提示、治愈池及敌方进入状态；传送不依赖尚未提交的 `Player.location`，因此插件传送和末影珍珠不能绕过陷阱，也不会等到下一次步行才移除基地效果。玩家离开基地后再次进入才会触发下一项。

运行阶段玩家跨方块移动时会独立比较所有队伍基地范围，并在真实切换后发布不可取消的 `GamePlayerBaseRegionChangedEvent`；跨基地按旧基地离开、新基地进入顺序发布，死亡时补发当前基地离开。该观察状态不复用陷阱的敌队集合，因此己方基地和魔法牛奶免疫期间仍有完整区域通知，同时不会改变既有陷阱与治愈池语义。

治愈池在队员跨方块进入己方基地时立即给予生命恢复 I，离开、死亡、淘汰或进入结算后立即移除，并由每秒刷新兜底处理传送和状态变化。参考村民粒子每 80 tick 在队伍出生区域发送一次；`shop.heal-pool.particles.enabled` 默认开启，`seen-by-team-only` 默认只让本队成员看到。为遵循 KaGameCenter 主线程规范，粒子使用每队每周期 48 次有界空气点采样，不移植参考项目异步遍历整个 35×35×35 立方体的 Bukkit 世界访问。

四类陷阱参数位于 `shop.traps`：失明与缓慢默认持续 5 秒、效果 amplifier 为 1，反攻速度和挖掘疲劳默认持续 15 秒、amplifier 同为 1；数值沿用 Bukkit 的零基等级，因此对应参考配置中的 II 级效果。警报陷阱默认只移除隐身，不附加参考实现不存在的发光；将 `alarm.glowing-seconds` 设为正数可显式恢复扩展发光。陷阱商品支持参考 `custom-announce` 和 `sound`：前者按商品 ID 读取 `bedwars.trap_<id>_{message,title,subtitle}`，参数依次为入侵者、陷阱名、敌队名和旧式队色，缺键时逐项回退通用提示；后者接受 Bukkit 音效名、`NONE` 或 `{ sound, volume, pitch }`。两项均在购买入队时连同 `receive` 动作保存快照，触发前重载不会改变已购买陷阱。

购买新陷阱后若已有有效敌人停留在床中心基地范围内，会立即按队列顺序消耗并触发第一项，行为与参考 `MenuBaseTrap` 一致。正常进入和购买即时触发共用同一路径，只向守方在线成员发送聊天、15/35/10 tick 标题及陷阱音效，不再向入侵者发送非参考提示。

## Sudden Death

`countdowns.dragon-spawn` 在床销毁阶段后计时。进入阶段时确保全部床销毁，并为每个仍有存活成员的队伍生成真实末影龙；基础数量和 Dragon Buff 增量来自 `dragons.base-count`、`dragons.buff-extra-count`。

Session 每 tick 引导龙追击最近敌队玩家，队友和观战者不会受到己方龙伤害；玩家只能伤害敌队龙。龙的生命、接触伤害、速度、攻击半径和生成高度均可配置。末影龙爆炸不会破坏地图，实体登记到房间资源作用域，死亡或关房时清理。

## 显示、聊天与重连

- `pre-game-items` 可按 0-8 槽位配置等待大厅快捷物品的材质、附魔光效和玩家命令；物品通过模块 PDC 标识，仅在等待阶段右键触发，倒计时开始时随背包重置回收。命令与参考 `RUNCOMMAND` 一致延迟到下一 tick，通过 `RoomTaskService` 归属当前房间，并在执行前复核玩家房间、Session 身份和 `WAITING` 阶段；期间离房、关房或开始倒计时会安全放弃，避免在 `PlayerInteractEvent` 内同步关闭/切换房间。默认提供个人战绩和离开房间两个入口，名称读取模块语言键 `bedwars.pre_game_item_<id>`，缺失时回退配置 ID。
- 模块接管 sidebar 和 ActionBar，显示阶段、时间、各队床状态、存活人数、个人击杀、最终击杀与破床数。
- `scoreboard-settings.sidebar.enable-lobby-sidebar` 与 `enable-game-sidebar` 参考默认都开启：前者控制 `WAITING/COUNTDOWN`，后者控制 `RUNNING/RESULT`。`title-refresh-interval` 默认 4 tick，仅原地推进 `bedwars.scoreboard_title` 列表帧；`placeholders-refresh-interval` 默认 20 tick，负责重新发布渲染事件并重建行、统计、时间和生命目标。两项间隔设为 `0` 时分别停用周期标题/内容刷新，加入与阶段边界仍立即写入。标题原地更新只在当前 objective 标题仍等于模块上一帧时执行，因此不会覆盖 `GameSidebarRenderEvent` 监听器的定制。阶段切换到关闭的一侧时只清除本 Session 确实渲染过的 Sidebar；两项开关都关闭时交回 KaGameCenter 通用房间面板。
- Sidebar 行从 `bedwars.sidebar_<阶段身份>` 的 12 个双语列表读取，覆盖等待/倒计时参赛与观战、运行存活/淘汰/观战、结算存活胜者/淘汰胜者/败者/观战/平局。列表一项对应一行，同行英文逗号分隔动画帧；`{teams}` 和 `{leaders}` 可展开多行，等级、下一事件和个人统计无数据时删除对应 token 行。支持 `{phase}`、`{time}`、`{players}`、`{role}`、`{team}`、`{money}`、`{level}`、`{nextEvent}`、`{teams}`、`{kills}`、`{finalKills}`、`{beds}`、`{deaths}`、`{finalDeaths}`、`{winner}`、`{winnerTeamName}`、`{winnerTeamLetter}`、`{winnerTeamColor}`、`{resultTop}`、`{leaders}`、`{room}`，以及参考通用的 `{player}`、`{playerName}`、`{date}`、`{version}`、`{progress}`、`{levelUnformatted}`、`{currentXp}`、`{requiredXp}`、`{on}`、`{max}`、`{server}`、`{serverIp}`、兼容旧名 `{server_ip}`、`{poweredBy}`、`{spectatorTarget}`、`{map}`、`{map_name}`、`{group}`，共 39 个固定拼写；`{money}` 与参考一致显示 Vault `double` 余额，缺服务时为 `0.0`，只有当前模板实际包含该 token 才查询经济提供者。
- token 独占整行时继续展开模块本地化完整行或多行列表，保证既有默认模板显示“击杀：1”“下一事件：钻石 II 1:20”等内容；嵌入管理员文本时改用参考原始值，因此 `Kills: {kills}` 只替换数字，`{nextEvent}` 只替换事件名，运行期 `{time}` 使用下一主事件 `m:ss`，等待期使用日期，倒计时使用秒数。`{teams}/{leaders}` 嵌入时仍用 ` | ` 连接，缺失身份或阶段值替换为空而不泄漏其他状态。
- `{date}` 分别使用中英文 `scoreboard_date_format` 的 `yy/MM/dd` 与 `dd/MM/yy`，非法管理员格式安全回退；`{version}` 读取当前 KaGameCenter 插件元数据版本。等级系统开启时，`{currentXp}/{requiredXp}` 使用参考最多两位小数的 `k` 缩写，`{progress}` 使用参考十格取整算法及 `levels.progress-bar` 的符号、已解锁颜色、锁定颜色和外框格式；关闭等级系统后四个等级明细 token 为空且不会产生虚假值。默认 12 套布局保持原样，升级不会强制增加新行。
- `{server}` 直接读取核心 `VelocityBridgeService.serverId`，关闭跨服桥时为 `local`；`{serverIp}/{poweredBy}` 读取 `scoreboard-settings.placeholders`，并兼容参考顶层旧键。`{spectatorTarget}` 仅在当前原版第一人称观战目标属于本 Session 时显示双语“队伍 + 玩家”，自由视角、托管观战或无效目标为空，避免跨房间泄漏名称。
- 每个配置队伍额外提供参考 `{Team<队名>Status/Color/Name/Letter}` 四类动态 token；队伍 ID `red` 同时接受 `{Teamred...}` 与参考 `{TeamRed...}`，连字符和下划线 ID 会转换为拼接首字母大写形式。状态按床存活显示绿色勾、床毁后显示有效存活人数、全灭显示红叉，并向 viewer 自己的队伍追加双语“你/YOU”。参赛者和已淘汰成员还可用 `{teamStatus}/{teamColor}/{teamName}/{teamLetter}` 快捷 token；外部观战者不伪造所属队伍。
- `{map}` 映射托管游戏显示名，`{map_name}` 映射 local ID，`{group}` 映射选择器分组；没有托管游戏时安全回退房间名、房间 ID 和 `default`。结算期 `{winnerTeamName/Color/Letter}` 分别提供获胜队显示名、旧式颜色和带颜色首字母，平局及其他阶段为空。参考每队 `{TeamRedLetter}` 保持无颜色字符，只有所属队伍快捷 `{teamLetter}` 带颜色。
- `scoreboard-settings.tab-header-footer.enable` 默认开启 BedWars 独立 Tab 头尾，`refresh-interval` 默认每 10 tick 刷新，设为 `0` 时与参考实现一致地关闭定时刷新，但加入、重连、选队和阶段边界仍立即写入。等待/倒计时各有参赛者和外部观战模板，运行阶段区分存活、已淘汰和外部观战，结算阶段区分存活胜者、已淘汰胜者、败者、外部观战和平局，共 12 组双语头尾模板。每个模板是字符串列表，一项对应一行；单行内用英文逗号分隔动画帧，各 viewer 独立推进并在模板切换时从首帧重置。Session 使用 Adventure 组件发送内容，只接管头尾；KaGameCenter 继续维护玩家列表名称和排序，并在离房时恢复加入前快照。
- Tab 模板键采用 `bedwars.tab_<阶段身份>_header/footer`，共同参数为 `{0}` 玩法、`{1}` 阶段、`{2}` 房间、`{3}` 当前人数、`{4}` 上限、`{5}` 身份、`{6}` 队伍、`{7}` 阶段秒数、`{8}` 获胜队、`{9}` 玩家、`{10}` 击杀、`{11}` 最终击杀、`{12}` 破床、`{13}` 最终死亡、`{14}` 下一事件。模块语言的内置回退保证旧管理员文件缺少新增模板时仍使用 JAR 默认值，不会把键名显示给玩家。
- `scoreboard-settings.player-list` 与参考默认值一致：等待和倒计时格式关闭，运行和结算格式开启，`names-refresh-interval` 每 1200 tick 刷新；设为 `0` 只关闭周期刷新，加入、重连、选队、最终淘汰和阶段边界仍立即同步。13 个名称语言键均支持字符串列表帧；外部观战者按等待、倒计时、运行和结算选择独立模板，结算获胜队区分存活与已淘汰成员，默认给运行观战、淘汰、两类胜者和平局提供双帧。参考 `{vPrefix}/{vSuffix}` 可放在任一名称帧中，通过可选 PlaceholderAPI 的 `%vault_prefix%/%vault_suffix%` 按目标玩家解析；缺插件或 Vault 扩展时回退空串。名称模板和外部前后缀都支持 `&`/`§` 旧式颜色，未显式着色的部分继续继承身份颜色。每个目标玩家独立推进，阶段、身份或队伍参数变化时复位。开启格式后按队色显示队伍和玩家，并在等级系统开启时附加持久等级。任一阶段启用时 Session 统一持有本房间名称所有权，关闭格式的阶段写回纯玩家名并清理动画状态；四项都关闭时交回核心。KaGameCenter 每 tick 计算默认 `playerListOrder` 后调用 Session 排序钩子；BedWars 在等待/倒计时按名称排列正式玩家，运行/结算按全部配置队伍排列存活成员，再按原队排列淘汰成员，外部观战者始终置后。核心在离房时恢复加入前的名称和排序快照。旧 `bedwars.tab_player_spectator` 继续保留为过渡关闭阶段的安全回退和管理员文件兼容键。
- BedWars 每秒低频调用 `SidebarBoardRenderer.show` 前发布可取消的 `GameSidebarRenderEvent`，稳定 objective ID 为 `bedwars_<roomId>`。外部监听器可修改标题、行列表、行长和两处原生生命显示；取消仅保留当前计分板，不影响 ActionBar、BossBar 或下一次刷新。事件同步发生在主线程，监听器不得执行阻塞 IO。
- `scoreboard-settings.health.enable` 默认仅在运行阶段于玩家头顶显示原生心形生命值；`display-in-tab` 默认同步到 Tab 玩家列表，等待、倒计时和结算阶段与参考一致地隐藏。`animation-refresh-interval` 默认 300 tick，在 `bedwars.scoreboard_health` 列表帧间切换，设为 `0` 时保留首帧但关闭动画。两处目标复用每名 viewer 的房间计分板和服务端 `health` criteria 自动更新，不额外轮询实体；每次标签切换仍经过 `GameSidebarRenderEvent`，关闭游戏 Sidebar 总开关时随自定义计分板一起停用。原生 criteria 在客户端全局 Tab 中对其他房间条目的实际过滤依赖服务端发包行为，仍须用至少两个并发房间实服验收，当前不以静态构建结果宣称隔离完成。
- 运行阶段 sidebar 会从钻石/绿宝石 II、III 阶、全床销毁、殊死决战和游戏结束中选择剩余时间最短的事件，以本地化名称和 `分:秒` 显示；修改任一阶段时间后无需额外配置即可自动重排。
- 进入结算后，聊天榜和 Sidebar 榜可通过模块或地图 `game-end.chat-top` 与 `game-end.sb-top` 分别按普通击杀、最终击杀、死亡、最终死亡或破床数排序；地图缺失字段时逐项回退模块配置，`hide-missing` 默认隐藏零值条目，之后继续以五项单局数据和 UUID 稳定处理并列。断线或已淘汰的历史参与者仍纳入榜单，Sidebar 同时保留结算阶段、重启倒计时和房间 ID。
- 结算标题按玩家逐一发送：获胜队历史成员（包括已淘汰观战者）显示“胜利”，其他玩家显示“游戏结束”，平局使用独立标题和副标题；三类受众共享获胜队伍副标题或平局说明。
- 床仍存活时死亡会向本人显示“你死了”和配置复活秒数；最终淘汰不显示错误复活提示。正常倒计时完成及离线期间倒计时结束后的重连均显示“已复活”，ActionBar 秒级倒计时继续保留。
- 与参考实现一致，运行阶段每秒查找同世界中最近的可行动队友，并在 ActionBar 显示己方队名和距离；单人队、队友复活中或离线时回退为床状态与时间。
- `PlayerNametagService` 按队色显示队伍前缀；外部观战者加入时刷新当前房间名牌。客户端 Teams 碰撞规则与服务端状态同步：运行期存活成员使用 `PUSH_OTHER_TEAMS`，其余身份使用 `NEVER`；真正的同队无碰撞由 Bukkit `collidableExemptions` 实现，不依赖 viewer 私有包。
- 最终淘汰者复用主插件 `MANAGED` 观战快捷栏，可循环跟随有效玩家、打开房间菜单或主动离房；玩法级 `canSpectatorFollow` 会排除已淘汰、复活中、断线、死亡和已弃赛成员。托管状态不移动历史参赛身份，结算显示淘汰者、主动离房和关房时分别解除，不会把隐身或快捷栏带回大厅。
- `spectator.mode` 只控制外部观战表现，不区分大小写地接受 `MANAGED` 或 `VANILLA`，非法值安全回退 `MANAGED`。托管模式使用下述快捷栏；原版模式进入首个有效玩家的第一人称镜头，目标选择被取消或没有可跟随玩家时落到地图观战点。最终淘汰和淘汰期间重连显式强制 `MANAGED`，不会因服主选择外部原版模式而丢失离房与跟随入口。
- 模块级 `spectator-items` 用于外部 `MANAGED` 观战者和最终淘汰者，默认将 `teleporter/menu/leave` 映射为 `PLAYER_HEAD` 槽 0、`NETHER_STAR` 槽 4 和 `RED_BED` 槽 8。每项支持 `material/slot/enchanted/action`，也可用 `display-name/lore/command` 定义自定义玩家命令项；内建动作优先于命令。解析会过滤非法材质、槽位和无交互项，重复槽位以后项覆盖，命令去除 `/` 并限制 256 字符；服务只执行自身 PDC 写入的命令。三个默认项目使用 BedWars 双语名称与说明，未知 ID 不查不存在的语言键而回退配置名称或 ID。
- 通用观战服务在目标动作前发布可取消的 `GameSpectatorTargetSelectEvent`，以 `TELEPORT` 表示托管快捷栏传送，以 `FIRST_PERSON` 表示外部配置为 `VANILLA` 时的原版观战镜头；提交后用 `GameSpectatorTargetChangedEvent` 发布前后 UUID/Player。初始自动跟随、快捷栏循环、原版潜行退出、目标死亡/离房、观战退出和房间清理均同步，取消或传送失败不会污染下一目标索引。
- `FIRST_PERSON` 镜头完成提交或清除后、默认标题发送前发布 `GameSpectatorFirstPersonFeedbackEvent`，`ENTER/LEAVE` 分支提供稳定房间 ID、观战者、可空目标 UUID/Player，以及可替换或置空的 Adventure `title/subtitle`。默认时长与参考一致为 0/40/10 tick，监听器可调整并最终限制在 0–72000；进入前取消仍只由选择事件负责。切换目标会重新显示进入标题，潜行退出、目标死亡/离房、观战退出和在线房间清理显示退出标题；托管 `TELEPORT` 模式不触发。
- 主菜单、房间菜单及 `/kgc stats [gameId]` 可查看个人持久战绩。BedWars 详情同时显示参与、胜负、总击杀/死亡、点数和 `final-kills/final-deaths/beds-destroyed`；房间内省略玩法 ID 时直接打开 BedWars，房间外进入全部玩法概览，菜单遵循 KaMenu 到箱子菜单的标准回退链。BedWars 详情由 KaMenu 或箱子菜单真实打开后，通过通用 `GameStatsMenuOpenedEvent` 播放参考 `stats-gui-open` 音效；配置路径为 `game.sounds.stats-menu-open`，默认 `ENTITY_CHICKEN_EGG` 并支持 `NONE/volume/pitch`。全玩法概览、其他模块详情和只回退主 Dialog 的失败路径不会误播。
- `/kgc selector bedwars [group]` 或 `kgc:open-rooms bedwars [group]` 打开 BedWars 专属房间选择器，按模块 ID 汇总所有 BedWars 托管玩法及现有 Velocity 房间；传入完整 globalId 时可缩小到单个玩法，传入非 `default` 分组时继续按托管配置 `selector-group` 过滤。参考 `default` 语义表示全部竞技场；分组使用 Velocity `group:` 标签同步，旧快照安全回退 `default`。标题、计数、空列表、刷新、详情、成员操作和返回链保持全部筛选上下文，旧默认模板动作也会在内存中兼容补齐，既有 `/kgc rooms` 文本状态与全局房间菜单不变。打开后事件新增可空 `group` 且保留旧构造签名，BedWars 继续精确播放参考 `arena-selector-open`；全局/其他模块列表和主 Dialog 失败回退不会误播。
- 默认聊天发送到队伍，`/a` 使用房间全局格式，继续由 KaGameCenter 聊天服务负责受众隔离。
- 房间内玩家命令按 `game.allowed-commands` 的根标签白名单过滤，默认允许 `/kagamecenter`、`/kgc`、`/allchat`、`/a`、`/globalchat` 和 `/g`；参数不参与普通白名单匹配，因此离房、菜单和聊天的全部合法子命令保持可用。参考 `CmdProcess`，精确的 `/party home` 与 `/party sethome` 会先于管理员权限和白名单硬拒绝；匹配会规范化大小写、连续空白及 `插件名:party` 命名空间，不能用别名形式绕过。`kagamecenter:` 命名空间会映射到同一根标签，其他插件命名空间不会借白名单中的同名标签绕过；除上述两个队伍传送子命令外，拥有 `kagamecenter.admin` 的管理人员不受限制。
- 参考 `Warnings`，OP 加入服务器 5 tick 后会收到双语环境诊断：检测到 Multiverse-Core 时提示避免其接管临时竞技场世界，`spawn-protection` 半径大于 0 时提示该设置可能阻止竞技场建造。普通玩家不接收，玩家在延迟期间离线或失去 OP 时不再发送。
- `game.reconnect-grace-seconds` 默认为 300 秒；设为 `0` 时恢复主插件立即离房行为。
- 临时断线保留房间席位、队伍、胜负参与者和大厅快照。运行期重连按参考行为默认重新进入 `game.respawn-seconds` 的 5 秒复活倒计时，完成后在队伍出生点重建当前永久装备与强化；`GamePlayerRoomReconnectEvent.respawnDelayTicks` 可调整为 `0` 立即复活、其他非负 tick 或 `null` 保留 Session 当前状态，BedWars 最终限制到 72000 tick。倒计时阶段重连不提供该值，继续恢复原阶段状态。
- 断线时暂存四类商店货币、断线位置和最近 15 秒敌方攻击者；玩家在宽限期内返回会直接丢弃该临时副本，不会产生复制。
- 宽限到期会把玩家最终淘汰、释放队伍席位，并在其下次上线时恢复大厅快照；若断线前存在有效敌方攻击，则记录对应普通/最终击杀并把暂存货币落在断线点，否则只记录一次死亡。
- 玩家被其他插件、传送门或管理员操作带离当前竞技场世界时，会按正常主动离房流程立即释放席位、队伍、名牌、计分板和玩法状态，并恢复进入房间前快照；进入竞技场世界以及正常离房恢复引发的世界切换不会递归处理。
- 主插件在正式玩家或外部观战者提交成员关系前统一发布可取消的 `GamePlayerRoomJoinEvent`；相同身份重复请求幂等，观战转正式玩家按“加入预检、`ROLE_CHANGE` 离开、正式提交”排序。断线宽限返回使用独立可取消 `GamePlayerRoomReconnectEvent`，拒绝时不应用复活时间并释放保留席位；通过后核心在重新附加显示与玩法恢复回调前应用事件最终 `respawnDelayTicks`。
- `GamePlayerRoomLeaveEvent` 在清理后覆盖主动离房、踢出、无宽限断线、重连超时/拒绝、关房和身份切换。在线主动离场会在 Session 状态移除前捕获最近有效攻击者；离线超时和关房允许 Player/攻击者为空，UUID 始终保留。
- 核心每 tick 先复制活动房间列表，再逐房执行 `GameSession.onTick()` 和显示刷新。任一房间回调抛异常时仅关闭该房间并走完整玩家快照、资源和世界清理，其他房间继续同一 tick；Velocity 心跳同样按房间隔离，单次发布失败不会跳过后续房间或取消周期任务。`onStart()` 及其状态、显示、代理提交属于同一失败关闭边界，部分初始化后抛异常不会留下仍可加入的半启动房间。
- Session 工厂必须返回持有同一 `GameRoom` 的实例；创建异常、房间不匹配或初次代理发布失败时核心拒绝暴露房间并清理已创建 Session。观战策略、准入预检事件、死亡归因与回调、聊天路由和观战目标过滤均有独立异常边界：准入失败使用 `CALLBACK_FAILED`，死亡链在下一 tick 关房以避开 Bukkit 死亡提交，聊天不安全回退受众，非法目标只从本次候选中排除。
