# 跑酷模块技术细节

更新时间：2026-06-22

本文档记录 `parkour` 模块当前实现约定，后续维护时以此为准。

## 模块定位

`parkour` 是 KaGameCenter 的外置小游戏模块，构建产物为 `parkour-<version>.jar`，运行时放置在：

```text
plugins/KaGameCenter/modules/parkour-<version>.jar
```

模块私有配置目录为：

```text
plugins/KaGameCenter/modules/parkour/
```

主插件只负责模块加载、房间、菜单、临时世界、选区、数据、发包和地图编辑基础设施。跑酷玩法参数、检查点、终点、道具点等内容必须放在跑酷模块自己的托管游戏配置内，不能写入主插件根目录配置。

## 目录结构

测试服运行目录的目标结构：

```text
plugins/KaGameCenter/
  maps/
    parkour/
      default/                 # 公用地图模板，只作为创建游戏时的源模板
  modules/
    parkour.jar
    parkour/
      config.yml               # 跑酷模块级默认配置
      lang/
        zh_CN.yml
        en_US.yml
      games/
        game/
          <游戏名>.yml          # 每个跑酷游戏一个私有配置
        map/
          <游戏名>/             # 每个跑酷游戏一份私有地图快照
```

`plugins/KaGameCenter/games.yml` 已废弃，不再作为游戏配置来源。

## 配置归属

`modules/parkour/config.yml` 只保留模块级默认值：

```yaml
id: parkour
name: Parkour
enabled: true
main: jar
jar: ../parkour.jar
entrypoint: org.katacr.kagamecenter.parkour.ParkourModuleProvider
description: External managed Parkour module.

game:
  display-name: Parkour
  min-players: 1
  max-players: 16
  start-countdown-seconds: 5
  finish-countdown-seconds: 60
  result-display-seconds: 15
  close-delay-seconds: 10
  fall-y: -32.0
  checkpoint-glow-seconds: 3
  checkpoint-glow-color: yellow

spectator:
  enabled: true
  mode: managed
```

以下内容不应出现在模块级 `config.yml`：

- 地图路线
- 检查点
- 起点区域
- 终点区域
- 等待大厅坐标
- Buff 道具点

这些内容属于具体游戏实例，应写入：

```text
plugins/KaGameCenter/modules/parkour/games/game/<游戏名>.yml
```

## 托管游戏创建

管理员通过主插件管理面板创建托管游戏：

```text
/kgc admin manage
```

创建流程：

1. 选择模块：`parkour`
2. 选择公用地图模板：例如 `parkour/default`
3. 输入游戏名称
4. 主插件创建配置文件：

```text
modules/parkour/games/game/<游戏名>.yml
```

5. 主插件复制公用地图模板为私有地图快照：

```text
modules/parkour/games/map/<游戏名>/
```

游戏名称会用于本地 ID 和文件名。当前实现会保留中文、英文、数字、下划线和短横线；空格会转为短横线；路径分隔符和危险字符会被过滤。

## 托管游戏配置格式

托管游戏配置示例：

```yaml
id: 跑酷测试
module: parkour
display-name: 跑酷测试
enabled: true
shared-map-template: parkour/default
runtime-map-template: modules/parkour/games/map/跑酷测试
min-players: 1
max-players: 16
description: ""

parkour:
  map-id: default
  lobby:
    x: 0.5
    y: 80.0
    z: 0.5
    yaw: 0.0
    pitch: 0.0
  start:
    spawn:
      x: 1.5
      y: 80.0
      z: 1.5
      yaw: 0.0
      pitch: 0.0
    region:
      min:
        x: 0
        y: 79
        z: 0
      max:
        x: 3
        y: 82
        z: 3
  checkpoints:
    - id: "1"
      display-name: "1"
      region: {}
      respawn: {}
      glow-region: {}
  finish:
    region: {}
    glow-region: {}
  buffs:
    - id: speed_1
      type: speed2
      point: {}
      color: aqua
      duration-seconds: 10
      amplifier: 1
      respawn-seconds: 15
```

`region` 和 `point` 的完整结构由代码写入，通常不需要手工编辑。

区域配置不保存世界名，只保存绝对坐标。房间运行时会创建随机临时世界，检查点、起点区域和终点区域都按当前房间世界中的相同坐标判断。

## 地图编辑

地图编辑会话由主插件 `MapEditorService` 管理，跑酷模块只负责告诉主插件当前游戏的配置字段如何保存。

编辑逻辑：

- 进入编辑器时，打开 `modules/parkour/games/map/<游戏名>/` 的私有地图快照。
- 管理员可以在编辑世界中直接破坏和放置方块。
- 点击保存或执行相关设置动作时，会同步保存当前编辑世界到私有地图快照。
- 公用地图模板 `maps/parkour/default` 不会被修改。

## 管理菜单

跑酷模块实现了 `ParkourManagedGameEditor`，由主插件菜单系统调用。

编辑面板显示：

- 当前游戏名称
- 公用模板
- 运行地图
- 私有快照状态
- 等待大厅状态
- 起点出生点状态
- 起点区域状态
- 终点状态
- 检查点数量
- Buff 数量

编辑按钮包括：

- 打开编辑世界
- 保存私有快照
- 关闭编辑世界
- 设置大厅
- 设置起点
- 设置起点区域
- 设置终点
- 新增检查点
- 删除检查点
- 添加速度道具
- 删除道具
- 预览路线

菜单当前由 `GameCenterMenuService.openExternalConfig(...)` 构造 KaMenu/Dialog 外部配置入口渲染。动作通过 `kgc:module-game-action <globalId> <action>` 回调到模块编辑器。内置箱子菜单只作为后续备用或局内操作菜单能力，不是当前跑酷编辑器的默认渲染路径。

## 检查点

检查点使用区域触发，不使用踏板。

当前规则：

- 检查点区域只保存 `min/max` 坐标，不保存编辑世界名。
- 检查点列表通过 YAML 嵌套结构递归读取，`region.min/max`、`glow-region.min/max`、`respawn` 必须能被解析，否则该检查点会被跳过。
- 新增检查点默认自动按数字编号。
- 编号从 `1` 开始，取第一个未占用数字。
- 不支持自定义检查点名称。
- 玩家进入检查点区域后记录进度。
- 玩家掉落到 `fall-y` 以下会传送回上一个检查点。
- 游戏内下一个目标使用私有粒子圆圈和上方向下箭头提示。
- 检查点提示圆圈以该检查点 `respawn` 为中心；终点提示圆圈以 `finish.region` 中心为准。
- 向下箭头由少量只对指定玩家可见的 `BlockDisplay` 组成，目标变化或玩家完成/离开时立即移除。
- 管理预览仍使用完整区域发光边界，方便校准判定范围。
- 区域预览当前使用只对指定玩家可见的 `BlockDisplay` 显示，并设置发光队伍颜色。
- `BlockDisplay` 没有实体碰撞体，可穿透，不会修改真实地图方块。
- 空气边界也会显示，预览到期后直接移除显示实体。

菜单新增检查点：

- 先用主插件选区工具选择检查点区域。
- 点击“新增检查点”。
- 当前位置会作为该检查点的复活点。

菜单删除检查点：

- 在输入框填写检查点编号，例如 `1`。
- 点击“删除检查点”。

命令新增检查点：

```text
/kgc admin parkour addcheckpoint
/kgc admin parkour addcheckpoint <编号>
```

在当前托管游戏编辑世界中执行时，可以省略地图和路线参数。不填编号时自动使用下一个数字编号。

命令删除检查点：

```text
/kgc admin parkour removecheckpoint <编号>
```

在当前托管游戏编辑世界中执行时，直接删除当前游戏的检查点。

旧 `<map> <route>` 参数格式已移除。管理命令只操作当前托管游戏私有编辑世界，避免继续写入模块级旧 `maps` 结构。

## 起点和终点

起点由两部分组成：

- `start.spawn`：玩家正式开始时的传送位置。
- `start.region`：起点区域。

终点使用区域触发：

- `finish.region`：完成判断区域。
- `finish.glow-region`：预览发光区域，默认与 `finish.region` 一致。

游戏开始时：

1. 玩家传送到起点。
2. 冻结玩家移动。
3. 显示 5 秒倒计时 Title。
4. 倒计时结束后解除冻结并开始计时。

首位玩家完成后：

- 开始结束倒计时。
- 未完成玩家仍可继续冲线。
- 完成玩家记录胜场和统计点数。
- 未完成玩家在结算时记录失败。
- 经济或物品奖励等待主插件提供通用服务后再接入。

## 速度道具

第一版内置一种可拾取道具：

- 类型：`speed2`
- 效果：速度 II
- 默认持续：10 秒
- 默认颜色：`aqua`
- 默认刷新：15 秒
- 视觉：只对对应玩家可见的 `ItemDisplay`，默认缩放 `1.8`，可通过主插件发包 API 传入缩放值。
- 提示：道具刷新时会显示短暂的私有信标光柱，当前用多段 `BlockDisplay` 模拟，不修改真实地图。

配置字段：

```yaml
buffs:
  - id: speed_1
    type: speed2
    point: {}
    color: aqua
    duration-seconds: 10
    amplifier: 1
    respawn-seconds: 15
```

添加道具时，当前位置作为道具点。

## 游戏运行

房间创建时，如果选择的是托管游戏 `parkour:<游戏名>`：

- `GameRoom.configuredGame` 保存托管游戏配置。
- `GameRoom.templateDirectory` 指向私有地图快照目录。
- `ParkourGameSession` 使用 `readManagedRoute(game)` 读取该游戏自己的 `parkour` 节点。
- 临时世界从 `modules/parkour/games/map/<游戏名>/` 复制创建。
- 游戏结束后临时世界卸载删除，不修改私有快照。

## i18n

跑酷模块语言文件位于：

```text
modules/parkour/lang/zh_CN.yml
modules/parkour/lang/en_US.yml
```

模块内玩家可见文本必须写入模块私有语言文件，不写入主插件语言文件。

主插件只保留通用菜单、通用管理、通用错误、通用服务相关文案。

## 关键类

```text
ParkourModuleProvider.kt
```

模块入口，注册：

- `ParkourGameModule`
- `ParkourAdminCommand`
- `ParkourManagedGameEditor`
- `ParkourListener`

```text
ParkourConfigService.kt
```

读取模块级配置和托管游戏配置，保存大厅、起点、区域、检查点、终点、道具点。

```text
ParkourManagedGameEditor.kt
```

托管游戏编辑 UI 和动作处理。

```text
ParkourGameSession.kt
```

跑酷房间运行逻辑，包括倒计时、冻结、检查点、掉落回传、终点、路线累计距离排名、完成玩家观战热栏、统计奖励、结算、道具。

```text
ParkourAdminCommand.kt
```

跑酷管理指令。当前只操作托管游戏编辑上下文，旧地图路线参数入口已移除。
